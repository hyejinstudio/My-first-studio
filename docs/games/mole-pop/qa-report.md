### 실행한 테스트와 결과
환경: Playwright 1.63 + Chromium. 스크립트는 Developer 것을 쓰지 않고 새로 작성했다(스크래치 `qa-mole/`, 저장소 밖). 시간이 걸리는 판정은 `page.clock`(install + pauseAt)으로 게임 시계를 프레임 단위(16ms)로 직접 진행했다. 터치는 `page.touchscreen.tap`과 CDP `Input.dispatchTouchEvent`(pointerType touch)로 보냈다.

1. **스모크 (`node tests/smoke.js`)**: 목록 게임 4개(mole-pop, bunny-ten, snake-garden, block-stack) × PC/iPad 세로/iPad 가로 = 12개 모두 통과. 기존 3게임 회귀 없음.

   - 폭탄: −30, 콤보 0, 최고 콤보 유지. 10점에서 폭탄 → 0점(0 미만 없음). 팝업 `−30`(U+2212).
   - 일반 도망 → 콤보 0. 황금 도망 → 콤보 유지. 폭탄 흘려보냄 → 점수·콤보 유지(다른 두더지 없이 격리해서 확인).
   - 빈 구멍 탭, 판 안쪽 여백 탭 → 점수·콤보 그대로. 같은 두더지 두 번 탭 → 두 번째는 무시.
   - 판정 구간: 올라오기 시작 0ms, 올라오는 중 80ms, 머묾 중 판정 인정. 내려가기 시작 후 22/50/66ms 인정, 82/90/106ms 불인정(코드 SINK_OK=80과 일치).
   - 머무는 시간 실측: 1단계 150+1400ms, 2단계 150+1200ms, 황금 1단계 840ms.
3. **반응성 (input.js, iPad 세로·가로 에뮬레이션, 전부 통과)**
   - 손가락을 대기만 하고(touchStart만, 떼기 전) 바로 점수가 반영된다. 순서: pointerdown(touch) → 판정 → touchstart.
   - 두 손가락 동시 탭(일반+황금): 두 마리 모두 잡힘, +70, 콤보 3. 한 손가락을 누른 채 다른 손가락을 추가해도 판정된다.
   - 빈 칸을 누른 채 두더지 칸으로 미끄러져 들어가도 추가 판정이 없다.
   - 판 위 드래그와 스크롤 제스처 뒤에도 scroll 0이고 문서가 화면을 넘치지 않는다. 판 위 핀치 후 visualViewport.scale 1. touch-action은 body manipulation, 판·칸 none, user-select none.
4. **흐름 (flow.js·keys.js, 전부 통과)**
   - 시작: 버튼, Enter, Space.
   - 일시정지: P, Esc, Ⅱ 버튼, visibilitychange(hidden), window blur. 일시정지 중 3초가 지나도 시간·두더지 상태가 그대로다. 팝업·탭 표시 WAAPI 애니메이션은 paused이고 currentTime이 변하지 않는다. CSS 반짝이·불꽃도 paused. 다시 보이게 되어도 자동 재개하지 않는다.
   - 재개: P, Esc, Enter, 계속 버튼. 재개 후 0ms·250ms 탭은 무시, 320ms 탭은 인정.
   - 마지막 10초: 시간 숫자·막대·판 테두리 경고.
   - 종료: 0초가 되면 ending 상태로 넘어가 입력이 무시된다. 0.3초 시점에는 결과 화면이 아직 없고, 0.5초 후 결과 화면이 뜬다.
   - 결과 통계: 시나리오(일반 6·황금 1·폭탄 1) 기대값과 일치. 80점, "잡은 두더지 7 (황금 1) · 최대 콤보 ×4", "폭탄 1번 · 최고 80점", 새 기록 배지.
   - 결과 잠금: 0~0.7초 동안 다시 하기 disabled. 이 동안 Enter·Space·클릭은 무시된다. 0.7초 후 버튼이 활성화되고 Space로 재시작한다.
   - 재시작 상태: 점수 0, 콤보 ×0, 시간 60, 경고 클래스 없음, 팝업 0개, 알약 숨김, 구멍 모두 빈 상태.
   - 최고 점수: 낮은 점수로 끝나면 새 기록이 없고 최고 점수가 유지된다. 새로고침 후에도 시작 화면·HUD에 최고 점수 표시.
   - 음소거: 클릭하면 아이콘이 실제로 바뀐다(스크린샷 mute-on/off). aria-label이 바뀌고 `mole-pop-muted`=1로 저장되며 새로고침 후에도 유지된다. M 키로 해제된다.
   - Ⅱ나 음소거 버튼에 포커스가 있을 때 Space를 눌러도 이중 토글이나 음소거 오작동이 없다.

### CEO 추가 확인 요청 3건
1. **맞은 두더지 머리 위의 옅은 테두리 원**: art-ui.md의 "탭 위치 표시"(누른 지점에 지름 36px 원, 테두리 `--ink` 25%, 200ms) 효과이고 잔여 요소가 아니다. 실제 시간으로 측정한 결과:
   - 0.1초: opacity 0.5~1
   - 0.2초: 0.09~0.41
   - 0.3초: 0~0.01
   - 0.45초 이후: 원이 DOM에서 사라짐
   - 별 입자, 연기 고리, 흙먼지 고리도 0.45초 안에 모두 없어진다. 1초와 2초 시점에 남은 애니메이션은 반복 CSS 18개(반짝이·불꽃)뿐이다.
   - 참고: 시계를 멈춘 테스트(가짜 시계)에서 찍은 스크린샷에서는 WAAPI·CSS 애니메이션이 중간에 멈춘 채로 찍혀 원이 남아 보인다. Developer 스크린샷도 그 경우이거나 200ms 안에 찍혔을 가능성이 높다. 버그 아님.
2. **콤보 알약이 시간 막대를 가림**: 아래 버그 목록 [낮음] 참고.
3. **+50 / −30 팝업이 옅게 보이는 프레임**: 사라지는 중인 정상 상태다. 팝업은 지속 시간의 60%까지 opacity 1이고 이후 0이 된다(일반·폭탄 650ms, 황금 750ms). 실측으로 0.45초에 0.5~0.8, 0.7초에 0.01~0.13이었고, 1초에는 DOM에서 제거됐다.

### 버그 (심각도: 치명/높음/보통/낮음)
- [낮음] **콤보 알약이 시간 막대 아래쪽 6px(높이 10px 중)를 가림**
  - 증상: 콤보 3 이상이면 판 위 가운데 알약(높이 30px, `top: -18px`)이 시간 막대의 가운데 부분을 덮는다. 6개 화면 모두 6.0px 겹친다. 알약 폭 156px(×5 이상, 배율 표시 포함)은 PC·iPad에서 막대 폭(692px)의 23%, 폰 세로에서 막대 폭(365px)의 43%다.
  - 재현: 시작 → 두더지 3마리 연속으로 잡기 → 시간 막대 가운데를 본다(스크린샷 1280x800-play.png, 390x844-play.png, v-ipad-light-last10.png).
  - 사용자 영향: 막대 끝이 가운데에 있을 때(남은 약 25~35초) 끝부분이 위 4px만 보인다. 남은 초는 HUD 숫자로 항상 보이므로 정보 손실은 작다. 다만 단계가 오를 때 알약이 금색으로 바뀌어 막대 위에 겹친 것이 눈에 띈다.
  - 기대: 알약이 막대와 겹치지 않는다. 막대와 판 사이 간격이 8px뿐이라 art-ui.md 명세 값(-14px)대로 해도 2px 겹친다. `top`을 -8px 이하(판 테두리에만 걸침)로 조정하거나 판 안쪽 위로 내리는 방안이 있다. art-ui 명세 조정이 필요하다.
  - 위치: `games/mole-pop/index.html` 191행 `.pill { position: absolute; top: -18px; ... }`, art-ui.md "판 위 콤보 알약" 절.

### 의견 (버그 아님)
- **Developer가 밝힌 명세 차이 4건**
  - 키보드로 구멍 치기 미구현: design.md "범위 밖"과 일치한다. art-ui.md 키 표(숫자패드·QWE)와는 다르지만, 시작 안내 문구가 "마우스로 클릭 · P/Esc 일시정지 · M 소리"여서 화면과 동작이 맞는다. 문제없음.
  - Space=시작/재시작 및 플레이 중 일시정지: design·art-ui와 맞고 포커스 상태 이중 토글도 없다. 문제없음.
  - 결과 잠금 0.7초: design.md 값이다(art-ui의 0.5초보다 우선). 문제없음.
  - viewport에 user-scalable=no 없음: 판 위 확대는 `touch-action: none`으로 막히고, 에뮬레이션에서는 판 밖 핀치 후에도 scale 1이었다. 다만 Chromium의 합성 핀치는 iPad Safari 동작을 보장하지 않는다. iPad 세로에서는 판 위아래에 약 143px 여백(body는 `manipulation`)이 있으므로 그 여백에서 두 손가락으로 확대되는지 실기기에서 확인해야 한다.
