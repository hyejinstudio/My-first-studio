# 꼬마 사장님 기획서
- slug: tiny-company
- 한 줄 소개: 직원 4명짜리 작은 회사의 1년. 월급·업무량·휴식을 매달 조절해 퇴사 없이, 망하지 않고, 매출을 최대로 올려라.
- 이름 이유: 「꼬마 사장님」 — 5글자로 짧고, "작은 회사 + 초보 사장" 느낌이 귀엽고, 플레이어 역할이 이름만으로 드러난다. (원안 예시 「작은 회사 사장님」보다 짧음)
- 순위 점수: **연 매출 합계(만원)**, 12개월 완주 + 12월 말 현금 ≥ 0 일 때만 (사용자 결정).

## 핵심 루프 (턴제, 1턴 = 1개월, 12턴)
**턴제로 결정**: iPad 터치로 천천히 조절 가능, 매달 "결과 리포트 한 장"으로 원인→결과를 설명하기에 실시간보다 적합.

1. **월초 결정 화면** (~25초)
   - 이번 달 주문량 D + 이번 달 사건(있으면) 배너.
   - 회사 전체 설정 3개: 월급 / 업무량 / 휴식 (단계 버튼).
   - 직원 카드(자리 배치도 위): 탭 → 개별 조치 1개(휴가 / 격려 보너스 / 없음).
   - 채용 후보 1명 카드(조건 충족 시) → "채용" + 빈 자리 선택.
   - **실시간 예측 패널**(설정을 바꿀 때마다 즉시 갱신): `예상 처리 52 / 주문 70`, `예상 이익 +420`, 직원별 행복·피로 예상 변화 화살표(▲▼ 숫자), 위험 표시.
2. **한 달 진행** 애니메이션 1.5초 (탭으로 건너뛰기).
3. **월말 리포트** 한 장 (아래 "리포트" 절). "다음 달" 버튼.
4. 12월 리포트 후 **결산 화면**. 또는 게임오버 화면.

- 한 판 목표 5~8분 (12턴 × 25~35초).
- 난이도 1개(쉬움 모드 없음). 이유: 사용자가 쉬운 걸 싫어함 + 순위표 공정성.

## 규칙 (승리/패배, 점수)
| 조건 | 결과 |
|---|---|
| 월말 현금 < 0 | "적자 경고"(빨간 배지). **2달 연속**이면 **파산 → 게임오버** |
| 12월 말 현금 < 0 | 결산 적자 → **파산 처리**(1번이라도) |
| 직원 0명 | **전원 퇴사 → 게임오버** |
| 12개월 완주 + 12월 말 현금 ≥ 0 | 성공. **점수 = 연 매출 합계(만원)** |

- **게임오버 시 점수 없음(순위 미등록)**. 결과 화면에는 "N개월 버팀 · 그때까지 매출 X만원 (완주해야 순위에 올라가요)"만 표시. → "혹사시켜 매출을 쌓고 11월에 망하기" 공략 차단.
- 매출은 수요 D를 넘을 수 없으므로(판매 = min(생산력, 주문)) 돈을 무한히 써서 매출을 올릴 수 없다. 남는 압박 = **현금 ≥ 0 유지 + 직원 유지**.
- 등급(결산 화면, 시뮬 후 조정): S ≥ 38,000 / A ≥ 33,000 / B ≥ 27,000 / C 그 외.
- 결산 화면: 연 매출(큰 숫자), 등급, 월별 매출 막대그래프 12개, 최종 현금, 남은 직원(표정), 퇴사자 수, 최고 기록, "다시 하기", 순위표.

### 이론상 최대·순위표
- 최대 판매 ≈ Σ 최대 주문(기본 821 × 1.05 노이즈 + 첫 달 +25 + 대형 주문 +30 − 경기 침체 최소 손실 ~54) − 첫 달 생산 한계(최대 56/70) ≈ 845건 × 50 = **약 42,300**.
- 현실 최고(적응형 상위) 예상 ≈ 39,000~40,000.
- **score_cap 50,000** → `docs/site/leaderboard-v5-tiny-company.sql`.
- `lib/leaderboard.js`, game key `'tiny-company'`. 결산/게임오버 화면에서 `window.Leaderboard && Leaderboard.report({game:'tiny-company', score, eligible, slot})`. 게임오버면 score 0(제출 없음, 내 순위만 표시).
- `eligible=false`: 테스트 훅 사용(시드 지정, 결정 주입, 상태 수정), URL `?seed=`.

### 채용
- 매달 후보 1명(시드). 직원 < 6, 현금 ≥ 채용비일 때 버튼 활성. 한 달 1명.
- 채용비 200 (즉시 차감). 첫 달 생산 ×0.5 (신입), H 65, F 10.
- 후보 능력: S ∈ {0.8, 0.9, 1.0}, stamina ∈ {0.8, 0.9, 1.0, 1.1, 1.2}, E = 270 + 10×rand(0~5) + 100×(S−0.9) + 5×(month−1).
- 이름 풀(12): 다온, 하람, 이든, 누리, 보람, 시온, 가온, 라온, 단비, 여름, 마루, 초롱 (중복 없이).
- 해고·자리 바꾸기 없음.

## 수치 모델 (월말 처리 순서 고정 — 결정론)
RNG: `mulberry32(seed)` 하나. 사용 순서: (게임 시작) 사건 배치 → 매달 [주문 노이즈 → 채용 후보 → 퇴사 판정(직원 자리 번호 순)]. 예측 패널은 RNG를 쓰지 않는다.

**0. 월초**: 사건 적용(아래 표) → D 확정·표시 → 후보 생성 → 플레이어 결정.

**1. 생산** (월초 H·F 기준):
```
fatM(F)  = 1 − 0.6 × max(0, F − 50) / 50          // F 100 → 0.4
moodM(H) = 0.8 + 0.3 × H / 100                     // 0.8 ~ 1.1
O_i = 10 × hF[W] × rF[R] × moodM(H_i) × S_i × fatM(F_i) × (신입 0.5) 
O_i = 0  (휴가 또는 병가)
C = Σ O_i (소수 1자리 표시)
판매 = min(floor(C), D)
```
**2. 돈**:
```
매출 = 판매 × 50
비용 = Σ P (휴가·병가 포함 전원) + 임대료 600 + 채용비 + 보너스 50×n
cash += 매출 − 비용
```
**3. 피로** (휴가 아님, 병가 아님):
`F_i += wF[W] × stamina_i − 6 − rRec[R]` → clamp 0~100. 휴가: F −35. 병가: F −40.

**4. 행복** (새 F 기준 패널티):
```
ΔH_i = wage_i + work[W] + rest[R]           // 휴가자는 work+rest 대신 +6, 병가자는 −5
     − max(0, F_i − 50) / 6                 // 피로 패널티 (F 80 → −5)
     + 이웃 영향  = clamp(0.1 × (avg H_이웃 − H_i), −4, +4)   // 이웃 없으면 0
     + 보너스 +10
     + 사건 항
H_i = clamp(H_i + ΔH_i, 0, 100)    // 표시·판정은 반올림 정수
```
- 이웃 영향은 이번 달 변화 전(월초) H로 계산(순서 무관하게).

**5. 숙련·기대**: 일한 직원(휴가·병가 아님) S += 0.02 (최대 1.5). 전원 E += 5 (매달 "몸값" 상승 — 월급 고정이면 서서히 불만).

**6. 번아웃**: F ≥ 90 → 다음 달 병가(생산 0, F −40, H −5). 리포트에 "피로 90 이상".

**7. 퇴사 판정** (자리 번호 순):
```
기준선 T_i = 30, 흔들림(shaken>0)이면 40
flag가 이미 켜져 있고 H_i < T_i  → 퇴사 확률 p = clamp((T_i − H_i)/15, 0.2, 1.0)
                                     (T30: H27→20%, H22→53%, H15 이하→100%)
그 뒤 flag = (H_i < T_i)   // 처음 기준선 밑 = 경고만, 다음 달에도 밑이면 확률 판정
```
- 즉 **퇴사는 항상 최소 1달 전 ✉ 경고**가 뜬다. 예외: 스카우트(사건, 예고됨).

**8. 연쇄 (동료 퇴사 충격)** — 퇴사(또는 이직) 1명마다:
| 대상 | 효과 |
|---|---|
| 이웃 | H −12 (보너스 받은 달 −6), shaken = 2 (2달간 기준선 40) |
| 그 외 | H −3 |
- 충격 적용 후 이웃의 H < 40이면 **즉시 flag = true** (✉) → 다음 달 말 확률 판정 대상. 같은 달 안 연쇄 퇴사는 없음(최소 1달 막을 기회).
- shaken은 매달 말 −1.

**9. 종료 판정**: 직원 0 → 게임오버. 현금 < 0 연속 2달 → 파산. 12월이면 현금 ≥ 0 확인 → 결산.

### 예측 패널 (결정 화면) — 같은 공식을 RNG 없이 실행
- 표시: 예상 처리/주문, 예상 매출·비용·이익·월말 현금, 직원별 ΔH·ΔF, 다음 위험 태그:
  - "✉ 퇴사 위험 35%" (flag 켜짐 + 예상 H < T)
  - "번아웃 예정" (예상 F ≥ 90)
  - **연쇄 예고**: flag 직원의 이웃에 점선 연결 + "소리 퇴사 시 → 바름 행복 44→32 (위험)".
  - "적자 2달째 → 파산" (지난달 적자 + 예상 현금 < 0)

## 월말 리포트 (한 장, 원인→결과, 숫자 근거)
위에서 아래로 4블록, 각 1~3줄. **문장은 공식의 항에서 자동 생성**(가장 큰 항 2개).
1. **돈**: "이번 달 **+420만원** (매출 2,600 − 월급 1,600 − 임대료 600 + …)" + 현금 그래프에 점 추가.
2. **매출 이유**: "주문 70건 중 **52건** 처리 → 놓친 18건 = −900만원". 생산력 막대: 기본 40 × 업무 ×1.15 × 휴식 ×0.90 × 기분 ×1.0 × 숙련 ×1.05 × 피로 ×0.93 (지난달 대비 바뀐 계수 강조). 판매 = D면 "주문 전부 처리 (생산력 여유 8)".
3. **직원** (카드별 1줄): 얼굴 + "행복 60→52 (−8): 업무 과중 −3, 기대보다 월급 20 적음 −2.5" / "피로 30→47 (+17)". 이웃 영향 항이 ±2 이상이면 표시: "옆자리 새봄(85) 덕분 +2".
4. **사건·경고** (빨간 줄 우선):
   - 퇴사: "**소리 퇴사**: 행복 18 (2달 연속 30 미만, 확률 80%). 가장 큰 원인: 월급이 기대보다 45 적음(−5.6/월)."
   - 연쇄: "소리가 떠나서 옆자리 **바름 −12**, **새봄 −12** → 2달간 흔들림(40 미만이면 퇴사 위험). 바름 행복 34 ✉"
   - 예고: "다음 달 위험: 바름 ✉ (행복 34 < 40). 막으려면: 보너스 +10 또는 휴가 +6, 업무량↓"
   - 번아웃, 적자 경고, 사건 결과(스카우트 성공/실패).
- **첫 판 1월 리포트**(최고 기록 없음): 2번 블록을 크게 + 한 줄 "업무량을 올리면 이번 달 처리량이 늘지만, 피로는 다음 달에 쌓여요." 튜토리얼 화면은 없음. 1월 결정 화면 위 한 줄만: "주문이 몰렸어요! 설정을 바꿔 보면 예상 처리량이 바로 변해요."

## 밸런스 검증 (봇 시뮬, 시드 1~200)
`__company.simulate(bot, seed)`로 헤드리스 실행. 아래 수치는 **손계산 추정**이며 시뮬로 확인·조정 필수.

| 봇 | 매달 규칙 | 목표 | 손계산 추정 |
|---|---|---|---|
| 혹사형 | P250, W5, R1, 채용 없음 | **100% 게임오버, 4월 이전** | 2월 말 전원 ✉, 3월 말 전원 퇴사 |
| 천사형 | P400, W1, R5, 채용 없음 | **≥ 90% 파산** (완주해도 ≤ 적응형 50%) | 월 −440 → 5~6월 파산 |
| 균형 고정형 | P300, W3, R3, 채용 없음 | 완주해도 **≤ 적응형 60%**, 70% 이상 시드에서 퇴사 ≥ 1 | 매출 ~21,000, 소리 이직/퇴사 |
| 고정 그리드 | 7×5×5 = 175 조합 × {채용 없음, "가능하면 채용"} | 어떤 조합도 **중앙값 ≤ 적응형 75%** 또는 파산률 ≥ 30% | P400 W3 R3 무채용 ~25,000(≈67%); 6명 고월급은 침체 때 파산 |
| 적응형 | 아래 | **완주율 ≥ 95%, 매출 중앙값 35,000~39,000** (A~S) | ~37,500 |
| 랜덤 | 매달 무작위 | 완주율 < 30% | — |

**적응형 봇 규칙** (위에서부터 적용):
1. 월급 = 25단위 올림(직원 평균 E + 10). H < 45인 직원 있으면 +25. 침체 달이고 예상 현금 < 500이면 −25. clamp 250~400.
2. 업무량 = 예측 처리 ≥ D인 가장 낮은 W. 평균 F ≥ 60이면 최대 W3, ≥ 75면 최대 W2. 12월은 F 무시하고 필요한 만큼(마지막 달 스퍼트는 의도된 전략).
3. 휴식 = 3. 평균 F ≥ 55 → 4. 침체 달 → 5.
4. 개별: F ≥ 75인 직원 중 최고 1명 휴가. flag·shaken·스카우트 대상 중 예상 H < 기준선+5인 직원에 보너스(최대 2명).
5. 채용: 직원 < 6, 침체 달 아님, 지난달 놓친 주문 ≥ 6 또는 다음 달 D > 예측 처리(W3), 현금 − 200 ≥ 800 → 채용, 빈 자리 중 행복 높은 이웃이 많은 자리.

**조정 순서**(목표 미달 시 한 번에 하나): 고정 고월급이 너무 강함 → E 상승 +5→+7 / moodM 계수 0.3→0.25. 천사형 완주 → 단가 50→48. 혹사형이 4월 넘김 → 피로 패널티 /6→/5. 적응형 파산 잦음 → 시작 현금 1,500→2,000 또는 임대료 600→550. 연쇄가 너무 잔인(적응형 퇴사 평균 > 1.5) → 이웃 충격 −12→−10.
**추가 확인**: 평균 한 판 소요(클릭 수 기준) ≤ 8분, 적응형 판에서 연쇄(이웃 ✉ 발생) 1회 이상 나오는 시드 ≥ 40%(연쇄를 실제로 보게).

## 테스트 훅 `window.__company`
| 멤버 | 설명 |
|---|---|
| `state()` | 상태 깊은 복사 (cash, month, staff[], D, event, history[]) |
| `newGame(seed)` | 시드 지정 새 게임 (eligible=false) |
| `decide({pay, work, rest, actions:{seat:'leave'\|'bonus'}, hire: seat\|null})` | 이번 달 결정 주입 (pay는 만원값, work·rest는 1~5) |
| `forecast()` | 예측 패널 결과 객체 |
| `step()` | 한 달 처리, 리포트 객체 반환 (문장 배열 포함) |
| `simulate(bot, seed)` | bot = 'grind'\|'angel'\|'fixed'\|'adaptive'\|'random'\|함수(state→decision). 반환 {completed, months, revenue, cash, quits, chainQuits, bankrupt} |
| `bots` | 위 봇 함수들 |
- 훅 사용 시 그 판 eligible=false. URL `?seed=N`도 동일.
- 시뮬은 DOM·애니메이션 없이 순수 함수로(게임 로직과 렌더 분리).
