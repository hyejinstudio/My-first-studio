# 붕어빵 눈싸움 아트·UI 명세

> slug: `bungeo-snowfight` · `design.md`(격자 크기, 제한 시간, 사거리, 칠하는 범위, 팥붕 지속 시간, 슈붕 튕김 횟수, 재장전 시간, CPU 난이도)와 `sound.md`를 함께 본다. **수치는 design.md가 정하고**, 이 문서는 그것을 어떻게 보여 줄지만 정한다. 아래의 `16×10`, `1:30`, `58%`는 자리 표시용이다. 레이아웃은 격자 **N=14~18 × M=8~12** 어느 값에서도 동작한다.
> 그래픽: **필드 = Canvas 2D 한 장**(격자·붕어빵·발사대·궤적·이펙트), **HUD·패널·오버레이 = DOM + 인라인 SVG**. 이미지 파일·이모지 그래픽 없음.
> 오리지널 원칙: 붕어빵 실루엣은 이 문서의 좌표로 직접 그린 것. 특정 게임(잉크 칠하기 슈팅, 새총 퍼즐 등)의 캐릭터·로고·색 조합·UI를 따라 하지 않는다.

## 스타일 콘셉트
- "조용한 눈밭에서 하는 붕어빵 땅따먹기": 연한 회청 눈밭 격자 위로 갓 구운 붕어빵이 포물선을 그리며 날아가고, 떨어진 자리의 눈이 내 편 색으로 동그랗게 번지듯 물든다.
- **눈 피로 최소화 (사용자 누적 취향)**: 채도를 낮춘 파랑·분홍 두 진영 색, 칸 경계는 1px 연한 선, 외곽선 1.5px 같은 계열 색. 화면 흔들림·깜빡임·광택·그라데이션 없음. 무늬(줄무늬·물방울)는 진영 색보다 한 톤만 진하게.
- **진영 색은 붕어빵 색(갈색·황금)과 겹치지 않는 차가운 파랑 vs 부드러운 분홍.** 색 + **무늬(줄무늬 vs 물방울)** + **명도 차(파랑이 어둡고 분홍이 밝음)** 세 가지로 구분 → 색맹이어도 구분된다.
- 붕어빵 2종은 **같은 실루엣**, 색(진갈색 vs 황금색)·크기(팥붕 큼 vs 슈붕 작음)·속 무늬(검붉은 팥 자국 vs 흰 크림 자국)로 구분.
- 스튜디오 공통: 따뜻한 종이색 페이지 배경(`--bg`), 흰 패널, 주황 강조(`--accent`), 둥근 모서리, 그림자 대신 면 색 차이. 상단 바·오버레이 구조는 두더지 뿅뿅·개구리 텐과 같다.
- 글꼴: 글자는 사이트 공통 `system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`. **숫자(시간·점유율 %·카운트다운·결과)는 BungeoDigits**(아래).

### 숫자 글꼴 BungeoDigits (Pretendard ExtraBold 800 서브셋, SIL OFL 1.1)
- 두더지 뿅뿅 `mole-digits-800.woff2`와 같은 방식. 원본 Pretendard **ExtraBold(800)**.
- 파일: `games/bungeo-snowfight/fonts/bungeo-digits-800.woff2` + 같은 폴더 `OFL.txt`(Pretendard 저작권 줄 + OFL 1.1 본문, 기존 게임 것 복사 가능).
- 글리프: `0-9`(U+0030–0039), `%`(U+0025), `:`(U+003A), `.`(U+002E). **`tnum`(고정폭 숫자) 유지** — 시간·%가 바뀌어도 폭이 흔들리지 않게.
  - 예: `pyftsubset Pretendard-ExtraBold.otf --unicodes="U+0030-0039,U+0025,U+003A,U+002E" --flavor=woff2 --layout-features='tnum' --output-file=bungeo-digits-800.woff2` 후 fontTools로 name 테이블 교체.
- **Reserved Font Name 때문에 이름 변경 필수**: family/full/PostScript/typographic 이름 모두 `BungeoDigits`, 압축 해제 바이트에 "Pretendard" 문자열이 없어야 함(QA가 fontTools로 확인 — 기존 게임과 같은 검사). 다른 게임의 서브셋 파일은 `%`가 없으므로 재사용 금지. 원본을 못 받으면 CEO에게 보고.
```css
@font-face { font-family: "BungeoDigits"; src: url("fonts/bungeo-digits-800.woff2") format("woff2");
  font-weight: 800; font-style: normal; font-display: swap;
  unicode-range: U+0030-0039, U+0025, U+003A, U+002E; }
:root { --num-font: "BungeoDigits", system-ui, -apple-system, "Apple SD Gothic Neo", sans-serif; }
.num { font-family: var(--num-font); font-weight: 800; font-variant-numeric: tabular-nums; }
```
- 캔버스 안 카운트다운 숫자도 `ctx.font = '800 <px> BungeoDigits, system-ui'`. 첫 그리기 전에 `document.fonts.load('800 20px BungeoDigits')`를 기다린다(실패해도 진행).

## 레이아웃 (PC / iPad 세로 / iPad 가로)

### 구성 요소
```
가로 (landscape: innerWidth ≥ innerHeight)
[← 게임 목록] 붕어빵 눈싸움  ▤42% [▤▤▤▤▤▤(1:23)░░••••] 38%•  [🔈][Ⅱ]   ← 상단 바 52px
┌패널A┐ ┌──────────────── 필드 캔버스 ────────────────┐ ┌패널B┐
│ 나  │ │기지│ 16×10 눈밭 격자                   │기지│ │컴퓨터│
│ 42% │ │ ◎ │ ▤▤▤▤▤░░░░░░•••••                 │ ◎ │ │ 38% │
│[팥붕]│ │발사│                                    │발사│ │[팥붕]│
│[슈붕]│ │대  │                                    │대  │ │[슈붕]│
└─────┘ └────────────────────────────────────────┘ └─────┘

세로 (portrait)
[상단 바]
(iPad: "가로로 돌리면 더 크게 보여요" 안내 알약 28px)
┌──────────── 필드 캔버스 (화면 너비) ────────────┐
└──────────────────────────────────────────────┘
┌── 패널A (왼쪽 절반) ──┐ ┌── 패널B (오른쪽 절반) ──┐
│ 나 42% [팥붕][슈붕]   │ │ [팥붕][슈붕] 38% 컴퓨터 │
└───────────────────────┘ └─────────────────────────┘
```
- **필드 캔버스** = 왼쪽 기지 띠 1.5c + 격자 N·c + 오른쪽 기지 띠 1.5c, 높이 M·c. 즉 캔버스 크기 `(N+3)·c × M·c`. 기지 띠는 `--base` 단색, 격자 바깥 테두리 2px `--field-edge`(캔버스 안쪽에 그림), radius 12px(CSS `border-radius` + `overflow:hidden`이 아니라 캔버스에 직접 둥근 사각 clip).
- 발사대는 각 기지 띠 가로 가운데(필드 가장자리에서 0.75c 바깥), 세로 위치는 design.md(고정 가운데 또는 이동 가능). 진영 패널은 DOM.

### 높이 기준 레이아웃 규칙 (필수)
1. `--app-h` = `window.innerHeight + 'px'`, `resize`·`orientationchange`·`visualViewport.resize` 때 갱신. CSS 기본값 `100dvh`(미지원 `100vh`). `100vh` 단독 금지.
2. `html, body { height: var(--app-h); overflow: hidden; }`, body 패딩 `max(12px, env(safe-area-inset-*))` 네 방향, viewport meta `width=device-width, initial-scale=1, viewport-fit=cover`.
3. `W` = innerWidth − 좌우 패딩, `H` = app-h − 상하 패딩. 상단 바 `TB = 52`(높이 ≤ 520px이면 44), 아래 간격 8.
4. **가로**: 패널 너비 `P = clamp(84, round(0.1·W), 128)`, 패널–캔버스 간격 8.
   `c = floor(min((W − 2P − 16) / (N+3), (H − TB − 8) / M, 64))`.
   패널 높이 = 캔버스 높이(M·c). `.stage`(패널+캔버스+패널)는 남은 공간 가운데.
5. **세로**: 패널 줄 높이 `Q = clamp(112, round(0.13·H), 150)`, 두 패널은 너비 반반(간격 8). iPad(짧은 변 ≥ 600) 안내 알약 28 + 8.
   `c = floor(min(W / (N+3), (H − TB − 8 − [36] − 8 − Q) / M, 64))`.
6. `c` 하한 16(그 이하라도 그려지기만 하면 됨). 캔버스 내부 해상도 = CSS 크기 × `min(devicePixelRatio, 2)`.
7. JS가 `--c`, `--cw`(캔버스 CSS 너비), `--ch`, `--P`, `--Q`를 넣는다. **크기가 바뀌어도 게임 상태는 칸 좌표 기준이라 그대로**(비행 중인 붕어빵도 칸 단위 좌표로 저장해 다시 그리기만).
8. 수치표 (패딩 12px, 안전 영역 0 기준. `c(16×10)` / `c(18×12)`):

| 화면 | W × H | 배치 | P 또는 Q | c 16×10 | 캔버스 16×10 | c 18×12 |
|---|---|---|---|---|---|---|
| PC 1280×800 | 1256 × 776 | 가로 | P 126 | **52** | 988 × 520 | 47 |
| iPad 가로 1080×810 | 1056 × 786 | 가로 | P 106 | **43** | 817 × 430 | 39 |
| iPad 가로 1080×740 | 1056 × 716 | 가로 | P 106 | **43** | 817 × 430 | 39 |
| iPad 세로 810×1080 | 786 × 1056 | 세로 + 안내 알약 | Q 137 | **41** | 779 × 410 | 37 |
| 폰 가로 844×390 | 820 × 366 | 가로, TB 44 | P 84 | **31** | 589 × 310 | 26 |
| 폰 세로 390×844 | 366 × 820 | 세로 + **회전 안내 오버레이** | Q 112 | **19** | 361 × 190 | 17 |

9. **검증 기준** (QA와 공유): 6개 뷰포트 모두 `scrollWidth ≤ innerWidth`, `scrollHeight ≤ innerHeight`, 캔버스·두 패널 `getBoundingClientRect()`가 화면 안(bottom ≤ innerHeight − 4), 붕어빵 종류 버튼 ≥ 44×44(가로 iPad·PC는 ≥ 64), 상단 바 버튼 44×44. 390×844에서 회전 안내 오버레이에 "세로로 계속하기"와 "← 게임 목록"이 보임. 844×390에서 시작 오버레이의 "시작하기"가 화면 안.

### 상단 바
- 순서: `← 게임 목록` · 제목 "붕어빵 눈싸움"(18px 800) · **점유율 묶음**(flex 1) · 음소거 · 일시정지.
- **점유율 묶음**: `[A 견본 18px][A% .num 18px] [막대] [B% .num][B 견본]`, 가운데에 **시간 알약**이 막대 50% 지점 위에 겹쳐 놓인다.
  - 막대: 높이 14px, radius 999, 트랙 `--snow` + 1px `--snow-line` 테두리. 왼쪽부터 A 칸 비율만큼 `--team-a` + 줄무늬(`repeating-linear-gradient(135deg, var(--team-a-pat) 0 2px, transparent 2px 7px)`), 오른쪽부터 B 비율만큼 `--team-b` + 물방울(`radial-gradient(circle, var(--team-b-pat) 1.4px, transparent 1.6px) 0 0 / 7px 7px`). 가운데 빈 눈은 트랙 그대로. 너비 변화는 `transform: scaleX()`(origin 각 끝) 200ms ease-out.
  - **임시 부분 (v2)**: 각 진영 막대를 2구간으로 — 바깥 끝(자기 쪽)부터 **영구 비율은 진하게**(위 색+무늬 그대로), 그 안쪽(가운데 쪽)에 **임시 비율은 옅게**: 같은 색·같은 무늬 opacity .42 + 위·아래 1px `--team-?-ink` α .5 점선(`border-block: 1px dashed`). 영구–임시 경계에 1px `--panel` 틈. 즉 `A[영구▓▓][임시░░]  빈 눈  [░░임시][▓▓영구]B`. 임시 칸이 바래면 임시 구간만 줄어들고, 영구 확정되면 경계가 가운데 쪽으로 이동(둘 다 200ms ease-out).
  - % 숫자는 design.md 점수 기준(임시 포함 여부)을 그대로 표시. 임시 몫은 진영 패널의 `임시 n%` 줄로만 보조 표시(상단 바에는 숫자 추가 안 함 — 좁음).
  - 50% 기준선: 막대 위·아래로 3px 튀어나온 1px `--muted` 선(알약에 가려지지 않게 알약 바로 위·아래에만 보임).
  - 견본: 18×18 radius 5, 진영 색 + 같은 무늬(줄무늬 / 물방울 2×2). 1인 모드는 견본 옆 라벨 "나" / "컴퓨터"(12px 700 `--team-?-ink`), 2인 모드는 "왼쪽" / "오른쪽".
  - %: 정수 + `%`(예 `42%`), 색 `--team-?-ink`. 이기고 있는 쪽 %는 굵기 그대로, 이름 앞에 작은 ▲ 없음(색·위치로 충분 — 시끄럽지 않게).
- **시간 알약**: 높이 32, 최소 너비 72, `--panel` 바탕, 1px `--grid`, radius 999, `.num` 18px `m:ss`(예 `1:23`). 마지막 10초 `--danger` + 매 초 scale 1→1.08→1(200ms). 화면 깜빡임 없음.
- 버튼 2개(음소거·일시정지) 44×44, 두더지 뿅뿅과 같은 SVG 아이콘·`aria-label`. 아이콘 전환은 **`el.toggleAttribute('hidden', bool)`** (SVG 요소에는 `.hidden` 속성이 없음 — 교훈).

### 1인 모드 세로 필드 (v4) — 나는 아래, 컴퓨터는 위
사용자 요청: "AI와 함께하는 1인용 모드에서는 사용자가 아래 있고 AI가 위에 있는 형식으로." → **화면에 그릴 때만 90° 돌린다.** 논리 좌표(16×10, P1 발사대 `(−0.6, 5)`, P2 `(16.6, 5)`)·규칙·AI·판정·`window.__bungeo`는 그대로. 2인 모드는 지금 가로(왼쪽 vs 오른쪽) 그대로.

**회전 규칙 (방향 고정, 좌우 반전 없음)**
- 논리 x(0 → 16, P1 → P2) = 화면 **아래 → 위**. 논리 y(0 → 10) = 화면 **왼 → 오**.
- 즉 논리 칸 좌표 `(x, y)` → 화면 `(X, Y) = (y·c, SH − (BOT + x)·c)`. 화면에서 보면 **반시계 90° 회전**(오른쪽을 보던 것이 위를 봄). 행렬식 +1인 순수 회전이라 거울상이 아니다 — P1이 위를 보고 섰을 때 왼손 쪽(논리 −y)이 화면 왼쪽.
- 진영 무늬·글자·숫자·고리·점선·궤적 점은 **똑바로**(아래 '그리기 구현 지침'). 붕어빵은 날아가는 방향으로 머리(회전 결과 그대로 맞음: 내 붕어빵은 위로, 컴퓨터 붕어빵은 아래로 머리).

**세로 필드 캔버스 = 폭 10c × 높이 20c**
- 위: 컴퓨터 기지 띠 **1.5c**(P2 발사대 중심이 필드 위 끝에서 0.6c 위) / 가운데: 격자 10열 × 16행 / 아래: 내 기지 띠 **2.5c**(가로 모드 1.5c보다 1c 넓음).
- 아래 띠를 넓힌 이유: 내 발사대 중심이 캔버스 아래 끝에서 1.9c 위에 오므로, 발사대를 바로 잡고 **아래로 끝까지 당겨도 손가락이 화면 아래 끝을 넘지 않는다**(아래 '당겨 쏘기' — 화면 최대 당김 2.2c ≤ 1.9c + 아래 패딩 12px, c ≤ 40에서 성립, c 49인 iPad 세로는 3px 차라 무시). 넓어진 띠는 "내 기지" 자리로 읽혀 손가락 놓을 곳도 넓어진다.
- 기지 띠·칸·테두리·radius 12 등 모양은 가로와 같다. 코드상 그리기 원점 `OX = 2.5c`, 논리 그리기 길이 `CWv = 20c`(= 2.5 + 16 + 1.5), 화면 캔버스 `SW × SH = 10c × 20c`.

**배치 고르기** (`S.mode === 'ai'`일 때만. W, H, TB, 패딩은 기존 '높이 기준 레이아웃 규칙' 그대로)
1. **옆 배치(side)**: `[내 패널 | 세로 필드 | 컴퓨터 패널]` — `cSide = floor(min((W − 2·96 − 24)/10, (H − TB − 8)/20, 64))`
2. **위아래 배치(stack)**: `[컴퓨터 띠 K] / [세로 필드] / [내 패널 Q]` — `K = 52`, `Q = clamp(112, round(0.13·H), 150)`, `cStack = floor(min(W/10, (H − TB − 8 − K − 8 − Q − 8)/20, 64))`
3. `max(cSide, cStack) ≥ 24`이면 큰 쪽(같으면 side)을 쓰고, **둘 다 24 미만이면 예외로 기존 가로 배치**(왼쪽 나 vs 오른쪽 컴퓨터, 기존 c 식). 24 = 팥붕 길이 23px로 "붕어빵이 붕어빵으로 보이는" 하한. 현재 6개 화면 중 **폰 가로(844×390)만 예외**(세로라면 c 16).
4. side의 패널 너비: `P = clamp(floor((W − 10c − 24)/2), 96, 160)`, 패널–캔버스 간격 12. 무대 너비 `2P + 24 + 10c`, 높이 `20c`, 가운데 정렬.
5. JS가 `--c --cw(=10c) --ch(=20c) --P --Q --K --sw`를 넣고, `.stage`에 `vert` + `side`/`stack` 클래스(QA가 이 클래스로 세로 여부를 확인). `ov-full` 판정은 기존 식(무대 높이 < 460 또는 너비 < 600) 그대로.
6. **모드가 바뀔 때마다 `layout()` 다시**: 시작 화면 모드 버튼 클릭, `startGame`, `toMenu`. 시작 화면 뒤에 보이는 필드 모양도 고른 모드를 따른다. 크기가 바뀌어도 게임 상태는 칸 좌표라 그대로.

**패널**
- **side**: 내 패널(`#panel1`)은 **왼쪽 열, 아래 맞춤**(`align-self: end` — 패널 아래 = 캔버스 아래 = 화면 아래쪽, 왼손 엄지로 종류를 바꾸고 오른손으로 당기는 자리). 컴퓨터 패널(`#panel2`)은 **오른쪽 열, 위 맞춤**(`align-self: start` — 상대 기지와 같은 높이). 즉 "왼쪽 = 나 / 오른쪽 = 컴퓨터"는 가로 모드·상단 바와 같고, 높이로 "아래 = 나 / 위 = 컴퓨터"를 더한다. 패널 높이는 캔버스에 늘이지 않고 내용 높이(약 268): 머리·%·임시 줄 → 버튼 2개 세로(각 `P − 16` × **88**, 간격 8). 패널 안 구성·선택/재장전 표시는 기존과 같다. 남는 열 공간(내 패널 위, 컴퓨터 패널 아래)은 비워 둔다(조용하게).
- **stack** 컴퓨터 띠(K 52, 너비 W, `--panel` 카드 radius 14, 패딩 4px 10px): 한 줄 `[견본 16][컴퓨터 13px 700][27% .num 18px][임시 n칸 11px]` …… 오른쪽 끝 `[팥붕][슈붕]` 보기 전용 칩 2개(각 76 × 40, 아이콘 팥붕 26px / 슈붕 21px + 이름 12px 700 **`white-space: nowrap`**, 아래 재장전 막대 4px, 선택된 칩은 기존처럼 tint 바탕 + 2px `--team-b-ink` 테두리, 체크 원은 생략). `disabled`라 44px 규칙 대상 아님.
- **stack** 내 패널(Q, 너비 W): 기존 세로 패널 한 줄 형식 `[머리·% 70][팥붕][슈붕]`, 버튼 `abw = clamp((W − 16 − 70 − 24)/2, 64, 110)` × `Q − 18`(폰 세로 110 × 94).

- 상단 바 너비 = `min(W, max(무대 너비, 560))` 기존 식 그대로.

**시작 화면 문구 (1인 세로일 때만 바꿈 — 가로 예외·2인은 기존 문구)**

**당겨 쏘기 (세로)**

**카운트다운·마지막 3초 큰 숫자·오버레이**
- 카운트다운 `3 2 1 시작!`, 마지막 3초 숫자: 위치 = **화면 캔버스 가운데**, 크기 기준을 `캔버스 높이` 대신 **`M·c`(= 필드 폭 10c)**로 — 가로 모드와 같은 크기(0.32·10c / 0.42·10c). 세로 캔버스 높이(20c)를 쓰면 "시작!"이 폭을 넘는다. 똑바로 그린다(회전 변환 밖에서).
- 일시정지·결과·시작 오버레이: 변화 없음(무대 위 absolute — 무대 모양만 세로로 바뀜). 결과의 숫자 순서는 왼쪽 나 / 오른쪽 컴퓨터 그대로(상단 바·패널과 같은 좌우).

**그리기 구현 지침 (권장: 캔버스 변환 한 번 + '똑바로' 예외 목록)**
좌표 변환 함수로 모든 `gx()/gy()` 호출을 바꾸는 방식은 고칠 곳이 수백 군데라 위험하다. **논리 좌표로 그리는 기존 함수는 그대로 두고, 그리기 시작할 때 변환만 바꾼다.**
1. 변환: `VERT`이면 `g.setTransform(0, −DPR, DPR, 0, 0, SH·DPR)`(= `translate(0, SH)` + `rotate(−π/2)`), 아니면 기존 `setTransform(DPR, 0, 0, DPR, 0, 0)`. 함수 하나(`viewT(g, SH)`)로 만들어 `draw()`(실제 필드), `drawBase()`(바닥 오프스크린), `tipDrawAll()`(미니 눈밭) 세 곳에서 쓴다. `withView(c, OX, tiles)`는 그대로.
2. 순서: 화면 좌표로 `clearRect(0,0,SW,SH)` → 둥근 사각 clip `(0,0,SW,SH,12)` → `drawImage(baseCv, 0,0,SW,SH)`(바닥은 이미 회전돼 그려져 있음) → `save; viewT` → 칸 애니·임시 칸·장애물·발사대·궤적·비행·이펙트 → `restore` → 카운트다운·마지막 3초 숫자(화면 좌표). 캔버스·baseCv 픽셀 크기 = `SW·DPR × SH·DPR`.
3. **'똑바로' 예외** (회전 변환 안에서 그려지지만 화면 기준으로 맞춰야 하는 것 — 이것만 고친다):
   - **줄무늬 타일**: 세로용 타일은 사선을 반대 대각선으로 그린다 — `moveTo(k, 0) lineTo(k + c, c)`(가로용은 `moveTo(k, c) lineTo(k + c, 0)`). −90° 회전 뒤 화면에서 가로 모드·HUD 견본과 같은 ↗ 방향이 된다. 물방울 타일(3×3 대칭)은 그대로. 실제 필드 타일·Tip 타일 모두 `VERT`가 바뀌면 다시 만든다(캐시 키에 방향 포함). 90° 회전이라 픽셀이 흐려지지 않음.
   - **높이(띄우기)**: 비행 붕어빵을 그림자에서 띄우는 방향은 항상 **화면 위**. 논리 px 벡터 `UP = VERT ? (+1, 0) : (0, −1)`로 `drawFish(X + UP.x·h·c, Y + UP.y·h·c, …)`. 장애물 그림자의 아래 오프셋(0.06c)도 `−UP`.
   - **타원**: 그림자·눈가루 고리 타원은 화면에서 가로로 납작해야 하므로 `ellipse(…, rotation = VERT ? π/2 : 0, …)`.
   - **팥붕 남은 시간 고리**: 시작각 `−π/2 + (VERT ? π/2 : 0)`(화면 12시), 시계 방향 유지(회전이라 방향 안 바뀜). 던진 쪽 점은 중심 `− UP·R`(화면 6시).
   - **글자**('장전 중', '취소', '깨기'): `upright(g, X, Y, fn)` = `save; translate(X, Y); if (VERT) rotate(π/2); fn(); restore` 안에서 `(0, 0)` 기준으로 그린다. 위치 오프셋은 `UP`으로(예: 발사대 + UP·0.95c, ✕ 위 '깨기'는 ✕ + UP·(m + 2)).
   - **흔들림**: 발사대 둔덕 흔들림은 화면 좌우 = 논리 `VERT ? (0, ±1) : (±1, 0)`.
   - 그대로 두는 것(회전돼도 맞음): 붕어빵 모양·머리 방향·눌림(로컬 축), 장애물 흔들림 각도, 원(둔덕·착지 점선 원·궤적 점·손가락·부스러기), 칸 사각·점선 안쪽 테두리·미리보기 사각, ✕.
4. 입력은 위 '당겨 쏘기 (세로)'의 역변환 한 곳(`aimInfo`)만.

## 필드 그리기 (Canvas 2D)

### 레이어 / 그리는 순서
1. **바닥 레이어(오프스크린 캔버스, 영구 칸이 바뀔 때만 다시 그림)**: 기지 띠 `--base` → 칸(빈 칸 `--snow` / A 영구 칸 무늬 타일 / B 영구 칸 무늬 타일) → 칸 경계 1px `--snow-line`(모든 칸에, 칠한 칸 사이도 같은 연한 선) → 필드 테두리 2px `--field-edge`. **임시 칸은 바닥 레이어에 넣지 않는다** — 바닥에는 그 칸이 바랜 뒤 돌아갈 상태(되돌아갈 영구 상태)가 그려져 있다.
2. **임시 칸 오버레이**(매 프레임, 아래 '임시 칸' 참고) → 칠해지는 중인 칸(애니메이션)
3. 팥붕 장애물(그림자 → 붕어빵 → 타이머 고리)
4. 발사대 2개 + 장전된 붕어빵
5. 예상 궤적(당기는 중일 때)
6. 비행 중 붕어빵(그림자 → 붕어빵) — 높은 것이 위에 오게 높이순
7. 이펙트(눈가루, 부스러기)
8. 카운트다운 숫자
- 매 프레임 = 바닥 레이어 `drawImage` 1번 + 움직이는 것만. 칸마다 무늬를 매 프레임 그리지 않는다.

### 칸 무늬 타일 (c×c 오프스크린, `createPattern` 대신 칸마다 `drawImage`해서 칸 경계와 무늬가 항상 맞게)
- **A 줄무늬**: 바탕 `--team-a`, `--team-a-pat` 선 굵기 `max(1.5, c/24)`px, 45°(왼쪽 아래 → 오른쪽 위) 사선, 간격 c/3(칸당 3줄). 칸 경계에서 선이 이어지도록 k = −c … 2c, 간격 c/3로 `moveTo(k, c) lineTo(k + c, 0)`.
- **B 물방울**: 바탕 `--team-b`, `--team-b-pat` 점 3×3, 중심 `(c/6 + i·c/3, c/6 + j·c/3)`, 반지름 `max(1.4, c/22)`.
- c < 22이면 무늬를 2줄 / 2×2 점으로 줄인다(작은 화면에서 지저분하지 않게).

### 붕어빵 실루엣 (두 종류 공통, 오리지널)
로컬 좌표: 머리가 +x, 몸 길이 약 96(−48~48), 폭 54(−27~27). 화면 크기로 `scale(s)`, `s = 길이px / 96`.
```js
function fishPath(g){ g.beginPath();
  g.moveTo(48,0); g.bezierCurveTo(48,-17,33,-27,12,-27); g.bezierCurveTo(-8,-27,-22,-19,-30,-8);   // 머리→등
  g.quadraticCurveTo(-38,-16,-45,-20); g.quadraticCurveTo(-50,-21,-48,-15);                        // 꼬리 위 둥근 끝
  g.quadraticCurveTo(-42,0,-48,15);                                                                // 꼬리 오목
  g.quadraticCurveTo(-50,21,-45,20); g.quadraticCurveTo(-38,16,-30,8);                             // 꼬리 아래 끝
  g.bezierCurveTo(-22,19,-8,27,12,27); g.bezierCurveTo(33,27,48,17,48,0); g.closePath(); }
```
같은 모양의 SVG path(패널 버튼·범례·목록 아이콘용):
`M48 0C48-17 33-27 12-27C-8-27-22-19-30-8Q-38-16-45-20Q-50-21-48-15Q-42 0-48 15Q-50 21-45 20Q-38 16-30 8C-22 19-8 27 12 27C33 27 48 17 48 0Z` (viewBox 예: `-52 -31 104 62`)

그리는 순서(로컬 좌표, 선 굵기는 `화면px / s`로 환산해 화면에서 일정하게):
1. `--halo` 테: fishPath를 화면 4.5px로 stroke(바깥 약 3px만 보임).
2. 몸: fill `--pat` / `--shu`.
3. 속 자국: 팥붕 = `ellipse(-3, 0, 15, 8)` fill `--pat-bean` α .55 / 슈붕 = `ellipse(-2, 0, 13, 6.5)` fill `--shu-cream` + 1px `--shu-mark` 테.
4. 무늬 선(화면 1.3px, `--pat-mark` / `--shu-mark`, round cap): 아가미 `moveTo(20,-16) quadraticCurveTo(27,0,20,16)`, 비늘 호 3개 `arc(2,-8,6, .15π, .85π)`, `arc(2,8,6,…)`, `arc(-12,0,6,…)`, 꼬리 선 `(-35,-5)→(-42,-12)`, `(-35,5)→(-42,12)`, 눈 자국 `arc(32,-9,3.6)` stroke만(얼굴 표정 없음 — 틀에 찍힌 눈 자국).
5. 외곽선: fishPath 화면 1.5px `--pat-edge` / `--shu-edge`.

| 화면 길이 | **0.96c** (폭 약 0.54c) | **0.76c** (폭 약 0.43c) |

### 팥붕 장애물 (필드에 남은 팥붕)
- 칸 가운데(또는 착지 지점)에 팥붕을 그대로 그린다(길이 0.96c, 착지 각도). 그림자는 비행보다 진하게 고정(α 그대로).
- **남은 시간 고리**: 중심 같은 원, 반지름 0.56c, 화면 2.5px. 트랙 `--ink` α .14 전체 원. 남은 부분 `--team-?-ink`(던진 쪽) α .8, 12시에서 시작해 **시계 방향으로 줄어듦**(남은 비율 × 360°). 끝은 round cap.
- 던진 쪽 표시는 고리 색 + 고리 아래쪽 6시 위치에 **작은 견본 점**(지름 6px, A는 줄무늬 대신 단색 원, B는 원 안 흰 점 1개 — 색 외 구분). 
- 마지막 1000ms: 붕어빵 α 1 → .55 서서히(깜빡이지 않음). 사라짐: scale 1 → .7 + α → 0, 240ms, 갈색 부스러기 4개(반지름 0.05c `--pat`)가 0.35c 바깥으로.
- 장애물이 칸을 막는 규칙(통과/튕김/칠하기 불가 등)은 design.md. 붕어빵이 장애물에 막히면: 날던 붕어빵은 장애물 가장자리에서 멈추고(규칙에 따라 그 자리 착지/소멸), 장애물은 회전 ±6° 흔들림 160ms + 작은 눈가루 고리.

### 슈붕 통통 튀기기와 사라짐
- 각 홉은 포물선. 첫 비행 높이 `H1 = 1.0c`, 다음 홉 높이 ×0.55, 홉 시간·거리는 design.md.
- 착지마다: 눌림 scaleX 1.18 / scaleY .82(진행 방향 기준) 80ms → 복귀 80ms, 눈가루 점 3개 퍼짐(아래), 해당 칸 칠하기 시작.
- 마지막 착지 후 사라짐: 그 자리에서 scale 1 → .5 + α 1 → 0, 260ms easeInCubic, 노란 부스러기 3개(`--shu`, 반지름 0.04c) 0.4c 바깥으로 α → 0.
- 팥붕은 착지 시 한 번만 "털썩": scaleX 1.1 / scaleY .9 120ms 복귀 + 눈가루 고리. 그 뒤 장애물로 남는다.

### 칠해질 때 (칸 색 바뀜)
- 칸마다 **원형 번짐**: 새 색 타일을 `clip(arc(착지점, r))`로 그리며 r 0 → (착지점에서 칸 먼 모서리까지 거리) 240ms easeOutCubic. 착지점에서 칸 거리 d(칸 단위)만큼 시작 지연 `35ms × d` → 물결처럼 바깥으로.
- 상대 칸을 빼앗을 때도 같은 효과(새 색이 옛 색 위로 번짐). 이미 내 칸이면 효과 없음.
- 번짐이 끝나면 바닥 레이어에 그 칸을 다시 그려 확정. 점유율 숫자·막대는 **판정 즉시** 갱신(번짐은 보여주기만).

### 임시 칸 (슈붕이 칠한 칸 — v2)
규칙(design.md): 슈붕이 칠한 칸은 **임시**, 약 6초(최종값 `T_temp`는 design.md) 뒤 바래서 칠하기 전 상태(빈 눈 또는 상대 영구 칸)로 되돌아간다. 팥붕이 칠한 칸은 영구. 내 임시 칸 위에 내 팥붕이 칠하면 영구로 확정.

**한눈에 구분 (영구 vs 임시)** — 같은 진영 색·같은 무늬를 쓰되 세 가지를 다르게:
1. **옅음**: 임시 칸은 진영 무늬 타일을 `globalAlpha = a(t)`로 바닥(되돌아갈 상태) 위에 겹쳐 그린다. 영구 칸은 α 1. → 바닥이 비쳐 보이므로 "바래면 무엇으로 돌아가는지"가 저절로 보인다.
2. **점선 안쪽 테두리**: 칸 안쪽 `inset = max(2, c/14)`px 사각, 선 화면 1.5px, `--team-?-ink`, 대시 `[max(3, c/8), max(2, c/12)]`, α `0.55 × a(t)/a0`. 영구 칸에는 테두리가 없다 → **색을 못 봐도 "점선 테두리 = 임시"**로 구분. 무늬(줄무늬/물방울)는 그대로라 진영 구분도 유지.
3. **모서리 남은 시간 표시 없음**(칸마다 링을 그리면 화면이 시끄러움 — 남은 시간은 옅어지는 정도로만 보여 준다).
- 인접한 임시 칸끼리도 칸마다 테두리를 따로 그린다(칸 단위로 사라지므로).

**옅어지는 곡선** (`t` = 칠한 뒤 경과 ms, `T = T_temp`, 경고 구간 `W = 1500`):
- `a0 = 0.78`. `t ≤ T − W`: `a = 0.78 − 0.33·(t / (T − W))` → 0.78에서 0.45까지 linear로 서서히.
- 경고 구간 `T − W < t ≤ T`: 기본 `a`는 0.45 → 0.30으로 linear, **점선 테두리만 느린 맥동**: 테두리 α = `0.55 × (0.65 + 0.35·cos(2π·u/1000))`(u = 경고 구간 경과 ms) → **주기 1000ms(1Hz), 1.5회**, 칸 채움 자체는 맥동하지 않음. 깜빡임(켜짐/꺼짐)·색 반전·크기 변화 없음.
- 같은 슈붕 한 발이 칠한 칸들은 칠한 시각이 약간씩 달라도(홉마다) 칸별 `t`로 계산 → 물결처럼 순서대로 바랜다.
- 일시정지 중 `t` 멈춤(게임 시간 기준). 시간 종료 순간 모든 임시 칸의 `t`를 멈춘 채 결과를 표시(판정 포함 여부는 design.md).

**바랠 때 (되돌아감)** — 320ms easeInCubic:
- 임시 오버레이를 칸 중심 기준 원형 clip으로 **반지름 (칸 대각 반) → 0으로 줄이며** α 0.30 → 0, 점선 테두리는 같은 시간 α → 0. 칠할 때 번지던 효과의 반대 방향이라 "녹아 사라짐"으로 읽힌다. 아래 바닥(빈 눈 / 상대 영구 칸)이 그대로 드러남 — 바닥 레이어는 다시 그릴 필요 없음.
- 작은 눈가루 점 2개(`--puff`, 반지름 0.04c, 0.2c 바깥, α .5 → 0) — 선택 구현. 소리는 sound.md.
- 판정(점유율 감소)은 바래기 시작하는 순간 즉시 반영.

**영구 확정 (내 임시 칸 위에 내 팥붕)** — 280ms:
- 칸 칠하기와 같은 원형 번짐으로 영구 타일(α 1)이 임시 위로 번지고, 번짐이 끝나면 바닥 레이어에 영구로 그림.
- 점선 테두리가 **실선으로 바뀌었다가 사라짐**: 점선 제거 → 같은 위치 실선 1.5px `--team-?-ink` α .6 → 0, 280ms ease-out. "점선이 굳어 실선이 됐다"는 신호. 칸 크기 변화·번쩍임 없음.
- 상대 임시 칸 위에 팥붕이 칠하면 일반 빼앗기(번짐)와 같고, 임시 오버레이는 번짐과 함께 제거.
- 임시 칸 위에 다시 슈붕(같은 편)이 칠하면 `t`를 0으로 되돌림: 오버레이 α가 현재 값 → 0.78로 160ms ease-out 회복(번짐 없음). 상대 슈붕이면 상대 임시 칸으로 번짐(바닥은 그대로).

**성능**: 임시 칸은 칸 목록(`{x, y, team, t0}`)으로 들고 매 프레임 `drawImage(무늬타일)` + `strokeRect` 한 번씩. α는 0.02 단위로 반올림해도 됨. 수십 칸 수준이라 바닥 레이어 재그리기보다 싸다.

### 발사대 (양쪽 기지 띠)
- 눈 둔덕: 원 반지름 0.55c, fill `--snow`, 테두리 화면 2.5px `--team-?-ink` α .8 (진영 표시).
- 기둥 2개: 발사 방향에 수직으로 ±0.42c 떨어진 원 반지름 0.11c, `--post`. (기본 발사 방향은 상대 쪽 +x / −x, 기둥은 위·아래에 놓임)
- 고무줄: 평소엔 두 기둥 사이 직선, 당기는 중엔 기둥 → 주머니(당긴 점) → 기둥 두 선, 화면 2px `--band`.
- 장전된 붕어빵: 주머니 위치에 선택된 종류를 조준 방향으로. 장전 중(재장전 미완)이면 주머니 비고 둔덕 α .6.
- 컴퓨터 발사대: 던지기 250ms 전부터 고무줄이 뒤로 당겨지는 모습(궤적 점은 그리지 않음) → 손을 놓는 것처럼 튕김. 플레이어가 날아올 것을 미리 알 수 있게.

### 예상 궤적 점선
- 위에서 내려다본 직선 경로를 따라 점, 간격 0.4c. 점 반지름 `2 + 3·sin(πt)`px(t = 경로 진행 0~1) — **가운데가 큰 점 = 포물선 높이 표현**. 색 `--ink` α .42.
- 착지 표시: 착지점에 점선 원 반지름 0.45c, 화면 2px, `[5,4]` 대시, `--ink` α .7. 칠해질 칸(design.md 범위)을 `--team-?-ink` α .35 1.5px 사각 테두리로 미리 표시.
- 슈붕: 첫 착지 뒤 튕김 경로를 같은 방식으로 이어 그리되 홉마다 점 α .42 → .3 → .2, 착지 원은 작게(0.3c). 튕김에 무작위가 있으면 **첫 착지까지만** 그린다.
- 장애물에 막힐 경로면 막히는 지점까지만 그리고 그 지점에 작은 ✕(화면 2px `--muted`).
- 당김이 데드존(아래) 안이면 궤적 없음 + 둔덕만 살짝 강조(테두리 α 1).

### Tip 화면 — 팥붕·슈붕 반반 데모 (v3)
사용자 결정: "화면 반반 나눠서 팥붕, 슈붕이 각각 날아가고 작동하는 모습을 보여줘. 건너뛰기 가능하게." → **설명 문장 없이** 두 개의 미니 눈밭이 같은 당기기 동작으로 동시에 반복 재생되고, 결과 차이(팥붕 = 가까이 · 남아서 막음 · 영구 칠 / 슈붕 = 멀리 · 통통 · 임시 칠이 바램)를 보고 알게 한다. 시작 화면에는 설명을 추가하지 않는다("Tip은 경기 시작 때 나와요" 같은 안내도 넣지 않는다).

**미니 눈밭 (두 반쪽 같은 틀)**

- 그리기는 실제 필드와 **같은 함수·같은 팔레트**: 기지 띠 `--base`, 빈 칸 `--snow`, 칸 경계 1px `--snow-line`, 테두리 2px `--field-edge`, 진영 무늬 타일(줄무늬/물방울 — `m` 크기로 만든 타일), 임시 칸(옅음 + 점선 안쪽 테두리), 붕어빵 `drawFish`(팥붕 0.96m / 슈붕 0.76m, 할로·외곽선 그대로), 그림자, 발사대(둔덕 0.55m·기둥·고무줄 `--band`), 궤적 점선, 착지 점선 원, 눈가루 고리, 부스러기, 팥붕 남은 시간 고리. 선 굵기(px)는 실제와 같게 고정. `m < 22`가 되는 일은 없지만 그 경우 무늬 축소 규칙도 같게.
- 처음 상태(두 반쪽 공통): 격자 0–6열 빈 눈, **7열(맨 오른쪽)만 상대 영구 칸**(분홍 물방울) — "저쪽은 상대 땅" 힌트. 내 발사대 = 왼쪽 띠 가운데 `(−0.75, 1.5)`, 진영 A(파랑, `--team-a-ink` 둔덕 테). 장전된 붕어빵 = 그 반쪽의 종류. 오른쪽 띠에는 발사대 없음(좁은 띠만).
- 1인·2인 모드 모두 **같은 화면 1개**, 정방향, 화면 가운데. 데모는 항상 왼쪽(파랑) 발사대 기준.

**건너뛰기**
- `<button class="secondary" id="tipSkip">건너뛰기</button>` + 오른쪽 꺾쇠 SVG(›, 선 2px). 높이 44, 최소 너비 96, 오른쪽 위. 포커스: Tip 화면이 열리면 이 버튼에 `focus()`.
- 누르면(pointerdown이 아니라 click — 실수 방지) Tip 화면 페이드아웃 160ms → **바로 `3` 카운트다운**.
- 키보드: `Enter` · `Space` · `Esc` = 건너뛰기 (Tip 화면에서는 Space/Esc가 일시정지가 아님). `e.repeat` 무시 — 시작 화면에서 Enter를 꾹 누른 채라도 Tip이 바로 넘어가지 않게 **Tip 열린 뒤 300ms 동안 키 입력 무시**.
- 화면 아무 데나 탭해서 넘기기는 **하지 않는다**(아이가 화면을 만지다 넘어가 버리지 않게). 데모 영역은 `pointer-events: none`.

**reduced-motion (`prefers-reduced-motion: reduce`) — 정지 컷**
- 각 반쪽이 움직이지 않는 **한 장의 요약 그림**을 보여 준다. 진행 막대·자동 진행 시간(3200 / 처음 6600)·건너뛰기는 그대로.
  - 팥붕 컷: 손가락 원을 당긴 위치(−0.85m)에, 고무줄 늘어난 발사대 + 궤적 점선(α .42) + 착지 지점에 **남은 팥붕**(고리 80%) + 1–3열 파랑 영구 9칸 + 장애물 가장자리에 멈춘 상대 슈붕(α .6) + 그 앞 작은 ✕(화면 2px `--muted`, 실제 궤적의 막힘 표시와 같음) + `(3,1)` 분홍 임시 칸.
  - 슈붕 컷: 손가락·당긴 발사대 + 첫 비행·튕김 2번 점선(α .42/.3/.2) + 착지 칸 3개의 임시 칠이 **순서대로 더 옅게**(α .70 / .50 / .30, 점선 테두리 같이 옅게) — "바래 가는 중" + 마지막 착지 지점에 사라지는 슈붕(α .4).
- 페이드 전환은 120ms α만, scale·흔들림·번짐 없음.

**접근성·팔레트**
- 새 색 없음 — 기존 토큰만(차분함 유지, "눈이 아프다" 이력). 손가락 표시는 `--ink` 저α, 반짝임·깜빡임·화면 흔들림 없음.
- 색 외 구분: 두 반쪽은 **위치 + 이름 글자 + 붕어빵 크기·속 자국**으로 구분. 영구/임시 칸은 **점선 테두리 유무**, 진영은 **줄무늬/물방울** — 실제 경기와 같은 표기라 그대로 배운 것이 경기에 통한다.
- "Tip!" 배지 `#1f2430` on `--gold` 대비 9:1 이상. 건너뛰기 버튼은 공통 `.secondary`(44px) + 포커스 링.
- `aria-live="polite"`로 Tip 화면이 열릴 때 1회: "팥붕과 슈붕 차이 보기. 건너뛰려면 건너뛰기 버튼".

## 조작 UI (터치 버튼 크기 ≥ 44px, 제스처, 키 매핑)

### 당겨 쏘기 (터치·마우스 공통, Pointer Events)
- 캔버스 `touch-action: none`. `pointerdown`에서 시작 구역 판정 → 그 발사대에 `pointerId` 묶고 `canvas.setPointerCapture(id)`.
- **시작 구역** (관대하게): 자기 발사대 둔덕 원(반지름 `max(1.1c, 30px)` → 지름 ≥ 60px) **또는 자기 기지 띠 전체(세로 전체)**. 격자 위를 누르면 시작 안 함(오조작 방지).
- **상대 당김(relative)**: 당김 벡터 = 현재 손가락 − 누른 지점. 발사대 정확히 위를 누르지 않아도 된다. 화면 표시는 주머니 = 발사대 중심 + 당김 벡터(최대 길이로 clamp).
- 조준 = 당김의 반대 방향. 힘 = |당김| / 최대 당김 `Lmax = clamp(60px, 2.5c, 140px)` → design.md 사거리 공식에 넣는다.
- **데드존**: |당김| < `max(16px, 0.5c)`이면 궤적 없음, 이 상태에서 놓으면 **취소**(아무 일 없음).
- 각도 제한(design.md, 예: 정면 ±75°)을 넘으면 경계 각도로 clamp해 그린다.
- `pointerup` = 발사, `pointercancel`·`lostpointercapture` = 취소.
- 손가락이 캔버스·패널 밖으로 나가도 캡처로 계속 추적(기지가 화면 가장자리라 뒤로 당기면 화면 밖에 가까워짐 — 최대 당김 길이로 clamp되므로 문제없음).

### 동시 멀티터치 (2인)
- 발사대마다 활성 포인터 **최대 1개**. 왼쪽 플레이어 손가락은 왼쪽 시작 구역에서만, 오른쪽은 오른쪽에서만 시작 → 두 사람이 동시에 당겨도 서로 간섭 없음.
- 종류 버튼은 `pointerdown`에서 즉시 선택(click 아님). 한 손으로 당기는 중 다른 손으로 종류를 바꾸면 장전된 붕어빵·궤적이 바로 바뀜.
- 1인 모드: 오른쪽(컴퓨터) 시작 구역·버튼은 반응 안 함.
- PC 마우스 1개로 2인 모드는 가능은 하지만(번갈아) 권장하지 않는다 — 시작 화면에서 `(pointer: fine)`이면 "친구와" 아래 12px 안내 "한 화면 터치 기기에 알맞아요".

### 붕어빵 종류 버튼
- 크기 ≥ 64×64(가로 iPad·PC), 최소 64×64 폰 가로, 폰 세로 ≥ 70×70(그래도 44 기준 충족). 버튼 사이 간격 8px.
- `aria-pressed`, `aria-label="팥붕 (준비됨)"` / `"슈붕 (장전 중)"` 상태 갱신.

### 키보드 (PC, 1인 모드의 왼쪽 플레이어)
| 키 | 동작 |
|---|---|
| `1` · `Q` | 팥붕 선택 |
| `2` · `W` | 슈붕 선택 |
| `Tab`(게임 중 아님) | 오버레이 버튼 이동 |
| `↑` `↓` | 조준 각도 ±5° (누르는 동안 궤적 표시) — 선택 구현 |
| `←` `→` | 힘 −/+ 5% — 선택 구현 |
| `F` | 키보드 조준으로 발사 — 선택 구현 |

- 키 반복(`e.repeat`)은 종류 선택·일시정지에서 무시, 조준 키에서는 허용.
- PC 마우스: 발사대 위 `cursor: grab`, 당기는 중 `grabbing`.

### iPad Safari 공통
- `body { user-select: none; -webkit-user-select: none; -webkit-touch-callout: none; touch-action: manipulation; -webkit-tap-highlight-color: transparent; }`, 캔버스 `touch-action: none`.
- 더블탭 확대 방지: 위 `touch-action` + `dblclick`·`gesturestart` `preventDefault`. viewport에 `maximum-scale` 넣지 않음.
- `contextmenu` 막기(길게 누르기 메뉴). 가로 스크롤 금지(`overflow:hidden` + 크기 식). 안전 영역 패딩.
- `blur`·`visibilitychange`(숨김) 때 자동 일시정지, 진행 중 당김은 취소.

## 접근성 (대비, 색 외 구분 수단)
- **진영 구분 3중**: 색(파랑 vs 분홍) + 무늬(사선 줄무늬 vs 물방울) + 명도(파랑이 항상 어두움, 칸끼리 1.7~1.9:1). 상단 바·패널·결과·팥붕 타이머 고리 아래 점까지 같은 견본 사용. 위치(왼쪽/오른쪽)도 고정.
- **영구 vs 임시 칸 (v2)**: 색 옅기 + **점선 안쪽 테두리 유무**(모양 차) — 색각과 무관하게 구분. 진영 무늬(줄무늬/물방울)는 임시 칸에도 그대로 남아 진영 구분 유지. 경고는 1Hz 이하 테두리 맥동만(넓은 영역 깜빡임 없음). 범례·HUD 막대에도 같은 점선 표기.
- **붕어빵 구분**: 크기(0.96c vs 0.76c) + 명도(어두운 갈색 vs 밝은 황금, 2.8:1) + 속 자국(검붉은 팥 vs 흰 크림). 이름 글자는 버튼·범례에 항상 함께.
- **칠한 칸 위 붕어빵**: `--halo` 테 + 외곽선으로 분리(외곽선 대비: 팥붕 외곽선 대 파랑 3.3:1, 슈붕 외곽선 대 분홍 2.4:1, 다크 2.1~3.0:1 + 할로).
- 글자 대비: `--team-a-ink` / `--team-b-ink` 대 `--panel` 라이트 5.8 / 5.2:1, 다크 8.5 / 8.4:1. `--ink` 대 진영 칸 5.1:1 이상(카운트다운).
- **외곽선을 굵게·진하게 바꾸지 말 것, 무늬 대비를 올리지 말 것**(사용자 "눈이 아프다" 이력). 화면 전체·넓은 영역 깜빡임 없음.
- 포커스 링 `outline: 3px solid var(--accent); outline-offset: 2px` (버튼·링크). 캔버스는 Tab 순서에서 제외(키보드는 위 키 매핑 사용).
- 오버레이 열릴 때 주 버튼 `focus()`. `aria-live="polite"`: 결과("왼쪽 58%, 오른쪽 37%, 왼쪽 승리"), 남은 10초 1회. 칠할 때마다 읽지 않음.
- 캔버스 `role="img" aria-label="붕어빵 눈싸움 눈밭"`, 점유율 막대 `role="meter"` + `aria-valuenow`(각 진영 %), 시간 알약 `aria-label="남은 시간 1분 23초"`(10초 단위로만 갱신).

## 시안 (스크래치, 저장소 밖)
- 붕어빵 2종(빈 눈 / 파랑 / 분홍 칸 위), 칸 무늬, 팥붕 장애물 고리, 궤적 점선, 발사대를 라이트/다크로 Chromium 렌더해 확인: 같은 실루엣에서 크기·명도·속 자국으로 두 종류가 바로 구분되고, 줄무늬·물방울 무늬가 진영 구분을 보조하면서 거슬리지 않음. 목록 아이콘도 라이트/다크 타일·작은 크기로 확인. 실제 iPad Safari 표시·멀티터치는 미검증.
- v4 세로 필드: 현재 게임 코드를 스크래치에 복사해 위 지침(변환 1회 + 예외 목록 + 입력 역변환 + 배치 식)대로 고친 시제품으로 6개 화면(라이트, iPad 가로 다크 1장) 경기·Tip·시작 화면을 Chromium으로 확인 — 줄무늬 ↗ 방향이 HUD 견본과 같고, 고리·글자·카운트다운 숫자가 똑바로, 아래로 당기면 위로 궤적, 폰 가로는 가로 예외. 실제 iPad Safari·터치 당김 감도는 미검증.
