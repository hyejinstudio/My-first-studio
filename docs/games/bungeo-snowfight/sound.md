# 붕어빵 눈싸움 (bungeo-snowfight) — 사운드 명세

모든 소리는 Web Audio API로 실시간 합성한다. 음원 파일은 쓰지 않는다. 코드는 `docs/games/bungeo-snowfight/sound-module.js`에 있고, Developer가 게임 HTML 안의 독립된 `<script>` 블록에 그대로 붙여 넣는다.
API는 mole-pop 모듈과 같다: `Sound = { unlock(), play(name, opts), setMuted(bool), isMuted(), startMusic(), stopMusic() }`.

**톤**: 눈밭 + 따끈한 붕어빵. 겨울 느낌을 내려고 종소리(sine + 비조화 배음)와 썰매방울(고역 bandpass 노이즈)을 쓴다. 효과음과 BGM은 모두 **D 메이저 펜타토닉**(D E F# A B)에 맞췄다.
- 팥붕: 낮고 묵직하지만 부드럽게 (lowpass, 저역 sine)
- 슈붕: 가볍고 통통 튀게 (높은 sine 스윕, 짧게)
- 자주 나는 소리(당기기, 칠하기, 재장전, 장애물 사라짐)는 작고 짧게 만든다.

## 0. 공통 규칙

- **좌우 패닝** `opts.side`: `'L'` = 왼쪽 플레이어, `'R'` = 오른쪽 플레이어. 없거나 다른 값이면 가운데에서 난다. 패닝 폭은 ±0.55다. 완전히 분리하면 이어폰에서 어색해서 절반쯤만 벌렸다. iPad 내장 스피커는 가로 방향일 때만 스테레오가 분명하게 들린다. `StereoPannerNode`를 지원하지 않는 브라우저에서는 가운데에서 재생한다.
  - 컴퓨터 상대 모드: 사람 = `'L'`, 컴퓨터 = `'R'`. 화면 배치에 맞춰 반대로 써도 된다.
  - 공통 소리(start, tick, whistle, 결과 징글)는 side 없이 가운데에서 낸다.
- **스로틀**: 같은 소리가 최소 간격 안에 다시 호출되면 무시한다. 간격은 **이름 + side 단위**로 따진다. 그래서 두 플레이어가 동시에 던져도 둘 다 들린다. win/lose/draw는 묶어서 0.8초에 한 번만 난다.
- 엔벨로프는 0.0001에서 지수 어택으로 올라가고 0.0001까지 지수 감쇠한다. 클릭 노이즈를 막기 위해서다. 피크 값은 효과음 버스 기준이고, 여기에 마스터 0.5가 곱해진다.
- 실패 처리: AudioContext가 없거나, 생성이 실패했거나, 잠겨 있거나(running이 아님), 음소거 중이거나, 모르는 이름이 들어오면 아무 소리 없이 넘어간다. 예외는 밖으로 나가지 않는다.

## 1. 효과음 목록

| 이름 (`Sound.play`) | 언제 | opts | 합성 레시피 | 스로틀 | 길이 |
|---|---|---|---|---|---|
| `start` | 카운트다운이 끝나고 경기를 시작할 때 | – | 썰매방울(bandpass 7kHz 노이즈 0.04) + triangle D5→F#5→A5 100ms 간격(0.18) + 종 sine D6 450ms(0.16) + 배음 D6×2.76(0.025) + sine D4(0.10) | – | ~0.75s |
| `pull` | 새총을 당기는 동안 (pointermove마다 불러도 됨) | `power` 0~1, `side` | triangle f→f×1.04, 50ms, 피크 **0.025** + bandpass(f×4, Q6) 노이즈 40ms(0.012). f = 260 + power×340Hz. 아주 작은 '끼익'이 당길수록 올라간다 | side별 80ms, 그리고 **power가 직전 소리보다 0.06 이상 커졌을 때만** 난다 | 0.05s |
| `throw` | 손을 놓아 발사할 때 | `type` `'pat'`/`'shu'`, `side` | **pat**: bandpass 노이즈 700→300Hz, 어택 50ms, 240ms(0.13) + sine 180→110Hz(0.06). 낮고 묵직한 '휘익'. **shu**: bandpass 노이즈 1400→3200Hz, 어택 30ms, 140ms(0.10) + sine 500→900Hz(0.04). 가벼운 '휙' | side별 60ms | 0.14~0.24s |
| `land` | 팥붕이 떨어져 자리에 박힐 때 | `side` | sine 130→50Hz 180ms 스윕, 길이 300ms(0.28) + lowpass 노이즈 700→120Hz 180ms(0.10, 눈 '푹') + triangle 98Hz(0.05). 고역 없이 둥근 '쿵' | side별 70ms | 0.3s |
| `bounce` | 슈붕이 바닥에 튈 때마다 | `bounce` 1,2,3…, `side` | sine f×0.7→f 20ms 스윕, 120ms(0.18) + triangle f×2 50ms(0.03) + lowpass 노이즈 30ms(0.03). f는 아래 사다리를 따른다 | side별 50ms | 0.12s |
| `vanish` | 슈붕이 사라질 때 | `side` | sine 420→1100Hz 50ms 스윕, 100ms(0.12) + 40ms 뒤 sine A6 100ms(0.02). 작은 '퐁' | side별 60ms | ~0.14s |
| `paint` | 칸이 내 색으로 바뀔 때. **여러 칸이 한꺼번에 바뀌어도 한 번만** 부른다 | `count` 바뀐 칸 수, `side` | highpass 노이즈(3k~5kHz) 120ms(0.04~0.08, 눈 '사락') + sine F#5×(1~1.5) 80ms(0.025). count가 클수록 아주 조금 크고 밝아진다(8칸에서 최대) | side별 **90ms** (폭주 방지) | 0.12s |
| `block` | 던진 붕어빵이 팥붕 장애물에 막힐 때 | `side` | sine 320→170Hz 50ms, 80ms(0.16) + lowpass 1.2kHz 노이즈 50ms(0.06). 짧은 '툭' | side별 80ms | 0.08s |
| `patGone` | 팥붕 장애물이 시간이 지나 사라질 때 | `side`(그 팥붕을 던진 쪽) | bandpass 노이즈 2500→900Hz, 어택 50ms, 250ms(**0.025**) + sine 520→300Hz(0.025). 눈 녹듯 '스르' | side별 120ms | 0.25s |
| `reload` | 다음 붕어빵 장전이 끝났을 때 | `side` | sine E6 50ms, 피크 **0.03**. 아주 작은 '틱' | side별 100ms | 0.05s |
| `tick` | 남은 시간 10…1초, 1초마다. `urgent: true` = 마지막 3초 | `urgent` | sine 1200→960Hz 40ms(0.09) + bandpass 1.8kHz 노이즈 30ms(0.03). urgent: 1600Hz, 0.13, 노이즈 0.045 | 300ms | 0.04s |
| `whistle` | 시간 0, 경기 종료 | – | sine 1900→2100Hz, 28Hz 비브라토 ±45Hz, 0.45초 유지 후 1800Hz로 내려가며 끝남(0.10) + bandpass 2kHz 바람 노이즈(0.03). 귀를 찌르지 않는 '삐이익' | 500ms | 0.7s |
| `win` | 결과: 승리 | – | triangle D5-F#5-A5-B5 110ms 간격(0.18) → triangle D6+A5 화음 600ms(0.20/0.10) + sine D4(0.12) + 썰매방울 | 결과 공통 0.8s | ~1.1s |
| `lose` | 결과: 패배 (컴퓨터 상대 모드에서 사람이 졌을 때) | – | triangle A5-F#5-E5 160ms 간격(0.15) → sine D5→A4 '뿌우' 500ms(0.15) + sine D3(0.10). 슬프지 않고 귀엽게 | 결과 공통 0.8s | ~1.0s |
| `draw` | 결과: 무승부 | – | triangle A5-E5-A5-E5 주고받기 140ms 간격(0.15) → sine A5+E5 화음 450ms(0.12/0.10) | 결과 공통 0.8s | ~1.0s |

### `bounce` 사다리 (바운스마다 한 칸씩 올라감)

| bounce | 1 | 2 | 3 | 4 | 5 | 6 이상 |
|---|---|---|---|---|---|---|
| 음 | A4 | B4 | D5 | E5 | F#5 | A5 (고정) |

`bounce` 값이 없거나 1보다 작거나 숫자가 아니면 1단(A4)으로 낸다.

### 판단 메모
- **`pull`(당기기)**: 모듈에 넣었다. **기본은 호출하는 것을 권장**한다. 당기는 힘을 귀로도 느낄 수 있기 때문이다. 아주 작고(피크 0.025), 손가락을 가만히 두면 소리가 나지 않으며, 끝까지 당겨도 소리는 많아야 16번 정도다. 2인 모드에서 거슬리면 Developer가 호출만 빼면 된다. `throw`가 불리면 당기기 기준값이 초기화된다. 당기다가 취소했다면 다음에 당길 때 power가 낮아진 지점부터 다시 올라간다.
- **`paint`**: 게임 로직에서 한 번의 착지·바운스로 바뀐 칸들을 모아 **`count`와 함께 1회만** 부른다. 실수로 칸마다 불러도 90ms 스로틀이 막아 주지만, 그렇게 되면 count 정보를 쓸 수 없다.
- **`land`와 `paint`가 같은 순간에 날 때**: 둘 다 불러도 된다. 쿵(저역)과 사락(고역)은 대역이 겹치지 않는다.
- **`win`/`lose`/`draw`, 2인 모드**: 두 사람에게 모두 결과를 알리는 자리라 `lose`는 쓰지 않는다. 한쪽이 이기면 `win`(가운데), 비기면 `draw`를 쓴다. 컴퓨터 상대 모드는 사람 기준으로 win/lose/draw를 쓴다.
- **`tick`**: 마지막 10초 동안 1초에 1번 부른다. 3, 2, 1초는 `urgent`. BGM 템포는 바꾸지 않는다.

## 2. 배경음악 (낮은 볼륨)

- 기본은 켜짐이고 볼륨은 낮다(음악 버스 0.045 × 마스터 0.5). **경기 중에만** 재생하고, 일시정지·종료 때 멈춘다. 음악만 따로 끄는 토글은 없다. 음소거 버튼 하나로 효과음과 음악을 함께 끈다.
- 오리지널 루프다. D 메이저 펜타토닉, **100 BPM**, 8분음표 32스텝(4마디, 약 9.6초)으로 반복한다.
- **멜로디**(오르골·종 느낌): sine 기음(0.40, 길이 1.6스텝) + 3.01배 비조화 배음(0.05, 짧게)
  - 1마디: A5 · F#5 · E5 F#5 A5 · / 2마디: B5 · A5 · F#5 · · · / 3마디: D5 · E5 F#5 A5 · E5 · / 4마디: F#5 · E5 · D5 · · ·
- **베이스**: triangle. 마디 첫 박에 길게(0.40), 3박째에 5도 위를 짧게(0.22). 마디 순서는 D3 → B2 → G2 → A2.
- **썰매방울 셰이커**: 뒷박(홀수 스텝)마다 bandpass 8kHz 노이즈 50ms. 2·4박 뒤(0.10)는 조금 크게, 나머지(0.05)는 작게.
- 스케줄러: `setTimeout` 100ms 주기로 250ms 앞까지 미리 예약한다.

## 3. 오디오 시스템

- **잠금 해제 (iPad Safari)**: AudioContext는 **사용자 제스처 안에서 처음 만들거나 `resume()`해야 한다**. "시작"·"모드 선택" 버튼의 `click`/`pointerup`/`touchend` 핸들러 **안에서 동기로** `Sound.unlock()`을 부른다. 여러 번 불러도 안전하다. unlock은 무음 1샘플 버퍼를 재생해 iOS의 출력 경로를 깨운다. unlock하기 전의 `play()`는 소리 없이 무시된다.
- **음소거**: `Sound.setMuted(bool)`, `Sound.isMuted()`. localStorage 키는 **`bungeo-snowfight-muted`**(`'1'`/`'0'`)이고, 읽기와 쓰기 모두 try/catch로 감쌌다. 저장이 막힌 환경(사생활 보호 모드 등)에서는 기본값인 켜짐으로 동작한다. 음소거를 바꿀 때 마스터 게인을 20ms에 걸쳐 부드럽게 바꾼다.
- **탭 전환·홈 화면 이동**: `visibilitychange`에서 숨겨지면 `ctx.suspend()`, 돌아오면 `ctx.resume()`을 부른다. 음악 예약 시각도 다시 맞춘다. 게임 타이머를 멈추는 일은 Developer 몫이다.
- **iPad 무음 스위치/무음 모드**: iOS에서는 측면 무음 스위치나 제어 센터의 무음 모드가 켜져 있으면 **Web Audio 소리가 나지 않을 수 있다**. 기기 설정이라 코드로 우회하지 않는다. 화면 안내 문구는 "소리가 안 나면 무음 모드를 확인하세요" 정도면 충분하다(Art/Developer 판단).
- 볼륨 조절 UI는 두지 않는다. 기기 볼륨을 따른다.

## 4. Developer 연결 지점

| 시점 | 호출 |
|---|---|
| 시작/모드 선택 버튼 핸들러 안 (제스처 안, 동기) | `Sound.unlock()` |
| 경기 시작 (카운트다운이 끝난 순간) | `Sound.play('start'); Sound.startMusic();` |
| 새총을 당기는 중 (pointermove, 컴퓨터는 생략 가능) | `Sound.play('pull', { power, side })` |
| 발사 | `Sound.play('throw', { type: 'pat' \| 'shu', side })` |
| 팥붕이 떨어짐 | `Sound.play('land', { side })` |
| 슈붕 n번째 바운스 | `Sound.play('bounce', { bounce: n, side })` |
| 슈붕 사라짐 | `Sound.play('vanish', { side })` |
| 착지·바운스로 칸 색이 바뀜 (한 번에 모아서 1회) | `Sound.play('paint', { count, side })` |
| 장애물에 막힘 | `Sound.play('block', { side })` |
| 팥붕 장애물이 사라짐 | `Sound.play('patGone', { side })` |
| 장전 완료 (선택. 컴퓨터 쪽은 생략 권장) | `Sound.play('reload', { side })` |
| 남은 시간 10…1초 | `Sound.play('tick', { urgent: sec <= 3 })` |
| 시간 0 | `Sound.stopMusic(); Sound.play('whistle');` |
| 결과 화면 (휘슬과 겹치지 않게 약 0.8초 뒤) | `Sound.play('win' \| 'lose' \| 'draw')` |
| 일시정지 / 재개 | `Sound.stopMusic()` / `Sound.startMusic()` |
| 음소거 버튼 | `Sound.setMuted(!Sound.isMuted())`. 버튼 아이콘은 `Sound.isMuted()`로 처음 상태를 맞춘다 |

`side`: 2인 모드에서는 왼쪽 플레이어가 `'L'`, 오른쪽 플레이어가 `'R'`이다. 컴퓨터 상대 모드에서는 사람과 컴퓨터를 화면 위치에 맞춰 `'L'`/`'R'`로 준다.

## 5. 청취 확인 필요 (헤드리스 테스트로는 들을 수 없음)

- 팥붕/슈붕 `throw`·`land`·`bounce`가 무게 차이로 구분되어 들리는지
- `pull` '끼익'이 거슬리지 않는지 (2인 모드에서 동시에 당길 때 특히)
- 2인 모드에서 좌우 패닝이 실제로 느껴지는지 (iPad 가로 내장 스피커, 이어폰)
- `paint`가 많이 겹치는 순간 지저분하지 않은지
- `whistle`이 날카롭지 않은지
- BGM 볼륨이 효과음보다 충분히 낮은지, 루프 이음새가 자연스러운지
- iPad Safari에서 첫 터치 후 소리가 나는지, 탭 전환 후 돌아왔을 때 복귀하는지, 무음 스위치가 켜졌을 때의 동작
