# 개구리 텐 아트·UI 명세

> slug: `bunny-ten` · 기획서 `docs/games/bunny-ten/design.md`와 같은 수치 사용 (판 17열×10행, 숫자 1~9, 제한 시간 120초, 점수 = 지운 칸 수).
> 선택 판정 규칙(어느 칸이 사각형에 포함되는지, 시작 칸~현재 칸)은 design.md를 따른다. 이 문서는 **판정된 칸 범위를 어떻게 보여 줄지**를 정한다. 비주얼은 칸 경계에 스냅된 사각형 그대로.
> 모든 그래픽은 Canvas 2D 도형과 CSS로 그린다. 이미지 파일·이모지 그래픽 없음. 원작(Fruit Box)의 사과 모양·빨강 판·레이아웃을 따르지 않는다.
> **v4**: 캐릭터가 하늘다람쥐 → **개구리**로, 게임 이름이 "하늘다람쥐 텐" → **"개구리 텐"**으로 바뀌었다(사용자 결정 2026-11-13). slug `bunny-ten`·localStorage 키·`window.__bunny` 훅은 그대로. 토큰 이름(`--meadow`, `--fur` 등)은 코드 변경을 줄이려고 **이름은 그대로 두고 값·의미만 바꾼다**(아래 "토큰 이름 정리 제안" 참고).

## 스타일 콘셉트
- "고요한 연못의 개구리들": 옅은 청록 회색 연못 판 위에 연두빛 세이지 개구리 170마리가 줄지어 앉아 몸 가운데에 숫자를 하나씩 들고 있다. 합이 10이 되게 감싸면 개구리들이 차례로 **폴짝 뛰어올랐다가 제자리 물속으로 퐁당** 들어가고, 작은 물결 하나가 남는다.
- **눈 피로 최소화가 최우선 (v3 원칙 유지)**: 같은 그림이 170번 반복되므로 —
  - 판·몸은 **밝기 차이가 거의 없는 차분한 색**(청록 회색 판 vs 연두 몸 — 밝기가 아니라 색상(hue)과 얇은 외곽선으로만 구분). 화면에서 가장 진한 것은 **숫자 하나뿐**.
  - 외곽선은 얇고 연한 회녹색. 체크무늬·줄무늬·칸 구분선·그림자·하이라이트·배 무늬·점박이 무늬 없음.
- **개구리 모양 (v4, 오리지널)**: 칸은 정사각형. 정면에서 본 **앉은 개구리 실루엣 하나** = 가로로 넓은 타원 몸 + 몸 위 양쪽 모서리에 반쯤 솟은 **둥근 눈 혹 2개** + 몸 아래 양옆으로 살짝 벌어진 **납작한 앞발 2개**. 이 다섯 도형을 **합쳐진 하나의 실루엣**(도형 사이 안쪽 선 없음)으로 그린다. 몸 가운데에 큰 숫자.
  - **얼굴 없음**: 눈동자·눈 흰자·입·볼·콧구멍·혀 없음. 눈 혹은 몸과 **같은 색**의 둥근 돌기일 뿐(안쪽 무늬·하이라이트 없음).
  - 특정 캐릭터 연상 금지: 유명 만화·게임·인형의 개구리(큰 흰 눈+검은 눈동자, 큰 입, 왕관·모자·옷, 진한 초록+노란 배 조합, 굵은 검정 선)를 쓰지 않는다. 이 게임 고유 요소 = **얼굴 없는 세이지 실루엣 + 몸 가운데 숫자 + 얇은 회녹 외곽선 + 퐁당 퇴장**.
- 스튜디오 공통: 따뜻한 종이색 페이지 배경(`--bg`), 흰 패널 카드, 주황 강조색(`--accent`), 둥근 모서리, 그림자 대신 면 색 차이. (판만 청록 회색 — 종이색 페이지 위의 차분한 "연못 창" 느낌.)
- **가독성**: 개구리는 모두 같은 색, 숫자는 모두 같은 진한 녹흑색. 숫자별 색 구분 없음(색은 선택 상태 3가지 전달에만 사용).
- 폰트: 사이트 공통 `system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif` (HUD·배지·오버레이·점수 팝업). **판 위 숫자만 BunnyDigits(Pretendard ExtraBold 800 서브셋)** — 변경 없음.

### 숫자 글꼴 (Pretendard, SIL OFL 1.1) — 변경 없음
- 굵기 **800 한 가지**. 파일 `games/bunny-ten/fonts/bunny-digits-800.woff2`(U+0030–0039 서브셋) + 같은 폴더 `OFL.txt`. CSS 별칭 `"BunnyDigits"`.
  ```css
  @font-face { font-family: "BunnyDigits"; src: url("fonts/bunny-digits-800.woff2") format("woff2");
    font-weight: 800; font-style: normal; font-display: swap; unicode-range: U+0030-0039; }
  ```
- `NUM_FONT = '"BunnyDigits", "Pretendard", ui-rounded, "SF Pro Rounded", system-ui, -apple-system, "Apple SD Gothic Neo", sans-serif'`.
- 시작 시 `document.fonts.load('800 32px "BunnyDigits"')` → 성공하면 스프라이트·예시 그림 재생성. 1.5초 초과·실패면 대체 글꼴로 진행(현재 코드 방식 유지).
- **6·9 밑줄 없음** (v3.1 결정 유지).

- **삭제**: `--tail`, `--ear-in` (개구리에는 꼬리·귀 안쪽 없음). `PAL_KEYS`에서 `tail`, `ear-in` 제거. CSS 3곳(라이트·다크 미디어·다크 강제)에서 모두 제거·교체.
- **=10 색을 초록 → 파랑으로 바꾼 이유**: 선택된 개구리는 몸에 상태색을 22% 섞는데, 초록을 섞으면 연두 몸이 거의 그대로라 "선택됨/합 10"이 몸 색으로 드러나지 않는다. 또 초록 사각형이 초록 개구리 무리 속에 묻힌다. 파랑은 ① 연두 몸에 섞이면 청록(#accdbd)으로 확실히 바뀌고 ② 보라(합<10)·빨강(합>10)과 색상이 멀며 ③ 적록색약에서도 빨강과 분리된다(파랑-노랑 축은 보존). "성공 = 초록" 관습 대신 합계 배지 `10 ✓`, 굵은 실선, 들썩 움직임으로 의미를 전달한다. → **design.md의 "=10 초록 계열 강조" 문구도 "파랑 계열"로 맞춰야 함(CEO/Game Designer).**
- 섞은 몸색(참고, `mix(--fur, S, .22)`): 라이트 합<10 #bdc6be(회보라) / =10 #accdbd(청록) / >10 #d2c19f(황갈), 다크 #a3b1ad / #93b6aa / #b7a98d.
- `-edge` 토큰: 섞은 몸 위에서 외곽선이 3:1 이상 보이도록 상태색보다 한 톤 진하게(라이트도 v4에서 분리). 선택 사각형·합계 배지·팝업은 `--sel-*`를 그대로 쓴다.
- Canvas는 CSS 변수를 못 읽으므로 시작 시와 테마 변경 때 `getComputedStyle`로 팔레트 캐시 → 스프라이트 재생성 (기존 방식).
- `<meta name="theme-color" content="#e4572e">` 유지.

### 토큰 이름 정리 제안 (선택 — 이번 v4에서는 하지 않아도 됨)
`--meadow`→`--pond`, `--meadow-edge`→`--pond-edge`, `--burrow`→`--pad`, `--fur`→`--skin`, `--fur-edge`→`--skin-edge`, `--dust`→`--ripple`. 코드 전체 치환이 필요하므로 **v4는 이름 유지·값만 교체**를 기본으로 하고, 다음 큰 정리 때 한 번에 바꾼다. 코드 주석에는 "fur = 개구리 몸" 식으로 의미를 적어 둔다.

## 레이아웃 (PC / iPad 세로 / iPad 가로)
**v3와 완전히 동일** (판 항상 가로 17×10, 칸 크기 계산식, 세로 가운데 배치, `ov-full` 오버레이, 검증 기준). 아래는 이름·캐릭터 지칭만 바꾼 v3 본문.

### 공통 구조 (위→아래, 한 화면 안, 스크롤 없음)
```
[← 게임 목록] 개구리 텐        [점수][최고][시간]  [🔈][Ⅱ]   ← 상단 바 52px (아이콘은 SVG)
[■■■■■■■■■■■■■■■■■■■■■■■■■■■□□□□□□□□]               ← 시간 막대 10px
┌──────────────── 연못 판 (항상 17×10) ────────────────┐
│  개구리 ...                                            │
└───────────────────────────────────────────────────────┘
```
- 상단 바·시간 막대·보드 묶음(`.app`)은 가로 가운데, 세로로도 남는 공간의 **가운데**(`body { justify-content: center }`). 세로 화면에서는 위아래에 같은 크기의 여백이 생겨 판이 화면 한가운데에 온다.
- 상단 바 너비 `min(100%, max(보드 너비, 560px))`, 너비 < 560px이면 제목 숨김·"← 목록" (기존 그대로).

### 높이 기준 레이아웃 규칙 (필수 — v3 그대로)
1. `--app-h` = `window.innerHeight + 'px'` (resize·orientationchange·visualViewport.resize 때 갱신). `100vh` 단독 금지.
2. `html, body { height: var(--app-h); overflow: hidden; }`, body 패딩 `max(12px, env(safe-area-inset-*))`, `viewport-fit=cover`.
3. 고정 높이 `F = 52 + 8 + 10 + 8 = 78px`. `W = innerWidth − 좌우 패딩`, `H = app-h − 상하 패딩 − F`. 보드 테두리 4px×2 제외: `Wi = W − 8`, `Hi = H − 8`.
4. **판 방향은 항상 가로 17열×10행.** `c = floor(min(Wi / 17, Hi / 10, 64))`, 하한 8. 보드 픽셀 = `17c × 10c` + 테두리 8. 기기를 돌리면 크기만 다시 계산(진행 중 드래그 취소, 시간은 계속).
5. 수치 (패딩 12px, 안전 영역 0 기준):

| 화면 | 칸 c | 보드(테두리 포함) | 세로 여백(위·아래 각각) |
|---|---|---|---|
| PC 1280×800 | **64** | 1096×648 | 약 25 |
| iPad 가로 1080×810 | **61** | 1045×618 | 약 45 |
| iPad 가로 1080×740 (Safari 주소창) | **61** | 1045×618 | 약 10 |
| iPad 세로 810×1080 | **45** | 773×458 | 약 260 |
| iPad 세로 Safari 실높이 ~1000 | **45** | 773×458 | 약 220 |
| 폰 세로 390×844 | **21** | 365×218 | 약 262 |
| 폰 가로 844×390 | **28** | 484×288 | 0 |

6. **칸 크기 하한**: 목표 ≥ 32px (PC·iPad 충족). 폰 세로 21px는 사용자 결정(항상 가로 판)에 따른 의도된 결과. **c < 28이면 앞발 생략**(1px 수준 디테일 → 노이즈). 숫자 글자 최소 14px 유지.
7. **작은 보드의 오버레이**: 보드 바깥 높이(`10c + 8`) **< 300px**이면 `body`에 `ov-full` → 오버레이를 화면 전체에.
   ```css
   body.ov-full .overlay { position: fixed; inset: 0; border-radius: 0; z-index: 10;
     padding: max(16px, env(safe-area-inset-top)) max(16px, env(safe-area-inset-right))
              max(16px, env(safe-area-inset-bottom)) max(16px, env(safe-area-inset-left)); }
   ```
   - 시작 오버레이 배경 `--meadow` 단색, 일시정지 97%, 시간 종료 84%. `.board`·`.board-wrap`·`.app`에 `transform`/`filter` 금지(`fixed`가 깨짐). `@media (max-height: 520px)` 축약 규칙 유지.
8. 캔버스 내부 해상도 = 표시 크기 × `devicePixelRatio`(최대 2). 크기 바뀌면 캔버스·스프라이트 재생성.
9. **검증 기준** (QA와 공유): `node tests/smoke.js bunny-ten`의 모든 뷰포트에서 `scrollHeight ≤ innerHeight`, `scrollWidth ≤ innerWidth`, 보드 `bottom ≤ innerHeight − 4`, 모든 뷰포트에서 보드 너비 > 높이. 810×1080에서 c = 45·세로 가운데(여백 차 ≤ 2px). 390×844에서 시작 오버레이가 화면 전체를 덮고 "시작하기" 버튼이 화면 안에 보임.

### 보드
- 테두리 `4px solid var(--meadow-edge)`, `border-radius: 14px`, 캔버스 `border-radius: 10px`, 바탕 `--meadow` 단색. 칸 사이 선·체크무늬·그라데이션·연잎 무늬 없음.
- `.board-wrap` 패딩 10px 영역에서도 드래그 시작 가능, 좌표는 보드 안으로 clamp (기존).

### "← 게임 목록" 링크
- 기존과 동일 (14px `--muted`, min-height 44px, 대상 `../../`).

## 개구리 그리기 (Canvas 2D, 칸 왼쪽 위 기준, c = 칸 크기)
숫자 9종 × 상태 4종(보통 / 합<10 / =10 / >10)을 **오프스크린 스프라이트로 미리 그려** `drawImage` (기존 방식, 함수 이름 `drawBunny`는 유지 가능 — 주석만 개구리로). c·테마·dpr 바뀌면 재생성.

```
 0 ┌────────────────────────┐   (c × c 정사각형)
.25│   ╭─╮          ╭─╮     │   눈 혹: 원 중심 (.27,.38) (.73,.38), 반지름 .13
   │  ╭╯ ╰──────────╯ ╰╮    │   몸: 타원 중심 (.50,.64), 반지름 .40 × .28  (y .36~.92)
   │  │                 │    │
   │  │        7        │    │   숫자: 중심 (.50,.65)
   │  ╰╮               ╭╯    │
.95│ ╰──╯─────────────╰──╯   │   앞발: 타원 중심 (.27,.905) (.73,.905), 반지름 .10 × .045
 1 └────────────────────────┘
```

### 합쳐진 실루엣 그리기 (중요 — 도형 사이 안쪽 선 없음)
겹친 도형을 각각 `fill → stroke` 하면 몸 위로 눈 혹·앞발의 원 선이 지나가 "귀 달린 동물"처럼 보인다. 그래서 **① 모든 도형을 두 배 굵기로 먼저 stroke → ② 모든 도형을 fill**로 덮는다. 바깥쪽 절반 굵기만 남아 하나의 외곽선이 된다.
```js
var lw = Math.max(1, 0.028 * c);                  // 보이는 외곽선 굵기
var vis = tint ? Math.max(1.5, lw * 1.6) : lw;    // 선택 상태는 더 굵게
g.lineWidth = vis * 2; g.lineJoin = g.lineCap = 'round';
g.strokeStyle = edge; g.fillStyle = body;
SHAPES.forEach(function (s) { path(s); g.stroke(); });   // 1) 전부 stroke
SHAPES.forEach(function (s) { path(s); g.fill(); });     // 2) 전부 fill
```
- 보이는 외곽선: c=64 → 1.8px, 45 → 1.26px, 28/21 → 1px. 선택 상태 c=64 → 2.9px, 45 → 2.0px, 21 → 1.5px.
- `body` = 보통 `--fur`, 선택 시 `mix(--fur, S, .22)`. `edge` = 보통 `--fur-edge`, 선택 시 `--sel-*-edge`.
- 눈 혹 안쪽 무늬·하이라이트·눈동자 **없음**. 배 무늬·점박이·볼터치 **없음**.

## 애니메이션·이펙트 (지속시간 ms, easing)
**변형 기준점(피벗)은 모두 몸 바닥 가운데 `(.5c, .93c)`** (v3와 같음).

- 선택 사각형은 트윈 없이 다음 프레임에 따라감. 판정·점수는 손 뗀 즉시 확정, 애니메이션은 보여주기만(`effects[]` 분리, 기존 구조). 일시정지 중엔 이펙트 시간도 정지.
- **`prefers-reduced-motion: reduce`**: 판 등장·웅크림·도약·퐁당 이동·물결 고리·흔들림·들썩·시간 경고 pulse·시간 종료 폴짝 끔. 성공 시 개구리 **제자리 alpha 1→0 150ms만**(빈 자리 표시는 즉시), 실패 시 사각형 테두리 색 120ms 유지 후 사라짐. 경고 줄무늬·색은 유지.
- 사운드 참고(Sound Designer 몫): 지우기 소리의 연속 블립 45ms 간격은 개구리 25ms 지연과 무관하게 그대로 써도 된다. 퐁당 순간(마리별 280ms)에 맞춘 물소리를 넣을지는 sound.md에서 결정.

## 접근성 (대비, 색 외 구분 수단)
- **숫자 대비 (v4 실측, WCAG 공식)**: `--num` 대 몸 — 라이트 #1b2e26/#d4e7bb **10.9:1**, 다크 #14211b/#a3bb96 **8.0:1**. 선택 상태로 섞은 몸 위 최저: 라이트 **8.1:1**, 다크 **7.2:1** → 목표 7:1 충족. 숫자가 화면에서 가장 대비가 큰 요소.
- **눈 피로 기준 (의도적으로 낮춤)**: 라이트 몸 대 판 **1.03:1**(밝기 거의 같음 — 연두 vs 청록 회색 색상 차이 + 외곽선으로만 구분), 외곽선 대 판 2.0:1, 빈 자리 대 판 1.15:1. **외곽선을 굵게·진하게 바꾸지 말 것, 몸을 진한 초록으로 바꾸지 말 것**(v2 피드백 원인). 다크는 몸 대 판 7.7:1이지만 몸 색을 #a3bb96으로 낮춰 눈부심을 줄였다(v3 10.4:1보다 낮음).
- 선택된 개구리 외곽선 대 섞은 몸: 라이트 4.0 / 3.8 / 3.7, 다크 3.2 / 3.5 / 3.3 (3:1 이상).
- 합계 배지 글자 대 배경: 라이트 흰 글자 5.9 / 5.1 / 5.0, 다크 진한 글자 6.8 / 6.9 / 6.6.
- **선택 상태는 색 외에도**: 합<10 = 점선 테두리, =10 = 굵은 실선 + `✓` + 들썩 움직임, >10 = 실선 + `✕`. 보라/파랑/빨강 — 파랑과 빨강은 적록색약에서도 분리되고, 보라·파랑은 점선 vs 실선(3 vs 4px)·기호로 구분.
- 마지막 10초: 색 + 줄무늬 + pulse.
- 포커스 링 `outline: 3px solid var(--accent)`, 오버레이 열릴 때 주 버튼 `focus()`.
- `aria-live`: 시간 종료 결과 "시간 끝. 84마리, 최고 102마리", 10초 남음 1회.
- 캔버스 `role="img" aria-label="개구리 텐 게임 판"`.
