### 실행한 테스트와 결과
환경: Playwright + Chromium. PC 1280×800, iPad gen7 세로/가로 에뮬레이션(터치), 그 밖의 뷰포트 크기. 검증 스크립트는 Developer 테스트를 재사용하지 않고 새로 작성했다(스크래치 폴더, 저장소 밖).

1. **스모크 (`node tests/smoke.js`)**: 목록에 게임 3개(bunny-ten, snake-garden, block-stack), 3개 게임 × PC/iPad 세로/iPad 가로 = 9개 모두 통과. 콘솔 오류·404·가로 스크롤 없음. 회귀 이상 없음.

2. **"잘 하면 전부 지울 수 있다" 독립 검증**: 무작위 32비트 시드 2992개와 경계 시드 8개(0, 1, 2, 3, 2^31−1, 2^31, 2^32−1, 123456789), 합계 **3000개**.
   - `__bunny.generate(seed)`의 grid와 solution을 Node로 가져와 **직접 구현한 규칙**으로 재생했다. 각 그룹마다 직사각형 안의 '남은 칸' 집합이 그룹 cells와 정확히 같은지, 칸이 2개 이상인지, 합이 10인지 확인하고, 마지막에 170칸이 모두 0인지 확인했다. 시작 칸 값은 모두 1~9였고, 총합은 10 × 그룹 수와 같았다.
   - 결과: **3000/3000 통과, 실패 0**.
   - 검증기 자체 확인: 숫자 1개 바꾸기, 그룹 순서 바꾸기, 마지막 그룹 빼기를 각각 넣어 보니 모두 실패로 잡았다.
   - 재현성: 같은 시드로 두 번 생성하면 3000/3000 동일. 다른 시드끼리 판 중복 0. 안전장치(시드 +1 재시도) 발동 0회.
   - 성능(데스크톱 Chromium): 평균 0.12ms, 99% 구간 0.30ms, 최대 4.9ms (기준 평균 10ms, 최대 50ms 이하).
   - 분포: 그룹 크기 2/3/4/5 = 59.2/27.8/10.4/2.6% (기획 60/28/10/2). 숫자 1~9 = 20.0/17.0/14.2/12.0/10.1/8.5/7.1/6.1/5.1% (기획 참고치와 일치. 9는 3% 이상, 1은 30% 이하로 경고 기준 통과). 판당 평균 그룹 66.3개.
   - **실제 입력으로 끝까지 풀기**: 화면에 표시된 판(`grid()`)이 `generate(seed()).grid`와 같은지 확인한 뒤, 정답 순서를 실제 입력으로 하나씩 드래그했다. 경우는 PC 마우스, iPad 가로 터치, iPad 세로 터치(10×17 회전 판), PC 마우스 역방향(오른쪽 아래 → 왼쪽 위, 셀 중심에서 벗어난 위치) 4가지다. 4판 모두 단계별 점수와 칸 제거가 정확했고 **170점, "판 완성!"**으로 끝났다. 중간에 "조합 없음" 조기 종료로 잘못 끝난 경우는 없었다.

3. **"매번 바뀜"**: 새로고침 후 시작 20회 → 서로 다른 시드 20개, 서로 다른 판 20개. 일시정지 → "처음부터" 20회 → 20/20 다름. 시간 종료 → "다시 하기" 4회 → 4/4 다름.

4. **기능 (PC 마우스)**
   - 합 ≠ 10 드래그(예: 합 14): 판·점수 변화 없음. 배지 "14 ✕", 빨강(`over`). 손을 떼면 배지가 사라진다.
   - 합 > 10: "59 ✕". 합 = 10: "10 ✓", 초록(`ok`). 손을 떼면 3칸이 지워지고 +3점.
   - 탭(5px 이동): 변화 없음. 우클릭 드래그: 무시. 합성 `pointercancel`: 판정 없이 취소.
   - 셀 중심 기준: 0.6칸에서 다음 칸 0.4칸까지 끌면(중심을 하나도 지나지 않음) 선택 안 됨. 중심에서 중심까지 끌면 2칸 선택.
   - 판 가장자리: 보드 왼쪽 위 바깥 7px(패딩 영역)에서 시작해도 가장자리 칸이 포함되어 지워졌다. 포인터를 보드 오른쪽 아래 바깥으로 60px 내보내도 마지막 칸까지 정상 선택됐다(clamp).
   - 빈칸 포함 선택: 정답 재생 과정에서 직사각형 안에 이미 지운 빈칸이 들어간 그룹이 다수 정상 처리됐다.
   - 일시정지(P / Esc / Ⅱ / 탭 숨김(visibilitychange)): 덮개가 보이고 캔버스 그림 0픽셀(판 완전히 가림). 실제 2.5초, 가상 시계 30초 동안 시간이 멈췄다. 일시정지 중 드래그는 무시된다. Esc / P / 계속하기로 재개된다.
   - Ⅱ나 음소거 버튼을 클릭해 포커스가 남은 상태에서 Space를 눌러도 이중 토글이나 음소거 변경이 없었다.
   - 시간 (`page.clock`): 1초 후 119, 30초 후 90. 마지막 10초에 시간 값·막대·보드 테두리 모두 `warn`(빨강 rgb(214,69,69)) + `pulse`, 화면 낭독용 "10초 남음". 종료 시 "시간 끝!", 0초. 시간 종료를 넘겨 드래그를 계속 누르고 있다가 떼도 판정되지 않았다(점수 그대로).
   - 조합 없음 조기 종료: 시드 1000에서 시뮬레이터로 무작위 진행 60수를 만들어 실제 마우스로 재생했다. 마지막 수 직후 "더 이상 10을 만들 수 없어요", 162점, 남은 시간 113초. 남은 8칸은 시뮬레이터 결과와 일치하고, 그 전에 잘못 끝나지 않았다.

### 버그 (심각도: 치명/높음/보통/낮음)
- **[높음] 음소거해도 버튼 아이콘이 바뀌지 않음** (지난 뱀 정원과 같은 유형)
  - 증상: 음소거 버튼 클릭이나 M 키를 누르면 소리 상태, `aria-pressed`, `aria-label`, localStorage(`bunny-ten-muted`='1')는 바뀐다. 그러나 화면에는 항상 "스피커 켜짐" 아이콘이 보인다. 음소거 상태로 새로고침해도 켜짐 아이콘이 보인다. 측정값: `icoOn` display:block 20×20, `icoOff` display:none 0×0 (스크린샷으로도 확인).
  - 재현: 게임 페이지 → 스피커 버튼 클릭 → 아이콘이 그대로 켜짐 모양.
  - 원인: `updateMuteIcon()`이 `$('icoOn').hidden = m; $('icoOff').hidden = !m;`로 처리한다. `<svg>`는 HTMLElement가 아니라서 `.hidden` 속성이 없고, JS 값만 붙을 뿐 `hidden` 특성(attribute)은 바뀌지 않는다. 확인 결과 `icoOn instanceof HTMLElement === false`, 클릭 뒤 `icoOn.getAttribute('hidden') === null`, `icoOff`는 처음의 `hidden` 특성이 그대로 남아 있다.
  - 기대: 음소거 시 스피커+사선 아이콘, 해제 시 스피커 아이콘. 새로고침 뒤에도 저장된 상태대로 보여야 한다.
  - 위치: `games/bunny-ten/index.html` 1057–1062행 `updateMuteIcon`. 수정 방향: `toggleAttribute('hidden', m)` 또는 `setAttribute`/`removeAttribute` 사용 (CSS `button.icon svg[hidden]{display:none}`은 이미 있음).

- [낮음 / 의견] 선택이 한 줄이고 손가락이 그 줄 한가운데에 있으면 합계 배지가 직사각형 **아래**에 뜬다. `drag.y > ry + rh/2` 조건에서 같을 때는 아래로 가기 때문이다. iPad에서는 손이 아래에서 오므로 배지가 손가락이나 손에 가려질 수 있다(iPad 세로 스크린샷에서 확인). 명세 문구대로이긴 하지만, 터치(`pointerType==='touch'`)일 때 기본을 "위"로 두는 것을 권장한다. 위치: 827–829행.
- [낮음 / 의견] 타이머가 프레임 간격 `dt`를 100ms로 잘라 누적한다(1251행). 메인 스레드가 100ms 넘게 멈추거나 프레임이 10fps 아래로 떨어지면 남은 시간이 실제보다 천천히 줄어든다. 일반 상황에서는 영향이 없다.
