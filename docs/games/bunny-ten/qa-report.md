### 실행한 테스트와 결과
환경: Playwright + Chromium. PC 1280×800, iPad gen7 세로/가로 에뮬레이션(터치), 그 밖의 뷰포트 크기, 라이트/다크 모드.

1. **스모크 (`node tests/smoke.js`)**: 게임 3개 × PC/iPad 세로/iPad 가로 = 9개 모두 통과. 콘솔 오류·404·가로 스크롤 없음. 뱀 정원과 블록 스택에서도 회귀 없음.
2. **이전 버그 재확인**
   - [높음] 음소거 아이콘: **해결**. 클릭하면 `icoOn`이 display:none, `icoOff`가 block 20×20으로 바뀐다. `aria-pressed`는 true, 라벨은 "소리 켜기". 새로고침 뒤에도 음소거 아이콘이 유지되고, M 키를 누르면 켜짐으로 돌아온다. 버튼 스크린샷 4장(켜짐 → 클릭 후 꺼짐 → 새로고침 후 꺼짐 → M 키 후 켜짐)으로 아이콘 모양이 실제로 바뀌는 것을 확인했다.
   - [낮음] 터치 배지 위치: **해결**. iPad 가로 터치로 한 줄 그룹 3개(맨 윗줄 row 0, 가운데 row 4, 맨 아랫줄 row 9)를 각각 손가락이 줄 한가운데에 있는 상태로 잡고 확인했다. 배지는 3개 모두 직사각형 위에 떴다. 맨 윗줄도 보드 위 여백에 표시됐다. 마우스는 이전처럼 포인터 반대쪽에 뜬다.
   - [낮음] 타이머 클램프: **해결**. 게임 중 메인 스레드를 3초 동안 막아 보니 남은 시간이 120에서 117로 실제 경과만큼 줄었다. 가상 시계 검사도 통과했다(1초 → 119, 30초 → 90, 일시정지 중 30초 동안 멈춤, 재개 후 정상 진행, 마지막 10초 경고, 시간 종료, 시간 종료를 넘겨 누르고 있던 드래그는 판정 안 함). 탭 숨김 시 자동 일시정지도 통과.
3. **해 보장 회귀**: 무작위 시드와 경계 시드를 합쳐 1000개를 독립 재생기로 검증했다. **1000/1000 통과, 실패 0**. 재현성 1000/1000, 판 중복 0, 재시도 0회. 생성 시간은 평균 0.16ms, 최대 4.7ms. 그룹 크기와 숫자 분포는 이전과 같다(2/3/4/5 = 59.1/27.9/10.5/2.6%).
4. **실제 입력으로 끝까지 풀기**: PC 마우스, iPad 가로 터치, iPad 세로 터치, PC 역방향 드래그 4판 모두 170점에 "판 완성!"으로 끝났다. 단계마다 점수와 판 상태가 정확했다.
5. **새 디자인 (스크린샷 직접 확인)**
   - 얼굴 요소 없음: `drawBunny`는 귀, 몸통, 배 무늬, 숫자, 6·9 밑줄만 그린다. 눈·볼 코드도 없다. 1280/1080/810/390/844 폭 화면과 시작 화면 예시, 첫 페이지 카드 아이콘에서도 얼굴이 보이지 않았다.
   - 숫자 가독성: 셀 28(844×390), 35(390×844), 57(810×1080), 61(1080×810), 64(1280×800)px를 라이트와 다크 모드에서 모두 확인했다. 크림색 몸통 위의 진갈색 숫자가 또렷하다. 6과 9의 밑줄은 28px에서도 보인다.
   - 선택 3상태: 합 < 10은 파랑 점선 테두리와 배지("9"), 합 = 10은 초록 실선과 "10 ✓", 합 > 10은 빨강과 "17 ✕"로 표시된다. 라이트와 다크 모두에서 서로 쉽게 구분된다.
   - 레이아웃 7가지 크기: 스크롤 없음, HUD가 화면을 벗어나거나 겹치지 않음. 셀 크기는 이전과 같다.
6. **글꼴**
   - `fonts/bunny-digits-800.woff2`는 200 응답(font/woff2)으로 로드된다. `document.fonts`는 BunnyDigits:800:loaded이고, `document.fonts.check('800 32px "BunnyDigits"')`는 true다. 캔버스 measureText 너비가 대체 글꼴과 달라서(250.5 vs 240.8) 실제 사용되는 것을 확인했다.
   - fontTools 확인: name 테이블의 family/full/PostScript/typographic 이름이 모두 BunnyDigits다. 압축을 푼 바이트에서도 "Pretendard" 문자열이 없다(UTF-8·UTF-16 모두). cmap은 0~9만, usWeightClass는 800. `fonts/OFL.txt`가 있고 Reserved Font Name Pretendard 저작권 줄과 OFL 1.1 본문이 들어 있다.
   - 글꼴 요청 차단: 대체 글꼴로 숫자가 정상 표시되고 5수 모두 정상 제거·득점됐다. 콘솔 오류는 차단으로 생긴 리소스 로드 실패 1건뿐이고 페이지 오류는 없었다.
   - 글꼴 지연(3초): 판 진행 중에는 판 그림이 바뀌지 않았다. 다음 판을 시작하면 새 글꼴로 바뀌었다(의도대로).
7. **기능 회귀 (PC)**: 합 ≠ 10은 변화 없음, 합 > 10 배지, 합 = 10이면 제거 +3, 탭과 우클릭 무시, pointercancel, 가장자리·바깥 clamp, 중심 기준 선택, 일시정지(P/Esc/Ⅱ/탭 숨김, 덮개가 판을 완전히 가림), 버튼 포커스 상태에서 Space, 조합 없음 조기 종료(시드 1000, 162점), 종료 잠금 0.7초, 최고 점수 저장·새로고침·새 기록 표시, 재시작 새 판(새로고침 20/20, 처음부터 20/20, 다시 하기 4/4 모두 다름). 모두 통과.
8. **터치 회귀 (iPad)**: 시작 탭, 셀 탭 무시, 드래그 제거, 두 번째 손가락 무시, 일시정지/계속 탭, 페이지 스크롤 0, 세로에서 회전 안내. 모두 통과.
9. **첫 페이지**: PC·iPad 세로/가로·폰에서 카드 3개(토끼 텐 → 뱀 정원 → 블록 스택). SVG 아이콘이 있고(토끼 텐은 얼굴 없는 새 아이콘), 클릭이나 탭으로 각 게임에 들어간 뒤 "← 게임 목록"으로 돌아온다. 404·오류 없음.

### 버그 (심각도: 치명/높음/보통/낮음)
- **[높음] 음소거해도 버튼 아이콘이 바뀌지 않음** (지난 뱀 정원과 같은 유형)
  - 증상: 음소거 버튼 클릭이나 M 키를 누르면 소리 상태, `aria-pressed`, `aria-label`, localStorage(`bunny-ten-muted`='1')는 바뀐다. 그러나 화면에는 항상 "스피커 켜짐" 아이콘이 보인다. 음소거 상태로 새로고침해도 켜짐 아이콘이 보인다. 측정값: `icoOn` display:block 20×20, `icoOff` display:none 0×0 (스크린샷으로도 확인).
  - 재현: 게임 페이지 → 스피커 버튼 클릭 → 아이콘이 그대로 켜짐 모양.
  - 원인: `updateMuteIcon()`이 `$('icoOn').hidden = m; $('icoOff').hidden = !m;`로 처리한다. `<svg>`는 HTMLElement가 아니라서 `.hidden` 속성이 없고, JS 값만 붙을 뿐 `hidden` 특성(attribute)은 바뀌지 않는다. 확인 결과 `icoOn instanceof HTMLElement === false`, 클릭 뒤 `icoOn.getAttribute('hidden') === null`, `icoOff`는 처음의 `hidden` 특성이 그대로 남아 있다.
  - 기대: 음소거 시 스피커+사선 아이콘, 해제 시 스피커 아이콘. 새로고침 뒤에도 저장된 상태대로 보여야 한다.
  - 위치: `games/bunny-ten/index.html` 1057–1062행 `updateMuteIcon`. 수정 방향: `toggleAttribute('hidden', m)` 또는 `setAttribute`/`removeAttribute` 사용 (CSS `button.icon svg[hidden]{display:none}`은 이미 있음).

- [낮음 / 의견] 선택이 한 줄이고 손가락이 그 줄 한가운데에 있으면 합계 배지가 직사각형 **아래**에 뜬다. `drag.y > ry + rh/2` 조건에서 같을 때는 아래로 가기 때문이다. iPad에서는 손이 아래에서 오므로 배지가 손가락이나 손에 가려질 수 있다(iPad 세로 스크린샷에서 확인). 명세 문구대로이긴 하지만, 터치(`pointerType==='touch'`)일 때 기본을 "위"로 두는 것을 권장한다. 위치: 827–829행.
- [낮음 / 의견] 타이머가 프레임 간격 `dt`를 100ms로 잘라 누적한다(1251행). 메인 스레드가 100ms 넘게 멈추거나 프레임이 10fps 아래로 떨어지면 남은 시간이 실제보다 천천히 줄어든다. 일반 상황에서는 영향이 없다.
