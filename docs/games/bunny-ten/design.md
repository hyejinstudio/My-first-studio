# 개구리 텐 기획서
- slug: bunny-ten
- 한 줄 소개: 숫자를 품은 개구리들을 네모로 감싸 합이 10이 되면 퐁당 뛰어들어 사라지는 숫자 퍼즐
- 상태: 기획 (비주얼 v4 — 개구리 반영)
- 참고: "합이 10이면 사라지는 숫자 상자" 장르 규칙만 빌린 오리지널. 원작의 이름·아트·화면 구성은 쓰지 않는다.
- 캐릭터: 오리지널 **개구리** (v4, 세부는 art-ui.md). 토끼 → 하늘다람쥐 → 개구리 순으로 바뀌었다.
- **이름 메모**: 게임 이름은 **"개구리 텐"** (사용자 결정, 2026-11-13). 제목·aria-label 등 화면 문구만 바꾼다. slug `bunny-ten`, localStorage 키 `bunny-ten-best`·`bunny-ten-muted`, 테스트 훅 `window.__bunny`는 **그대로 유지**한다. 이유: slug를 바꾸면 게임 주소(URL)가 바뀌어 기존 링크·북마크가 깨지고, 저장 키를 바꾸면 기존 최고 점수·음소거 설정이 사라지며, 훅 이름을 바꾸면 기존 QA 테스트가 깨진다.

## 핵심 루프
1~9 숫자를 품은 개구리가 17 × 10 격자에 가득 → 드래그로 직사각형을 그림 → 직사각형 안 숫자 합이 실시간으로 보임 → 손을 떼는 순간 합이 정확히 10이면 그 개구리들이 퐁당 뛰어들어 사라지고 사라진 수만큼 점수 → 빈칸이 늘수록 멀리 떨어진 개구리끼리도 묶을 수 있게 됨 → 120초 동안 최대한 많이 지운다.

## 규칙
### 보드·숫자 배치
- 격자 17열 × 10행 = 170칸. 시작 시 모든 칸에 개구리 1마리, 숫자는 1~9.
- **매 판 무작위이면서, 170칸 전부를 지울 수 있는 정답 순서가 반드시 하나 이상 존재하도록 만든다.** (아래 "판 생성 알고리즘")
- **주의 — 해 존재 보장 ≠ 아무 순서로 해도 다 지워짐.** 정답 순서는 여러 가능한 순서 중 하나일 뿐이다. 플레이어가 다른 조합을 먼저 지우면 정답 경로가 깨져 중간에 막힐 수 있고, 이때는 아래 "조합 없음 → 조기 종료" 규칙이 그대로 적용된다. 화면 문구에 "반드시 다 지울 수 있어요" 같은 약속은 쓰지 않는다(시작 화면 문구는 "잘 고르면 전부 지울 수 있어요" 정도까지 허용).
- 개구리가 사라진 칸은 빈칸(값 0)으로 남는다. 위 개구리가 떨어지거나 새 개구리가 채워지지 않는다.

### 판 생성 알고리즘 (정방향 시뮬레이션)
좌표: 행 r = 0~9(위→아래), 열 c = 0~16(왼→오른). 직사각형은 (r0, c0)–(r1, c1), 양 끝 포함.

**난수**: 시드 기반 `mulberry32(seed)` 하나만 사용(생성 과정 전체에서 `Math.random` 사용 금지 → 같은 시드 = 같은 판 + 같은 정답).
- 일반 플레이 시드: `(Date.now() ^ Math.floor(Math.random() * 2**32)) >>> 0` (시드 결정에만 Math.random 허용).
- 시드는 화면에 표시하지 않는다.

**1단계 — 제거 그룹 만들기**
1. 모든 칸 = '남음'. 남은 칸 수 m = 170. 그룹 목록 = [].
2. **마지막 그룹**: m이 2~5이면 남은 칸 전부를 하나의 그룹으로 하고 종료. (남은 칸들의 바운딩 박스를 R로 기록. 그 안의 다른 칸은 모두 이미 제거된 칸이므로 성립.)
3. **목표 크기 n 뽑기**: 아래 분포에서 뽑는다. 단 m − n = 1 이 되는 n은 다시 뽑는다(남은 칸 1개 상황 금지). n > m 이면 다시 뽑는다.

   | 그룹 크기 n | 확률 |
   |---|---|
   | 2 | 60% |
   | 3 | 28% |
   | 4 | 10% |
   | 5 | 2% |

4. **직사각형 시도** (최대 120회, 단계적으로 크기 상한을 넓힘):
   - 앵커 = '남음' 칸 중 무작위 1칸.
   - 폭 w, 높이 h를 각각 1~상한에서 균등 무작위(1×1은 다시 뽑음). 앵커를 포함하도록 R의 위치를 무작위로 정하고 보드 안으로 잘라낸다.

     | 시도 회차 | w 상한 | h 상한 |
     |---|---|---|
     | 1~40 | 4 | 4 |
     | 41~80 | 6 | 6 |
     | 81~120 | 17 | 10 |

   - S = R 안의 '남음' 칸. **|S| = n 이면 성공** → S를 그룹으로 확정, 그 칸들을 '제거됨'으로 표시, m −= n, R과 S를 그룹 목록에 추가하고 2로.
   - 이유: 초반엔 빈칸이 없어 작은 붙은 묶음(가로·세로 2칸 등)이 되고, 후반엔 빈칸이 많아 멀리 떨어진 개구리를 큰 네모로 묶는 그룹이 자연스럽게 생긴다(원작 장르의 후반 감각과 같음).
5. **120회 모두 실패 시 전수 탐색**: 보드의 모든 직사각형(8,415개)을 '남음' 칸 2차원 누적합으로 세어, |S| = n 인 것 중 무작위 1개를 고른다. 없으면 n을 1씩 줄여(n−1, …, 2) 같은 방식으로 찾는다(단 m − n = 1 이 되는 크기는 건너뜀). 
   - **크기 2는 항상 존재한다** (남은 칸이 2개 이상이면, 바운딩 박스가 가장 작은 두 칸의 박스 안에는 정확히 그 두 칸만 있음). 따라서 생성은 실패하지 않는다. m − 2 = 1 인 경우(m = 3)는 2번 규칙에서 이미 마지막 그룹으로 처리되므로 생기지 않는다.
6. 안전장치: 그룹 수가 200을 넘거나 시간 예산 초과 등 예상 밖 상황이면 시드 +1로 처음부터 다시(최대 5회). 정상 동작에서는 발동하지 않아야 하며, QA 검증에서 발동 0회를 확인한다.

**2단계 — 숫자 배정**
- 각 그룹(크기 n)에 합이 정확히 10인 1~9 숫자 n개를 배정: 1~9 중 서로 다른 칸막이 n−1개를 무작위로 골라 정렬 → 0과 10 사이를 나눈 조각 길이가 숫자(10의 순서 있는 분할을 균등하게 뽑음, 모든 조각 1 이상·9 이하 자동 보장).
- 뽑은 숫자들을 그룹 칸들에 무작위 순서로 배치.
- 2개짜리 그룹은 (1,9)(2,8)(3,7)(4,6)이 각 2/9, (5,5)가 1/9로 고르게 나온다 → 특정 쌍 쏠림 없음.
- 예상 숫자 분포(판 1개 평균, 참고치): 1이 약 20%, 2 약 17%, 3 약 14%, 4 약 12%, 5 약 10%, 6~8 약 6~9%, 9 약 5%. 3~5개짜리 그룹은 평균값이 작을 수밖에 없어 작은 숫자가 많아지는 것은 정상(균등 무작위보다 작은 수 쪽으로 기움).

**산출물**: `grid[10][17]`(1~9) + `solution` = 그룹 목록(순서대로). 각 그룹은 `{ r0, c0, r1, c1, cells: [[r, c], ...] }`.

**성능 목표**: iPad에서 판 1개 생성 50ms 이내(예상 연산량: 그룹 약 65~70개 × 시도 최대 120회 × 칸 16개 수준 + 드문 전수 탐색, 데스크톱 기준 수 ms).

### 테스트 훅 (QA 전용, 화면에 노출 안 함)
`window.__bunny` (이름은 기존 테스트 호환을 위해 유지 — 개구리로 바뀌어도 변경하지 않음. 읽기 전용 함수만, 게임 상태를 바꾸는 것은 `newBoard`뿐):
- `__bunny.seed()` → 현재 판의 시드(정수).
- `__bunny.solution()` → 현재 판 정답 그룹 목록의 **깊은 복사본**(수정해도 게임에 영향 없음).
- `__bunny.grid()` → 현재 보드 값 복사본(빈칸 0).
- `__bunny.generate(seed)` → `{ grid, solution }`을 순수 계산으로 반환. 현재 게임 상태는 바꾸지 않음(QA의 1000개 시드 검증용).
- `__bunny.newBoard(seed)` → 지정 시드로 새 판을 만들어 바로 플레이 시작 상태로(점수 0, 시간 120초). 재현 테스트용.

### 선택 판정
- 드래그 시작점과 현재 손가락/마우스 위치를 두 꼭짓점으로 하는 축 정렬 직사각형.
- **포함 기준 (2026-11-13 변경): 시작점이 있는 칸부터 현재 포인터가 있는 칸까지(양 끝 포함)의 직사각형.** 보이는 스냅 사각형 = 판정 범위. (이전 '셀 중심 포함' 규칙은 위 칸 아래쪽에서 시작해 아래 칸 위쪽에서 놓는 자연스러운 드래그가 실패해 폐기 — 사용자 버그 신고 "세로로 묶으면 안 묶어짐")
- 드래그 시작은 보드 영역(보드 바깥 여백 0.5칸 포함) 안에서만 인정. 드래그 중 포인터가 보드 밖으로 나가면 직사각형을 보드 경계로 잘라서 계속 유지(포인터 캡처).
- 시작점에서 8px 미만 움직이고 뗀 경우(탭)는 선택 없음, 판정 없음.
- **빈칸 포함 허용**: 빈칸은 0으로 더한다. 직사각형 안 개구리가 1마리뿐이면 합이 10이 될 수 없으므로 자연스럽게 무효.
- 동시 터치: 첫 번째 포인터만 사용, 이후 포인터는 무시.
- `pointercancel`(시스템 제스처 등) 시 선택 취소, 판정 없음.

### 실시간 표시와 피드백
- 드래그 중 직사각형 테두리 + 포함된 개구리 강조 + 직사각형 모서리 근처(손가락에 가리지 않게 손가락 위쪽)에 현재 합계 숫자 표시.
- 합에 따른 상태 (색 값은 art-ui.md 기준):

| 합 | 드래그 중 표시 | 손 뗐을 때 |
|---|---|---|
| 0~9 (미만) | 중립 계열 테두리, 합계 숫자 | 선택 사라짐 + 작은 "툭" 흔들림(0.2초), 벌점 없음 |
| 10 | 초록 계열 강조, 합계 "10" 강조 | 포함 개구리 전부 폴짝 뛰어올라 퐁당 사라짐, 점수 + 사라진 수 |
| 11 이상 (초과) | 빨강 계열 테두리 | 미만과 동일(흔들림), 벌점 없음 |

- 실패에 벌점·시간 감소 없음. 부담 없이 드래그해 합을 확인하는 것도 플레이 방식으로 허용.
- 사라짐 연출 0.35초 동안에도 다음 드래그 가능(판정은 즉시 반영, 연출만 남음).

### 점수
- 점수 = 지운 개구리 수. 한 번에 지운 마리 수만큼 더한다(2마리 조합 +2, 1+2+3+4 조합 +4). 배율·콤보 없음.
- 최대 점수 170 (판 전체 클리어).
- 최고 점수: localStorage `bunny-ten-best` (키 이름 유지 — 기존 기록 보존). 게임 종료 시 현재 점수가 더 크면 갱신. 저장소 접근 실패 시 0으로 보고 게임은 정상 진행.
- 음소거 설정: localStorage `bunny-ten-muted` (키 이름 유지 — 기존 설정 보존, 세부는 sound.md).

### 시간·종료
- 제한 시간 120초. 첫 드래그가 아니라 "시작" 버튼을 누른 순간부터 흐른다.
- 상단 시간 막대 + 남은 초 표시.
- **마지막 10초 경고**: 시간 표시와 막대가 빨강으로 바뀌고 1초마다 한 번 맥동(크기 1.0 → 1.15 → 1.0). 매초 경고음은 sound.md에 따름.
- 종료 조건 (먼저 오는 것):
  1. 시간 0초 → "시간 끝!"
  2. 판 전체 클리어(170마리) → "판 완성!" (부제 "연못이 텅 비었어요!")
  3. **더 이상 합 10 조합이 없음** → "더 이상 10을 만들 수 없어요" 로 **조기 종료**.
     - 판단: 매 성공 판정 직후 모든 직사각형(170칸 기준 약 8,400개)을 2차원 누적합으로 검사. 개구리가 2마리 이상 들어 있고 합이 10인 직사각형이 하나도 없으면 종료. 계산량 작아 즉시 처리 가능.
     - 이유: 남은 시간을 헛되이 기다리게 하지 않음. 시간이 남아 있어도 점수는 그대로(보너스 없음).
- 시간이 0이 되는 순간 드래그 중이면 그 선택은 취소(판정하지 않음).

### 일시정지
- Ⅱ 버튼 / P / Esc로 일시정지, 탭이 숨으면(visibilitychange) 자동 일시정지.
- 일시정지 중 타이머 정지, **보드는 불투명 덮개로 가림**(멈춘 채 조합을 찾는 것 방지). "일시정지" + "계속" 버튼.
- 드래그 중 일시정지되면 선택 취소.

| 동작 | PC | iPad |
|---|---|---|
| 직사각형 선택 | 마우스 왼쪽 드래그, 버튼 놓을 때 판정 | 손가락 드래그, 손 뗄 때 판정 |
| 시작 | "시작" 버튼 클릭 / Enter / Space | "시작" 버튼 탭 |
| 일시정지/재개 | Ⅱ 버튼 / P / Esc (재개: 같은 키 또는 Enter) | Ⅱ 버튼 / "계속" 버튼 |
| 재시작 (종료 후) | "다시 하기" / Enter / Space | "다시 하기" 버튼 |

- 게임 화면에서 터치 스크롤·확대·더블탭 확대·길게 눌러 텍스트 선택/돋보기를 막는다(보드에 `touch-action: none`, `user-select: none`).
- 키보드로 셀을 선택하는 기능은 없음(범위 밖).

### 판 방향과 셀 크기 (v3)
- **판은 모든 화면에서 항상 가로 17열 × 10행** (사용자 결정). 세로 화면에서도 판을 회전하지 않는다. 포인터 좌표 → 칸 변환은 항상 열 = floor(x / 셀), 행 = floor(y / 셀).

| 환경 | 보드에 쓸 수 있는 폭(대략) | 셀 한 변 |
|---|---|---|
| iPad 10.2" 가로 (1080 × 810pt) | 폭 1040 / 높이 약 620(HUD·브라우저 바 제외) | 약 61 → 높이 제한으로 **약 60pt** |
| iPad mini 가로 (1133 × 744pt) | 높이 약 560 | **약 54pt** |
| iPad 세로 (810pt 폭) | 폭 780 | **약 45pt** |
| iPad mini 세로 (744pt 폭) | 폭 714 | **약 42pt** |

- 셀 크기 = min(사용 가능 폭 / 17, 사용 가능 높이 / 10), 정사각 셀. 보드는 화면 가운데(세로 화면에서는 남는 높이의 가운데).
- 판정이 "시작 칸~현재 칸"이라 손가락이 목표 칸 안에만 들어가면 된다.
- **세로 화면 안내**: 세로 화면에서도 회전 없이 가로 판 그대로 동작한다. 가로가 셀이 30% 이상 커서 더 보기 편하므로, 세로 화면(`innerHeight > innerWidth`)일 때만 시작 화면에 "가로로 돌리면 더 크게 볼 수 있어요" 안내 한 줄을 표시한다. 플레이 중에는 안내하지 않는다.
- 숫자 글자 크기는 셀의 약 50%. 개구리 그림이 숫자를 가리지 않게(세부는 art-ui.md).

## QA 검증 기준 (판 생성)
1. **해 재생 검증**: 무작위 시드 1000개에 대해 `__bunny.generate(seed)`로 판을 만들고, 정답 그룹을 순서대로 **실제 게임 규칙**(직사각형 안 남은 칸 합 = 10, 빈칸 0)으로 재생한다. 각 단계에서
   - 그룹의 직사각형 (r0,c0)–(r1,c1) 안 '남은' 칸 집합이 **정확히 그 그룹의 cells와 같고**,
   - 그 칸들의 합이 정확히 10이며,
   - 그룹 크기가 2 이상이어야 한다.
   마지막 그룹까지 재생하면 **170칸 모두 제거**되어야 한다. 1000개 전부 통과해야 합격.
2. **재현성**: 같은 시드로 `generate`를 두 번 부르면 grid·solution이 완전히 같다. 다른 시드끼리는 판이 달라야 한다(1000개 중 중복 0).
3. **값 범위**: 모든 칸 1~9, 총합 = 10 × 그룹 수.
4. **분포 참고(경고 수준, 불합격 아님)**: 1000판 평균 그룹 크기 2 비율 50~70%, 숫자 9 비율 3% 이상, 숫자 1 비율 30% 이하. 벗어나면 보고.
5. **성능**: 판 1개 생성 시간 데스크톱 Chromium 평균 10ms 이하, 최대 50ms 이하(iPad 실기기 50ms는 미검증으로 보고). 안전장치(시드 +1 재시작) 발동 0회.
6. **훅 무해성**: `solution()` 반환값을 수정해도 게임 판·이후 `solution()` 결과가 바뀌지 않는다. 훅은 화면에 아무것도 표시하지 않는다.
