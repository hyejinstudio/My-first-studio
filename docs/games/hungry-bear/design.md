# 폭식 불곰을 찾아라 기획서
- slug: hungry-bear
- 한 줄 소개: 강가의 불곰 세 마리가 연어를 먹어 치운다. 누가 제일 많이 먹었는지 눈으로 세서 맞혀라.
- 배포: 실험실 `lab/games/hungry-bear/` (순위표 없음). 나중 출시 대비 정수 점수 정의(아래 "점수").
- 장르: 관찰·세기(주의력) 게임. 스튜디오 기존 게임(블록 쌓기, 두더지, 리듬, 뱀, 경영 등)과 겹치지 않는다. 특정 상용 게임의 이름·캐릭터·레벨을 가져오지 않은 오리지널 설정이다.

## 핵심 루프
1. **준비** — "레벨 N" + 카운트 3·2·1 (0.6초씩, 1.8초). 새 요소가 처음 나오는 레벨이면 카운트 전에 한 줄 배너(아래 "보고 배우기").
2. **먹기** (약 7~10초) — 강에서 연어가 튀어 올라 세 곰 중 한 마리에게 날아가고, 곰이 **한 번에 한 마리씩** 받아먹는다. 레벨이 오르면 간격이 짧아지고, 두 마리가 동시에 먹기도 하고, 받아먹지 못하는 "헛물기"가 섞인다.
3. **선택** — 연어가 멈추고 "누가 제일 많이 먹었을까?" → 곰을 탭/클릭 (PC는 1·2·3 키). 시간 제한 없음.
4. **판정 + 해설** — 정답/오답, 곰별로 먹은 수(정확한 숫자), 헛물기 수, 타임라인 그림, "다시보기" 버튼.
5. 정답 → 다음 레벨(더 빠르게). 오답 → 목숨 −1, 같은 레벨을 **새 순서**로 다시. 목숨 0 → 게임 오버(마지막 라운드 해설 포함).

## 곰 (위치 고정, 이름은 해설용)
| 번호(키) | 위치 | 이름(제안) |
|---|---|---|
| 1 | 왼쪽 | 단풍 |
| 2 | 가운데 | 도토리 |
| 3 | 오른쪽 | 솔방울 |
- 세 곰은 크기·자세가 같고 색 띠·소품 같은 구분 표시만 다르다(아트 담당 결정). 해설 문장은 항상 "이름(번호)"로 쓴다. 예: "도토리(2번)".

## 규칙 (승리/패배, 점수)
| 항목 | 규칙 |
|---|---|
| 정답 | 그 라운드에서 **실제로 먹은 연어**(헛물기 제외)가 가장 많은 곰. 최다 곰은 항상 정확히 1마리(동률 없음) |
| 목숨 | **2개**로 시작. 오답이면 −1 후 같은 레벨 재도전(새로 생성한 순서·배정). 0이 되면 게임 오버. 회복 없음 |
| 점수 | **맞힌 라운드 수 = 클리어한 레벨 수** (정수, 0 이상). 오답은 레벨이 오르지 않으므로 "마지막으로 클리어한 레벨"과 같다 |
| 최고 기록 | localStorage `hungry-bear-best` (정수). 게임 오버 때 점수 > 기록이면 갱신 + "새 기록" 표시 |
| 끝 | 레벨 상한 없음(무한). 16레벨 이후 규칙은 아래 표 |
- 출시 대비: 점수 = 클리어 레벨 수. 이론상 상한은 없지만 16레벨 이후 사람 한계 근처라 순위표 score_cap 제안 100.
- 화면 이탈 무효: 먹기 도중 탭 전환·앱 전환(`visibilitychange` hidden)이 일어나면 그 라운드는 **무효** → 목숨 차감 없이 같은 레벨을 새 순서로 다시 시작. 문구: "화면을 벗어나서 이번 라운드는 다시 해요."

- 선택 화면이 뜬 직후 **300ms 동안 입력 무시**(먹기 중 손가락이 그대로 닿아 있는 오탭 방지).

## 공정성 규칙 (정답 단서는 '세기'뿐)
**금지** (먹기가 끝난 뒤 화면·소리에서 답이 보이면 안 됨):
- 뼈·가시·연어 조각이 쌓이거나 남는 것, 곰 앞에 쌓이는 무엇이든.
- 배 크기·몸 크기·표정·자세 변화가 먹은 수에 따라 달라지는 것. 곰 3마리의 끝 상태는 **픽셀까지 같은 대기 자세**(구분 표시 제외).
- 화면 위 개수·막대·점수 표시(먹기 중·선택 중 모두).
- 먹을 때마다 소리가 점점 높아지거나 커지는 등 누적되는 소리. 곰마다 **고정된** 먹는 소리 높이는 허용(귀로 세는 것도 세기).
- 먹는 연출의 길이·크기·이펙트가 곰이나 순번에 따라 다른 것. 모든 진짜 먹기는 같은 연출, 모든 헛물기는 같은 연출.
- 먹기가 끝난 순간 마지막에 먹은 곰이 따로 눈에 띄는 것(마지막 먹기 연출이 끝난 뒤 0.4초 기다렸다가 선택 화면으로).

**헛물기(가짜) 구분 규칙** — 헛물기는 "보고 구분할 수 있어야" 공정하다:
- 진짜: 연어가 곰 입에 닿는 순간 사라지고 "꿀꺽" 연출 + 먹는 소리.
- 헛물기: 곰이 입을 다무는데 연어가 코끝에 튕겨 **강으로 다시 떨어지는 모습이 최소 300ms 보이고** 물보라 + 첨벙 소리. 먹는 소리 없음.
- 헛물기는 같은 곰의 진짜 먹기와 똑같이 "그 곰의 사건"으로 보고 아래 간격 규칙을 지킨다.

**사람이 셀 수 있는 속도 한계 (모든 레벨, 절대 하한)**
| 항목 | 하한 |
|---|---|
| 같은 곰의 연속 사건(진짜·헛물기) 사이 | **≥ 500ms** (곰 한 마리당 초당 2번 이하) |
| 이웃한 슬롯(사건 시각) 사이 | **≥ 300ms** (흔들림 적용 후에도) |
| 한 슬롯에 동시에 일어나는 사건 | **최대 2개, 서로 다른 곰** (3마리 동시 금지) |
| 같은 곰이 연달아 이어지는 슬롯 수 | 최대 3슬롯 |
| 먹는 연출(입 벌림~다묾) 길이 | ≤ 250ms (다음 사건과 겹치지 않게) |
| 연어 비행 시간 | clamp(0.9 × 기준 간격, 350, 800) ms, 레벨 안에서 일정 |
- "사건 시각" = 연어가 곰 입에 닿는 순간(진짜는 먹는 순간, 헛물기는 튕기는 순간). 연어는 그 시각 − 비행 시간에 강에서 튀어 오른다.
- 최대 사건 속도: 기준 간격 380ms × 동시 30% → 초당 약 3.4개. 16레벨 이후에도 이보다 빨라지지 않는다(속도 대신 개수·헛물기로 어려워짐).

### 한 판 길이 추정
라운드당: 준비 1.8초 + 시작 지연 0.5초 + 먹기 ~8.5초 + 선택 ~2초 + 해설 ~3~5초 ≈ 16~18초. 8레벨 도달 + 오답 2번 ≈ 9~10라운드 ≈ **2.5~3분**. 1레벨부터 바로 두 번 틀리면 ~40초.

## 라운드 생성 규칙 (결정론, 시드)
RNG: `mulberry32(seed)` 하나. 게임 시작 시 시드(기본 = 시간값, 테스트는 `?seed=`)를 정하고 라운드마다 순서대로 사용.

**1. 개수 정하기**
- 레벨의 N 범위 안의 모든 (최다 M, 2위 S, 3위 T)를 나열: M + S + T = N, M − S = 차이, S ≥ T ≥ 1, (3위 근접 제한 있으면) S − T ≤ 제한. 이 목록에서 하나를 균등 선택. (1~15레벨 결과는 위 표의 "가능한 개수 조합"과 같아야 한다.)
- 16레벨 이후도 같은 식(N = 중심 −1 ~ +1, 최대 31). 예: 20레벨 N 29~31 → 11/10/8, 11/10/9, 11/10/10 중 하나(근접 2 이하인 것만).

**2. 곰에게 배정**
- (M, S, T)를 왼·가운데·오른 곰에게 무작위 배정. 단 **같은 위치의 곰이 3라운드 연속 정답이 되지 않게**(오답 재도전 포함) — 그러면 다시 뽑는다.

**3. 헛물기 배정**
- 첫 번째 헛물기는 **2위 곰**에게(진짜+헛물기로 세면 틀리게 되는 함정). 나머지는 세 곰 중 무작위, 단 한 곰당 최대 2개.
- 6~9레벨: 헛물기는 혼자 있는 슬롯에만(동시 슬롯에 넣지 않음). 10레벨부터는 동시 슬롯에도 가능.

**4. 순서 만들기 (슬롯 채우기)**
- 슬롯 k의 시각: t₀ = 500ms(시작 지연 후 첫 사건, 비행 시간은 그 전에), tₖ = tₖ₋₁ + 간격 × (1 + 흔들림 × u), u ∈ [−1, 1] 균등, 결과 < 300이면 300.
- 각 슬롯에서: 남은 사건이 있고 **간격 규칙(같은 곰 ≥ 500ms, 연속 3슬롯 이하)을 지키는 곰**만 후보. 후보 중 남은 사건 수에 비례한 확률로 1마리 고르고, "동시" 확률이면 다른 후보 1마리를 더 고른다. 고른 곰의 남은 사건(진짜/헛물기) 중 하나를 무작위로 꺼낸다. 후보가 없으면 빈 슬롯(쉬는 박자).
- 완성 후 아래 검사를 통과하지 못하면 처음부터 다시(같은 RNG 계속 사용, 최대 500번). 500번 안에 못 만들면 그 레벨 규칙에서 "순서 규칙"만 뺀 채 다시 생성하고 콘솔 경고(QA에서 0회여야 함).

**5. 순서 규칙 검사**
- **반 지점** (4~6레벨): 진짜 먹기 중 ⌈N/2⌉번째까지 셌을 때 최다 곰이 **혼자 3 이상 앞서 있지 않을 것**(초반만 보고 맞히기 방지).
- **역전** (7레벨~): ⌈N/2⌉번째 진짜 먹기 시점에 최다 곰이 **단독 선두가 아닐 것**(동률 또는 뒤짐).
- **막판** (10레벨~): 마지막 25%(⌈N/4⌉개)의 진짜 먹기 안에 최다 곰과 2위 곰이 **각각 1번 이상** 있을 것(끝까지 봐야 함).
- 동시 슬롯 안의 사건 순서는 곰 번호 순으로 센다.
- 공통: 첫 슬롯은 반드시 사건 1개(빈 슬롯·동시로 시작하지 않음). 빈 슬롯은 연속 2개까지(긴 정적이 끝났다는 착각 방지). 마지막 사건 뒤 0.4초 + 마지막 연출 후 선택 화면.

## 화면 흐름
```
타이틀 → [라운드: (새 요소 배너) → 준비 3·2·1 → 먹기 → 선택] → 판정+해설 → 다음 레벨 / 재도전 / 게임 오버 → 타이틀(다시 하기)
```
| 화면 | 내용 |
|---|---|
| 타이틀 | 이름, 한 줄 "누가 제일 많이 먹었는지 세어 보세요.", 시작 버튼, 최고 기록, 음소거. 설명은 이 한 줄뿐 |
| 라운드 상단 | 레벨 N, 목숨 2칸, 현재 점수. (먹기 중 개수 표시 없음) |
| 선택 | "누가 제일 많이 먹었을까?" + 곰 3마리가 살짝 들썩(같은 연출) |
| 판정+해설 | 아래 "해설". 버튼: 다음 레벨(정답) / 다시 도전(오답, 목숨 남음) / 결과 보기(목숨 0) + 다시보기 |
| 게임 오버 | 점수(클리어 레벨 수, 큰 숫자), 최고 기록(새 기록 표시), **마지막 라운드 해설 전체**(숫자·타임라인·다시보기), 다시 하기 |

### 해설 (매 라운드, 정답·오답 모두)
1. 판정 한 줄
   - 정답: "정답! **도토리(2번)가 7마리**로 가장 많이 먹었어요."
   - 오답: "아쉬워요. 고른 **단풍(1번)은 6마리**, **도토리(2번)가 7마리**로 1마리 더 많았어요."
2. **곰별 먹은 수** — 곰 아래 큰 숫자 3개(최다 곰 강조). 헛물기가 있으면 작은 글씨 "헛물기 1 (안 먹음)".
3. 헛물기가 있었던 라운드: "헛물기 3번은 먹은 게 아니에요 (단풍 1, 도토리 2)." — 특히 헛물기를 더했을 때 고른 곰이 최다가 되는 오답이면: "단풍(1번)은 6마리 먹고 2번 헛물었어요. 헛물기까지 세면 8번이라 많아 보였을 거예요."
4. **타임라인** — 가로 3줄(곰별), 각 사건을 시각 위치에 점으로: 진짜 = 채운 연어 아이콘, 헛물기 = 빈 테두리 + ✕. 줄 끝에 합계 숫자. 동시 사건은 세로로 나란히 보인다.
5. **다시보기** — 방금 라운드를 **같은 사건 목록·같은 시각**으로 다시 재생하고, 곰 머리 위 카운터가 진짜 먹을 때마다 +1(헛물기는 "헛!" 표시만, 숫자 그대로), 타임라인 위 진행선이 함께 움직인다. 기본 속도 ×1(실제 속도 그대로), "느리게 ×0.5" 토글. 여러 번 볼 수 있음. 다시보기는 점수·목숨에 영향 없음.
- 숫자 정확성: 해설·타임라인·다시보기 카운터 모두 **같은 사건 목록 하나**에서 계산한다(따로 세지 않음). 다시보기 끝의 카운터 = 곰별 숫자 = 타임라인 합계.

### 보고 배우기 (글 대신 첫 경험으로)
| 시점 | 배너(카운트 전, 1.5초 또는 탭으로 닫기) |
|---|---|
| 1레벨 | "연어를 하나씩 세어 보세요" |
| 5레벨(동시 첫 등장) | "이제 두 마리가 동시에 먹기도 해요" |
| 6레벨(헛물기 첫 등장) | "놓친 연어(헛물기)는 세지 마세요" + 배너 안 작은 그림으로 "꿀꺽(먹음)"과 "헛물기(안 먹음)"를 1번씩 시연(라운드 사건·집계에 포함되지 않음, 배너는 탭할 때까지 유지) |
| 7레벨 | "이제 차이는 단 1마리!" |
| 9레벨 | "박자가 불규칙해져요" |
- 배너는 해당 레벨에 **처음** 들어갈 때만(같은 판의 재도전에서는 생략). 매 판 다시 보인다(짧으니 생략 저장 안 함).

## 콘텐츠
- 곰 3마리(위치 고정), 연어(진짜/헛물기 같은 모양 — 차이는 결과 연출에만), 강·물보라.
- 레벨: 위 표 1~15 + 16 이후 규칙. 아이템·파워업 없음.

## 밸런스 검증 (QA 기준)
테스트 훅 `window.__bear`:
| 멤버 | 설명 |
|---|---|
| `genRound(level, seed, history?)` | 라운드 객체 {level, counts:[a,b,c], fakes:[a,b,c], winner, events:[{t, bear(0~2), real}], slots, durationMs, fallback} (DOM 없이 순수 함수) |
| `validate(round)` | 위반 목록 배열(빈 배열이면 통과) — 아래 항목 전부 검사 |
| `state()` | {screen, level, lives, score, best, round} 깊은 복사 |
| `start(seed, level?)` | 시드·시작 레벨 지정 새 게임 (URL `?seed=N&level=L`도 동일) |
| `answer(bear)` | 선택 주입 (0~2) |
| `skip()` | 준비·먹기 연출 즉시 끝내기 |
| `log()` | 마지막 라운드의 실제 화면 사건 시각 기록 [{bear, real, scheduledT, shownT}] |

**자동 검사 (레벨 1~25 × 시드 1~1000)**
1. 최다 곰 정확히 1마리, M − S = 레벨 차이, S − T ≤ 근접 제한, S ≥ T ≥ 1, M+S+T ∈ N 범위.
2. 1~15레벨: 나온 개수 조합이 표의 "가능한 개수 조합"과 정확히 같은 집합(빠진 것·추가된 것 없음).
3. 헛물기 수 = 표 값, 첫 헛물기는 2위 곰, 한 곰당 ≤ 2, 6~9레벨은 헛물기가 동시 슬롯에 없음.
4. 같은 곰 사건 간격 ≥ 500ms, 슬롯 간격 ≥ 300ms, 슬롯당 ≤ 2개·서로 다른 곰, 같은 곰 연속 ≤ 3슬롯, 빈 슬롯 연속 ≤ 2, 첫 슬롯 사건 1개.
5. 순서 규칙(반 지점/역전/막판) 해당 레벨에서 100% 지킴. `fallback` 0회.
6. 먹기 시간 6~13초. 레벨별 평균·최소·최대를 리포트에 표로.
7. 정답 위치 분포: 레벨당 1000라운드에서 각 위치 30~37%. 연속 라운드 생성(history 사용) 3000라운드에서 같은 위치 3연속 0회.
8. 동시 비율: 실제 동시 슬롯 비율이 표 값 ±7%p 안(간격 규칙 때문에 약간 낮을 수 있음 — 벗어나면 보고).

**화면 검사 (Chromium, PC·iPad 세로/가로)**
9. `log()`의 shownT − scheduledT 가 ±40ms 안(연출이 일정에 맞음).
10. 먹기 끝 → 선택 화면에서 곰 3마리 영역 스크린샷이 구분 표시를 빼고 같음(배·표정·잔해 차이 없음). 먹기 중·선택 중 화면에 숫자 없음.
11. 먹기 중 곰 탭·1/2/3 키는 무시, 선택 화면 첫 300ms 입력 무시.
12. 해설 숫자 = counts, 타임라인 점 개수 = counts + fakes, 다시보기 끝 카운터 = counts (×1, ×0.5 둘 다).
13. 오답 → 목숨 −1, 같은 레벨 새 순서(이벤트 목록이 다름). 목숨 0 → 게임 오버 화면에 마지막 라운드 해설·다시보기. 점수 = 클리어 레벨 수, 최고 기록 저장·갱신.
14. 먹기 중 `visibilitychange` hidden → 라운드 무효, 목숨 그대로, 같은 레벨 재시작.
15. 사람 속도 확인(수동, QA 1인 플레이): 1~3레벨은 대충 봐도 맞힐 수 있어야 하고, 7~9레벨은 집중하면 맞힐 수 있는 수준. 결과를 qa-report에 "사람 체감"으로 기록(미검증 시 미검증 명시).
