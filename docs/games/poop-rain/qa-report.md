# 똥비 피하기 (poop-rain) QA 리포트

## 2026-11-13 QA — 최초 구현 (games/poop-rain/index.html + 목록 카드)
판정: **실패 (밸런스 기준만)** — 기능, 흐름, 입력, 공정성, 레이아웃, 회귀는 모두 통과했다. 실패 사유는 design.md 「난이도 목표」의 통과 기준(봇별 생존 시간 중앙값)을 맞추지 못한 것 하나다. 지금 게임은 목표보다 **어렵다**. 코드 버그는 낮음 2건뿐이다.
조정 수치는 아래 「밸런스」에 있다. 지금 난이도를 그대로 받아들일지는 CEO가 판단한다.

### 실행한 테스트와 결과
도구: Playwright + Chromium. 스크립트는 저장소 밖 스크래치 폴더에 있다(`bots.js`, `sim.js`, `func.js`, `layout.js`, `mkvar.py`).

**1. 스모크 (`node tests/smoke.js`)**: 6게임 × PC / iPad 세로 / iPad 가로 = 18개 모두 통과. 목록 순서는 poop-rain, bungeo-snowfight, mole-pop, bunny-ten, snake-garden, block-stack이다. 기존 5게임 회귀 문제 없음.

**2. 규칙·흐름 (func.js, 61개 검사 모두 PASS)**
- 히트박스: 기본 똥은 중심 거리 29u에서 맞고 31u에서 안 맞는다(34×40 상자 + 반지름 13). 왕똥은 40u에서 맞고 42u에서 안 맞는다. 상자 가장자리 안쪽 10u 겹침은 맞는다.
- 아슬: 간격 1u와 12u는 +1, 13.5u는 0. 왕똥 12u는 +1. 점수(시간)에는 영향 없음. 결과 화면에 "아슬 N번"이 나온다.
- 난이도 표: t = 0/3/10/20/30/45/60/90초의 간격·속도·동시 최대·조준 비율이 표와 정확히 같다. 점 사이는 선형 보간된다(6.5초: 0.32 / 435 / 8 / 0.275). 90초 이후도 공식대로다(100초 0.095/800, 150초 이상 0.08/900).
- 처음 3개 똥: 0.517 / 1.1 / 1.717초에 x = 캐릭터 x(300), 속도 364~368. 그 사이 무작위 똥도 나온다.
- 변형 등장: 첫 왕똥 12.47초, 첫 흔들 똥 20.2초, 첫 우산 15.0초. 이후 우산 간격은 15.07~19.85초다(15회).
- 동시 최대: 왕똥 최대 2, 흔들 똥 최대 3, 화면 위 똥 수가 동시 최대를 넘은 적 0회.
- 낙하 속도 배율(기본 ×0.92~1.08, 왕 ×0.8, 흔들 ×0.9): 위반 0건.
- 실제 비율(무적 봇 3판): 40초 이후 왕똥 9.0%, 흔들 12.4%. 기획은 14%/15%다. 동시 최대 2/3에 걸린 것이 기본 똥으로 바뀌기 때문이고 기획 규칙대로다.
- 우산: 먹으면 무적 2.98(3.0)초. 무적 중에는 기본 똥과 왕똥을 맞아도 산다. 무적 중 다시 먹으면 3.0으로 다시 채운다(누적 없음). 무적이 끝나면 다시 맞는다.
- 게임 오버: dying 상태가 되고 시간이 멈춘다. 0.6초 뒤 결과("철퍽!", 시간, "최고 N초 · 아슬 N번")가 뜬다. 0.5초 동안 다시 하기가 disabled이고 그동안 클릭·Space·탭은 무시된다. 잠금이 풀리면 다시 하기에 포커스가 간다. 이후 클릭·탭 한 번, Space, Enter(포커스 없음) 모두 즉시 새 판(t≈0, x=300). "처음으로"를 누르면 시작 화면으로 가고 최고 기록이 보인다.
- 최고 기록: `poop-rain-best`에 저장되고 "새 기록!" 배지가 나온다. 더 짧은 판은 기록을 유지하고 배지도 없다. localStorage 접근이 막혀도 오류 없이 결과까지 간다. simulate나 setInvincible을 쓴 판은 저장하지 않는다(의도).
- 일시정지
  - P, Esc, Ⅱ 버튼, 탭 숨김(visibilitychange)에서 일시정지된다. 시간이 멈추고 덮개는 78% 반투명이다.
  - 재개(Esc, "계속")하면 resuming 상태가 1.0초 이어진다. 그동안 시간은 멈추고 키보드로 캐릭터는 움직일 수 있다. 이후 playing으로 돌아간다.
  - 맞은 연출 중에는 숨김·blur가 와도 자동 일시정지하지 않는다.
  - 일시정지 화면의 "처음으로"를 누르면 시작 화면으로 간다.
- 첫 판 힌트: 첫 판에만 나온다. 터치에서는 "← 끌어서 피하기 →"와 손가락 그림, PC에서는 "← → 또는 마우스"이고, 두 번째 판에는 없다(스크린샷 확인).
- 음소거: 클릭하면 icoOn은 display:none, icoOff는 표시로 실제 전환된다. aria-pressed=true, 라벨 "소리 켜기", 저장값 `poop-rain-muted`='1'. 새로고침해도 유지되고 M 키로 다시 켜진다.

**3. 입력**
- 키보드: 0.5초 누르면 실측 497u/s(가속 포함, 최고 520). 떼면 6.5u 안에 정지. A/D를 같이 누르면 나중에 누른 쪽으로 가고, 그 키를 떼면 남은 키 방향으로 간다.
- 마우스: 절대 추적한다(필드 80% 지점이면 x=480.0). 키를 누른 뒤 마우스가 5px 움직이면 무시하고, 15px 움직이면 다시 추적한다.
- iPad 세로·가로 터치(CDP touch 이벤트)
  - 땅에서 100px 끌면 정확히 100px × (600/필드 폭) u만큼 움직인다(세로 80u, 가로 110u).
  - 필드 밖 여백에서 끌어도 조종된다(세로는 필드 아래, 가로는 왼쪽 여백).
  - 손을 떼면 그 자리에 멈추고, touchcancel이 와도 멈춘다.
  - 오른쪽 끝(583)에 붙은 상태에서 반대로 끌면 바로 반응한다.
  - 멀티터치: 두 번째 손가락만 조종하고, 첫 손가락 이동은 무시한다. 두 번째 손가락을 떼면 첫 손가락이 움직여도 멈춘다.
  - 스크롤 0, visualViewport.scale 1(끌기와 더블탭 후), body touch-action none, 가로·세로 넘침 없음.
  - 결과 잠금 중 탭은 무시되고, 잠금 후 탭 한 번이면 새 판이 시작된다. Ⅱ와 "계속" 탭도 동작한다.

**4. 공정성 (완벽 봇)**
완벽 봇은 미래 위치를 정확히 아는 계획 봇이다. 1/30초 단위로 경로를 탐색하고, 중앙을 선호하며 벽을 피한다. 각 100판, 120초.

| 이동 한도 | 공정성 모드 | 120초 생존 |
|---|---|---|
| 키보드 520 u/s | strict(기본) | **100/100** |
| 키보드 520 u/s | spec(design.md 규칙만) | **100/100** |
| 480 u/s(더 느리게) | strict | 100/100 |
| 터치 1,100 u/s | strict / spec | 100/100 / 100/100 |

- 기준 ≥98/100을 충족하고, 피할 수 없는 배치는 0이다. 흔들 똥과 왕똥도 포함한 결과다.
- 참고 1: 처음 만든 봇(가장 가까운 안전 칸 선호)은 49~84/100에 그쳤다. 사망 지점을 추적해 보니 모두 봇이 벽(x=17)으로 피했다가 조준 똥에 갇힌 경우였다. 게임의 공정성 문제가 아니다. 공정성 검사는 "지금 위치에서 길이 있는가"만 보장하므로, 플레이어 입장에서 **벽에 붙는 것은 위험한 선택**이다(실기기 감상 확인 대상).
- 참고 2: 5초 시점 화면의 똥 수는 평균 5.17개다(기준 ≥4).
- fairStats(완벽 봇 100판 누적, strict): bucket 거절 37~46, link 0~4, path 7~50. 거절된 똥은 조건을 다시 뽑거나 미뤄 정상 처리됐다.

**5. 레이아웃 (6개 뷰포트 × 라이트/다크 = 12개, 시작·플레이·우산·일시정지·결과 스크린샷 60장을 직접 확인)**

| 화면 | 필드 (CSS px) | ov-full | 결과 |
|---|---|---|---|
| PC 1280×800 | 537×716 | 아니오 | OK |
| iPad 810×1080 | 747×996 | 아니오 | OK |
| iPad 1080×810 | 544×725 | 아니오 | OK |
| iPad 1080×740 | 492×656 | 아니오 | OK |
| 폰 844×390 | 235×313 | 예 | OK (작음, 아래 의견) |
| 폰 390×844 | 366×488 | 예 | OK |

- 12개 모두 다음을 만족한다: 스크롤 넘침 없음, 필드 비율 0.75, 필드가 화면 안(bottom ≤ innerHeight−4), 음소거·Ⅱ 버튼 44×44, 시작하기·다시 하기·계속 버튼이 화면 안.
- RainDigits 글꼴은 12개 모두 `document.fonts.check` true로 로드됐다.
- 폰 가로(844×390) 의견: 필드가 235×313px라 똥이 약 16px, 콩이가 약 25px로 작다. 손가락 1px이 2.55u로 민감하지만 상대 끌기라 정밀도는 손가락 이동량으로 조절된다. 화면 어디서 끌어도 되므로 손가락이 필드를 가리지 않는다. **플레이는 가능하지만 답답하다.** 세로로 돌리면 366×488이 되어 훨씬 낫다. 주 대상이 iPad이므로 지금 상태로 수용할 만하다. 개선하려면 폰 가로에서만 상단 바를 필드 옆으로 옮겨 세로를 더 쓰는 방법이 있다(선택).

**6. 비주얼 (스크린샷 직접 확인)**
- 똥: 3단 소용돌이와 꼭지, 하이라이트 1개만 있고 얼굴·파리·얼룩이 없어 귀엽고 깔끔하다. 왕똥(크고 진함)과 흔들 똥(밝은 캐러멜, 기울기, 양옆 괄호 선)이 크기와 모양으로 구분된다. 착지는 납작해지며 사라지고 자국이 남지 않는다.
- 많아질 때: 70초대에 화면의 똥은 약 10~14개다. 크기가 같고 간격이 고르며 배경이 단색이라 어지럽지 않다. 다크에서도 똥과 하늘의 대비가 좋다.
- 예고 그림자: 땅 가까이 온 똥의 그림자는 잘 보인다. 막 생긴 똥의 그림자(라이트 α 0.10)는 매우 옅어 거의 안 보이지만, art-ui 의도(멀면 옅게)대로다. 흔들 똥 그림자는 흔들 범위만큼 넓다.
- 콩이: 둥근 얼굴, 앞머리, 민트 상의다. 바라보는 방향으로 가르마와 눈이 바뀌고, 맞으면 `> <`와 똥 모자가 나온다. 원작 캐릭터 연상은 없다.
- 우산: 펼친 캐노피가 머리 위에 보이고, 상단 알약(폰에서는 필드 왼쪽 위)에 남은 시간 막대가 나온다.
- 글꼴: RainDigits는 name 테이블 모두 "RainDigits"이고, 글리프는 0-9 . : + × s이며 tnum이 있다. 압축 해제한 바이트에 "Pretendard" 없음(fontTools 확인). HTML 주석에 출처 표기로 "Pretendard"가 한 번 나오는데, OFL 출처 표기라 문제없다.

**7. 첫 페이지**: 카드 6개가 똥비 피하기 → 붕어빵 눈싸움 → 두더지 뿅뿅 → 개구리 텐 → 뱀 정원 → 블록 스택 순서다. 카드를 누르면 `games/poop-rain/`으로 가고, "← 게임 목록"을 누르면 목록으로 돌아온다. 콘솔·페이지 오류 0건.

### 밸런스 — 반응 시간 봇 (각 100판, 시드 0~99)
design.md 모델을 따랐다. R초 전 화면을 보고 0.05초마다 결정한다. 10u 후보 칸마다 1.0초 앞까지 경로와 겹치는지 검사해 가장 가까운 안전 칸으로 간다. 목표 x에 σ 떨림을 더하고, 키보드 방식(520u/s, 가속)으로 움직인다. 2초 안에 닿을 수 있는 우산은 잡으러 간다.
이 모델에는 **"R초 전 위치를 그대로 믿는가, 움직임을 보정하는가"**가 정해져 있지 않다. 결과가 이것에 크게 좌우되므로 세 가지로 측정했다.

| 모델 | 초보 (0.42/14) | 보통 (0.32/10) | 숙련 (0.24/6) |
|---|---|---|---|
| A. 문자 그대로(옛 위치를 지금 위치로 믿음) | 17.2 | 17.1 | 17.3 |
| D. 움직임 75% 보정 (**중심 추정**) | 21.3 (25~75%: 13.7~30) | 26.9 (16.7~34.6) | 31.9 (21.9~43.3) |
| B. 움직임 100% 보정(위치를 완벽히 외삽) | 46.7 | 57.1 | 61.0 |

- A는 Developer의 대략 봇 결과(15~18초)와 같다. 시간 착오가 0.1초를 넘으면 R과 상관없이 모두 비슷하게 죽는다. 비관적인 하한으로 본다.
- B는 1초 이상 앞을 완벽히 보므로 R이 거의 의미가 없다. 낙관적인 상한으로 본다.
- 실제 사람은 그 사이에 있다고 보고 D를 중심 추정으로 삼았다. D 기준: 초보는 목표 안이고, 보통(26.9)과 숙련(31.9)은 목표보다 짧다. **지금 게임은 기획보다 어렵다.**
- 숙련과 초보의 차이가 작다(약 1.5배, 목표는 약 2.4배). 30초 이후 밀도가 빠르게 올라 실력 차이가 덜 드러나는 구조다.

- **이 세 손잡이로는 숙련 60초 이상을 맞출 수 없다.** 간격을 ×1.4까지 늘려도 숙련은 약 44초에서 멈추고, 그 전에 5초 기준이 깨진다. 숙련 목표까지 맞추려면 30초 이후 곡선(속도·간격의 상승 기울기, 동시 최대)을 완만하게 하는 기획 변경이 필요하다. 이는 design.md 조정 범위 밖이라 Game Designer와 CEO가 판단할 일이다.
- 사용자 취향 의견: 사용자는 "너무 쉬우면 지루함"을 두 번 말했다. 그러니 지금 값(보통 약 27초)도 "짧고 긴장감" 쪽으로는 수용 가능한 범위다. 다만 첫 판의 체감은 모델 A(약 17초)에 가까울 수 있다. 억울함 없이 한 판 30초 안팎을 원한다면 위 제안 조합이 가장 균형이 맞다.
- 덜 바꾸고 싶다면 ① 간격 ×1.2만 적용해도 된다. 결과는 28.4 / 32.5 / 45.2이고 5초 똥 수는 4.25다.
- 이 수치는 모두 봇 모델의 추정이다. **실제 사람 몇 판으로 확인이 필요하다.**

### 버그 (심각도: 치명/높음/보통/낮음)
- [낮음] **우산 알약이 상단 바에 나오면 버튼이 오른쪽으로 밀린다.**
  - 증상: PC 1280×800에서 무적 중에는 음소거·Ⅱ 버튼이 약 62px 오른쪽으로 이동한다(Ⅱ 오른쪽 끝 919px → 981px). 상단 바(560px)를 넘쳐 필드 오른쪽 밖으로 나간다. iPad 가로 1080×810, 1080×740도 같다(제목이 보이는 폭 ≥1000에서 특히 심함). 플레이 중 Ⅱ 버튼 위치가 바뀌는 셈이다. 화면 밖으로 나가지는 않는다.
  - 재현: PC에서 시작 → 15초 뒤 우산 획득(또는 `__poop.spawnItem(x)`). 60초 이상이면 시간 알약이 "1:17.5"로 넓어져 더 심하다.
  - 기대: 상단 바 안에서 버튼 위치가 고정되어야 한다. 예를 들어 우산 알약을 시간 알약 아래나 필드 안으로 옮기거나, `--topw` 계산에 알약 폭을 포함한다.
  - 관련 코드: `.top { width: var(--topw) }`, `layout()`의 `--topw = min(W, max(fw, 560))`, `#upillTop`(.upill.intop)
  - 스크린샷: `layout/pc-1280x800-light-umbrella.png`, `layout/ipad-1080x740-dark-umbrella.png`
- [낮음] **흔들 똥이 땅에 닿는 프레임에서 판정이 가로로 최대 약 4u 더 나간다.**
  - 증상: 하위 스텝에서 y는 착지 높이(landY)로 고정하지만, x(흔들림)는 스텝 끝 시각까지 더 진행한 위치로 판정한다. 그래서 착지 순간 흔들 똥이 실제보다 최대 약 4u(45·2π/1.1 × 1/60) 옆에서 맞힐 수 있다. 완벽 봇 추적에서 "보이는 마지막 위치로는 간격 16u인데 다음 프레임에 사망"한 사례로 발견했다(seed 32, 21.8초. 여유 1.5u의 초기 봇).
  - 영향: 아주 드문 "착지 직전 스침" 억울함이다. 공정성 검사 여유 4u와 비슷한 크기라 완벽 봇 결과(100/100)에는 영향이 없다.
  - 기대: 착지 시점(나머지 시간 비율)의 x로 판정하거나, 착지 프레임에서는 흔들림을 진행하지 않는다.
  - 관련 코드: `stepPlaying()` 똥 이동 루프의 `p.age += h; … if (p.y > ly) p.y = ly; var hb = circleBox(...)`
