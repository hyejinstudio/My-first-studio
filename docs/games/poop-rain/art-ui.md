# 똥비 피하기 아트·UI 명세

> slug: `poop-rain` · 기획서 `docs/games/poop-rain/design.md`(똥 종류·속도·예고 시간·아이템·목숨·점수 규칙)와 `sound.md`를 함께 본다. **수치(속도, 판정 크기, 예고 시간, 우산 지속 시간, 목숨 수, 점수식)는 design.md가 정하고**, 이 문서는 그것을 어떻게 그리고 보여 줄지만 정한다. 아래 `3초`, `+N` 등은 자리 표시용.
> 그래픽은 **Canvas 2D(필드) + DOM/인라인 SVG(HUD·오버레이·버튼)**. 이미지 파일·이모지 그래픽 없음(💩 이모지 사용 금지 — 플랫폼마다 모양이 다르고 얼굴이 들어 있음).
> 시안 렌더로 확인한 그림 좌표다(Chromium). 그대로 옮기면 된다.

## 스타일 콘셉트
- "흐린 오후 공원에 내리는 소프트아이스크림 비": 연한 회청 하늘 + 연한 세이지 잔디 땅. 그 위로 **갈색 소프트아이스크림 모양 똥**이 떨어지고, 땅 위의 작은 아이가 좌우로 종종 걸어 피한다.
- **눈 피로 최소화 (사용자 누적 취향)**: 채도 낮은 흙·풀·하늘색, 외곽선은 1.5px 같은 계열 연한 색. 하늘 그라데이션·광택·강한 그림자 없음. **화면 전체 깜빡임·흔들림(셰이크) 금지, 어떤 요소도 점멸(on/off 반복) 금지** — 상태 변화는 색·크기·투명도의 연속 변화로만.
- **똥은 귀엽고 깔끔하게**: 3단 소용돌이 + 위로 살짝 말린 꼭지, 둥글고 매끈. 파리·냄새선·흩뿌림·얼룩 자국 **없음**. 땅에 닿으면 말랑하게 눌렸다가 사라지고 자국을 남기지 않는다.
- **똥 얼굴(눈) 없음 — 결정**: 낙하물이 한 화면에 10개 이상일 수 있으므로 눈·입을 그리면 "점 무리"가 되어 어지럽다(개구리 텐 숫자판 교훈). 얼굴 대신 작은 하이라이트 1개만.
- **얼굴은 주인공 한 명만**: 점 눈 2개(맞으면 `> <`). 화면에 얼굴이 하나뿐이라 시선이 자연스럽게 주인공에게 간다.
- **주인공 "콩이"(오리지널)**: 둥근 얼굴 + 이마를 덮는 갈색 앞머리 캡 + 민트색 둥근 상의 + 회청 바지 다리 2개. 모자·우산·소품·동물 귀 없음(기존 캐릭터 연상 방지). 앞머리 가르마·눈 위치가 **바라보는 방향**으로 바뀌어 좌우 이동이 잘 보인다.
- 스튜디오 공통: 페이지 배경 `--bg`(종이색), 흰 패널, 주황 `--accent`, 둥근 모서리, 상단 바 + 오버레이 구조는 두더지 뿅뿅·붕어빵 눈싸움과 같다.
- 글꼴: 글자는 사이트 공통 `system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", sans-serif`. **숫자(생존 시간·점수·최고·결과·팝업)는 RainDigits**.

### 숫자 글꼴 RainDigits (Pretendard ExtraBold 800 서브셋, SIL OFL 1.1)
- 기존 게임과 같은 방식. 파일: `games/poop-rain/fonts/rain-digits-800.woff2` + 같은 폴더 `OFL.txt`(기존 게임 것 복사 가능).
- 서브셋 글리프: `0-9`(U+0030–0039), `.`(U+002E), `:`(U+003A), `+`(U+002B), `×`(U+00D7), `s`(U+0073 — 폭이 좁은 폰 HUD에서 `12.3s` 표기 대비. 기본 표기는 한글 "초").
  - 예: `pyftsubset Pretendard-ExtraBold.otf --unicodes="U+0030-0039,U+002E,U+003A,U+002B,U+00D7,U+0073" --flavor=woff2 --layout-features='tnum' --output-file=rain-digits-800.woff2`. **`tnum` 유지**(시간이 0.1초마다 바뀌어도 글자 폭이 흔들리지 않게 — 중요).
  - **Reserved Font Name 때문에 이름 변경 필수**: name 테이블 family/full/PostScript/typographic 모두 `RainDigits`, 압축 해제 바이트에 "Pretendard" 문자열 없음(QA가 fontTools로 확인).
  ```css
  @font-face { font-family: "RainDigits"; src: url("fonts/rain-digits-800.woff2") format("woff2");
    font-weight: 800; font-style: normal; font-display: swap;
    unicode-range: U+0030-0039, U+002E, U+003A, U+002B, U+00D7, U+0073; }
  :root { --num-font: "RainDigits", system-ui, -apple-system, "Apple SD Gothic Neo", sans-serif; }
  .num { font-family: var(--num-font); font-weight: 800; font-variant-numeric: tabular-nums; }
  ```
- 시간 표기: 60초 미만 `12.3`(소수 1자리) + 단위 "초"(시스템 글꼴, 숫자보다 작게). 60초 이상 `1:02.3`. 천 단위 쉼표 쓰지 않는다(서브셋에 없음). 점수가 따로 있으면 정수만.

## 필드 좌표계와 그리기 (Canvas 2D)

### 단위 u
- 필드 논리 너비 = **14u 고정**. `u = 캔버스 CSS 너비 / 14`. 필드 높이는 화면에 따라 9.3u~18.7u(아래 레이아웃 비율 제한).
- 따라서 design.md 값은 **가로는 u(또는 너비 비율), 세로 낙하는 "필드 높이를 몇 초에 통과"(시간 기준)** 로 정하길 권장 — 화면이 세로여도 예고·반응 시간이 같아 공정하다. (CEO: design.md와 맞춰 주세요.)
- `groundY` = 필드 높이 − 1.4u (땅 띠 두께 1.4u). 똥은 **아래 끝(바닥 중심)** 이 groundY에 닿으면 착지.
- 캔버스 내부 해상도 = CSS 크기 × `min(devicePixelRatio, 2)`, `ctx.setTransform(dpr,0,0,dpr,0,0)` 후 CSS 픽셀로 그림. 선 굵기는 CSS 픽셀 고정(아래 "1.5px").

### 그리는 순서 (매 프레임)
1. 하늘 `--sky` 전체 채움 → 구름 3개 → 땅 띠 `--ground` + 윗선 1px `--ground-edge`.
2. 낙하 예고 그림자(땅 위).
3. 터치 목표 ▲ (터치 중일 때만).
4. 착지 중인 똥(눌림 애니메이션), 튕겨 나가는 똥(우산에 막힘).
5. 콩이(+펼친 우산).
6. 떨어지는 똥·아이템.
7. 팝업 글자(근접 회피 "아슬!" 등).
- 하늘·구름·땅은 크기 바뀔 때만 오프스크린 캔버스에 그려 두고 매 프레임 `drawImage`.

### 배경
- 하늘: `--sky` 단색. 그라데이션 금지.
- 구름 3개(고정 위치, **움직이지 않음** — 낙하물과 헷갈리지 않게): 각 구름 = 타원 3개 합(중심 (x,y), 크기 k=u·0.9 기준):
  `ellipse(x, y, 1.5k, 0.4k)`, `ellipse(x−0.45k, y−0.25k, 0.65k, 0.45k)`, `ellipse(x+0.4k, y−0.3k, 0.55k, 0.4k)`, 색 `--cloud`, 외곽선 없음.
  위치: (2.2u, 1.2u, k×1), (9.6u, 2.0u, k×0.8), (12.6u, 0.9u, k×0.6). 세로 화면에서도 위쪽 2.5u 안에만.
- 땅: `fillRect(0, groundY, W, H−groundY)` `--ground`, `fillRect(0, groundY, W, 1)` `--ground-edge`. 풀잎·돌 장식 없음.

### 똥 공통 모양 (원점 = 바닥 중심, 크기 s = 바닥 너비)
위쪽이 −y. 하나의 path에 아래 도형을 모두 넣는다:
```js
function poopPath(c, s) {
  c.beginPath();
  c.ellipse(0, -.17*s, .50*s, .17*s, 0, 0, Math.PI*2);          // 아래 단
  c.moveTo(.38*s, -.42*s); c.ellipse(0, -.42*s, .38*s, .15*s, 0, 0, Math.PI*2); // 가운데 단
  c.moveTo(.25*s, -.63*s); c.ellipse(0, -.63*s, .25*s, .13*s, 0, 0, Math.PI*2); // 위 단
  c.moveTo(-.13*s, -.70*s);                                      // 말린 꼭지
  c.quadraticCurveTo(-.10*s, -.86*s, .04*s, -.91*s);
  c.quadraticCurveTo(.13*s, -.93*s, .09*s, -.84*s);
  c.quadraticCurveTo(.07*s, -.77*s, .14*s, -.70*s);
  c.closePath();
}
```
그리기 (순서 중요 — **바깥 외곽선만** 남기는 방법):
1. `poopPath` → `lineJoin='round'; lineWidth=3; strokeStyle=선색; stroke()` (바깥으로 1.5px가 남음)
2. 같은 path `fillStyle=몸색; fill()` (안쪽 선을 덮음 → 단 사이 겹침 선 없음)
3. 단 구분선 2개(소용돌이 느낌): `globalAlpha=.45, lineWidth=1.2, 선색` — `M(−.34s,−.30s) Q(0,−.24s) (.34s,−.30s)` 와 `M(−.22s,−.53s) Q(0,−.48s) (.22s,−.53s)`
4. 하이라이트: `--poop-hi`, α .35(다크 .18), `ellipse(−.17s, −.45s, .07s, .035s, −0.3rad)`
- 높이 ≈ 0.93s, 너비 = s. **얼굴 없음.**
- 성능: 종류별로 한 번 오프스크린 캔버스(스프라이트)에 그려 두고 `drawImage`(회전은 그 위에서). 크기 바뀌면 다시 만든다.

### 똥 종류 (design.md가 확정한 종류만 구현. 없는 종류는 생략)
| 종류 | s | 몸 / 선 | 모양 구분 (색 외) | 낙하 연출 |
|---|---|---|---|---|
| 기본 똥 | 0.8u | `--poop` / `--poop-line` | 기준 크기, 똑바로 | 똑바로 낙하. 회전 없음 |
| 큰 똥 | 1.3u | `--poop-big` / `--poop-big-line` | **1.6배 크기**, 한 톤 진함 | 똑바로. 예고 그림자도 큼 |
| 흔들 똥 | 0.8u | `--poop-wob` / `--poop-wob-line` | **좌우로 기울며 흔들림 + 양옆 흔들 선** | 아래 참고 |
| (추가 종류가 생기면) | — | 갈색 계열 안에서 명도만 다르게 | 반드시 **크기·기울기·부가 표시 중 하나**로 모양 구분 | — |

- **흔들 똥**: design.md의 좌우 흔들림(x 오프셋)에 맞춰, 몸을 `rotate(θ)`, θ = 흔들 방향 × 최대 10°(x 속도에 비례). 회전 중심 = 몸 가운데(바닥에서 0.45s 위). 양옆 **흔들 선**: 몸 중심 기준 반지름 0.62u 원호 2개(왼쪽 153°~198°, 오른쪽 −18°~27°), `--poop-wob-line` α .4, 1.5px. 회전하지 않음(몸만 기울어짐).
- 낙하물에는 잔상·꼬리·속도선 없음(화면이 지저분해짐).

### 낙하 예고 그림자 (공정성·가독성의 핵심)
- 땅 위 `(착지 x, groundY + 0.12u)`에 납작한 타원: `rx = 0.4·s·(0.6 + 0.4·p)`, `ry = rx·0.28`, `--shadow`.
- `p` = 낙하 진행도 0→1(생성 시 0, 착지 시 1). **α = 0.10 + 0.22·p** (라이트), 다크는 **0.25 + 0.35·p**(검은 그림자가 어두운 땅에서도 보이게). 즉 멀리 있을 땐 작고 옅게, 가까울수록 크고 진하게 → 어느 것이 먼저 떨어질지 한눈에.
- 똥이 화면 위 밖에서 생성될 때도 그림자는 **생성 즉시** 보인다(예고 시간은 design.md). 그림자 자체는 판정 없음.
- **흔들 똥**: 착지 x가 흔들림 범위 안에서 바뀐다면 그림자를 **흔들림 전체 범위만큼 가로로 늘린 타원**(rx = 0.4s + 흔들 진폭)으로 그리고, α는 같게. 즉 "이 폭 안 어딘가에 떨어진다"를 정직하게 보여 준다. 착지 x가 고정이면 일반 그림자.
- 우산 아이템도 같은 방식의 그림자(색은 `--item`, α 절반) — 받으러 갈 위치가 보이게.

### 착지 연출 (지저분하지 않게)
- 똥 바닥이 groundY에 닿으면: 0~120ms `scaleX 1→1.25, scaleY 1→0.55`(원점 = 바닥 중심, ease-out) → 120~420ms 그 모양으로 α 1→0 (ease-in). 끝. **자국·튀는 방울·쌓임 없음.**
- 착지 순간 땅 위에 아주 옅은 고리 1개: 타원 rx 0.5s→0.8s, `--poop-line` α .25→0, 1px, 300ms. (생략해도 됨)

### 우산 아이템 (design.md에 아이템이 있을 때)
- **낙하 중 모양**(원점 = 중심): 후광 원 r 0.55u `--item-halo` + 1.5px `--item` 테두리. 안에 접히지 않은 우산 아이콘:
  - 캐노피: `moveTo(−.36u,.02u); arc(0,.02u,.36u,π,0)` 후 아래 가장자리 물결 3개 `arc(cx,.02u,.12u,0,π,true)`를 cx = .24u, 0, −.24u 순서로 → `closePath(); fill(--item)`.
  - 손잡이: `moveTo(0,.02u) lineTo(0,.30u)` + `arc(−.08u,.30u,.08u,0,π)`, 2px `--item`, round cap.
  - 천천히 좌우 기울기 ±6°(사인, 주기 1.6초). **반짝임·점멸·크기 박동 없음.** 착지 그림자 있음(위 참고).
- **획득**: 아이콘이 콩이 머리 위로 날아가며 r 0.55u→0 (180ms ease-in), 동시에 펼친 우산 등장.
- **펼친 우산**(콩이 위): 캐노피 반지름 0.9u, 중심 = 콩이 원점에서 (0, −2.0u), 위 캐노피 path 그대로 크기만 키움, 손잡이 선이 머리 옆(−0.1u)까지. 콩이와 함께 기울어짐.
  - 등장: 캐노피 `scaleX 0→1` 160ms ease-out(펼쳐지는 느낌).
  - 남은 시간: 정확한 값은 HUD 우산 알약(아래)으로 표시하고, 캔버스에서는 **마지막 1.5초 동안 캐노피 색이 `--item` → `--item-fade`로 연속 변화 + α 1→.6**. 점멸 금지.
  - 끝: 캐노피 `scaleX 1→0` 160ms ease-in.
  - 똥이 우산에 맞으면: 그 똥은 위쪽 바깥으로 튕김(위로 0.6u, 옆으로 ±1u, 회전 ±30°, 300ms ease-out) + α 1→0. 캐노피는 맞은 순간 scaleY 1→0.92→1 (140ms). 맞은 자리에서 작은 원 고리 1개(r 0.2u→0.5u, `--item` α .5→0, 240ms).
- 추가 아이템이 생기면 같은 규칙: 둥근 후광 + 단순 아이콘, **갈색 계열 금지**(똥과 혼동), 후광 색만 바꿈.

### 주인공 콩이 (원점 = 발 중심, groundY 위)
크기: 너비 약 0.88u, 높이 약 1.52u. `f` = 바라보는 방향(+1 오른쪽 / −1 왼쪽). 선은 모두 1.5px `--kid-line`.
1. 다리 2개(`--kid-pants`, 외곽선 없음): `roundRect(−.26u, −.16u, .18u, .16u, .06u)`, `roundRect(.08u, −.16u, .18u, .16u, .06u)`. 걷는 중이면 두 다리가 번갈아 y −0.04u 들림(주기 = 이동 속도에 비례, 최고 속도에서 6Hz).
2. 몸(상의): `roundRect(−.38u, −.80u, .76u, .68u, .28u)` fill `--kid-shirt` + stroke.
3. 머리: `arc(0, −1.10u, .42u)` fill `--kid-skin` + stroke.
4. (여기부터 `scale(f,1)`) 앞머리: `arc(0,−1.10u,.43u, π, 2π)` → `quadraticCurveTo(.30u,−1.20u, .10u,−1.22u)` → `quadraticCurveTo(−.20u,−1.14u, −.43u,−1.10u)` fill `--kid-hair`(가르마가 바라보는 쪽에 생김).
5. 눈: `arc(−.03u, −1.02u, .045u)`, `arc(.25u, −1.02u, .045u)` fill `--kid-eye` (바라보는 쪽으로 치우침). 입·볼·코 없음.
- **이동 기울기**: 움직이는 동안 원점 기준 `rotate(f × 6°)`(속도 비례, 0→6° 80ms ease-out), 멈추면 0°로 120ms. 방향 바꿀 때 `f`는 즉시 뒤집되 기울기는 연속.
- **대기**: 숨쉬기 scaleY 1↔1.02(원점 기준, 2000ms ease-in-out 반복).
- **피격 (맞았을 때)**:
  - 눈 → `> <`: 왼눈 `M(−.18u,−1.07u) L(−.08u,−1.02u) L(−.18u,−.97u)`, 오른눈 `M(.18u,−1.07u) L(.08u,−1.02u) L(.18u,−.97u)`, 2px round, `--kid-eye`(`scale(f)` 밖에서 그려 좌우 대칭).
  - 몸 눌림 scaleX 1.08 / scaleY 0.88 → 1 (220ms ease-out, 원점 기준). 기울기 0.
  - **맞은 똥이 머리 위에 작게 얹힘**: 같은 종류 똥 s = 0.4u를 (0, −1.50u)에 그림(떨어지던 위치에서 그 자리로 100ms 이동). 게임 오버면 결과 화면이 뜰 때까지 유지 — 귀여운 "똥 모자" 연출. 목숨이 남아 계속하면 600ms 뒤 α 1→0(300ms).
  - 화면 흔들기·빨간 번쩍임·전체 화면 효과 **없음**.
- **목숨이 남은 경우의 무적 시간**(design.md에 목숨이 있으면): 콩이 α **0.5 고정**(점멸 금지) + 발밑 얇은 타원 고리(rx .6u, ry .15u, `--muted` α .5, 1px). 무적 끝나면 α .5→1 150ms.
- **근접 회피**(design.md 정의: 예 "똥이 콩이 판정 바깥 0.3u 이내에 착지"):
  - 땀방울: 콩이 머리 뒤쪽(−f 쪽) (−f·.45u, −1.40u)에 물방울 `M0,−.10u q.07u,.10u 0,.14u q−.07u,−.04u 0,−.14u` fill `--sweat`. 500ms 동안 위로 0.15u 떠오르며 α 1→0.
  - design.md가 근접 회피 보너스를 주면 콩이 위 (0, −1.9u)에 팝업 "아슬! **+N**"(13px 700 `--muted`, 숫자 `.num` `--ink`), 600ms 위로 0.3u + α 1→0. 보너스가 없으면 땀방울만.
- **우산 쓴 상태**: 위 "펼친 우산". 콩이 표정은 기본(점 눈).

### 높이 기준 레이아웃 규칙 (필수 — 기존 게임과 같음)
1. `--app-h` = `window.innerHeight + 'px'`, `resize`·`orientationchange`·`visualViewport.resize` 때 갱신. CSS 기본값 `100dvh`(미지원 `100vh`). `100vh` 단독 금지.
2. `html, body { height: var(--app-h); overflow: hidden; }`, body 패딩 `max(12px, env(safe-area-inset-*))` 네 방향, viewport meta `width=device-width, initial-scale=1, viewport-fit=cover`.
3. `W` = innerWidth − 좌우 패딩, `H` = app-h − 상하 패딩. 상단 바 `TB = 52`(높이 ≤ 520px이면 44), 아래 간격 8. 필드 영역 `A = H − TB − 8`.
4. **필드 비율 제한 0.75 ≤ 너비/높이 ≤ 1.5** (공정성 — 너무 넓거나 좁은 필드 방지):
   - `W / A > 1.5` → 높이 `A`, 너비 `floor(1.5·A)`, 가로 가운데. 좌우 남는 공간 = 여백(또는 폰 패드).
   - `W / A < 0.75` → 너비 `W`, 높이 `floor(W / 0.75)`, 상단 바 바로 아래 붙임. 아래 남는 공간 = 패드 줄.
   - 그 사이면 `W × A` 전부.
   - 필드 캔버스 `border-radius: 14px` + 1px `--grid` 테두리(CSS). 둥근 모서리는 CSS `border-radius` + `overflow:hidden` 래퍼로(캔버스 자체에 clip 안 해도 됨).
5. **터치 패드 표시 조건**: 좌우 여백 각각 ≥ 96px(가로 남는 경우) **또는** 아래 남는 높이 ≥ 96px(세로 남는 경우)일 때만 `body.has-pad`. 패드는 터치·마우스 모두 동작(키보드도 계속 동작).
   - 좌우 여백형: 왼쪽 여백에 ◀, 오른쪽 여백에 ▶. 각 패드 크기 `min(여백 − 8, 132)` 정사각, 필드 바닥선에 아래 정렬.
   - 아래 줄형: 필드 아래 8px 간격, 두 패드 가로 반반(간격 12), 높이 `min(남는 높이 − 8, 148)`.
6. JS가 `--fw`, `--fh`(필드 CSS 크기), `--u`를 넣는다. **크기가 바뀌어도 게임 상태는 u·진행도 기준으로 저장**해 다시 그리기만(떨어지는 똥의 x는 u, y는 진행도 p).
7. 수치표 (패딩 12, 안전 영역 0 기준):

| 화면 | W × H | TB | 필드 영역 A | 필드 (CSS px) | u | 필드 높이(u) | 남는 공간 / 패드 |
|---|---|---|---|---|---|---|---|
| PC 1280×800 | 1256 × 776 | 52 | 1256 × 716 | **1074 × 716** | 76.7 | 9.3 | 좌우 각 91px → 패드 없음(키보드) |
| iPad 가로 1080×810 | 1056 × 786 | 52 | 1056 × 726 | **1056 × 726** | 75.4 | 9.6 | 없음 |
| iPad 가로 1080×740 | 1056 × 716 | 52 | 1056 × 656 | **984 × 656** | 70.3 | 9.3 | 좌우 각 36px → 패드 없음 |
| iPad 세로 810×1080 | 786 × 1056 | 52 | 786 × 996 | **786 × 996** | 56.1 | 17.7 | 없음 |
| 폰 가로 844×390 | 820 × 366 | 44 | 820 × 314 | **471 × 314** | 33.6 | 9.3 | 좌우 각 174px → **◀▶ 패드 132×132** |
| 폰 세로 390×844 | 366 × 820 | 52 | 366 × 760 | **366 × 488** | 26.1 | 18.7 | 아래 264px → **◀▶ 패드 177×148** |

- 폰 세로는 회전 안내 없이 그대로 플레이(필드가 세로로 길어 오히려 예고 시간 체감이 좋음).
- 실제 iPhone 노치 가로에서는 안전 영역 때문에 여백이 줄어든다 — 그래도 96px 이상이면 패드, 아니면 화면 터치 조작만.
8. **검증 기준** (QA와 공유): 6개 뷰포트 모두 `scrollWidth ≤ innerWidth`, `scrollHeight ≤ innerHeight`, 필드·패드 `getBoundingClientRect()`가 화면 안(bottom ≤ innerHeight − 4), 필드 너비/높이 0.75~1.5, 상단 바 버튼 44×44, 패드 ≥ 96×96(있을 때). 844×390·390×844에서 패드 2개가 보임. 시작 오버레이의 "시작하기"와 결과 오버레이의 "다시 하기"가 6개 화면 모두 화면 안.

- **금지**: 화면 셰이크, 전체 화면 번쩍임, 점멸(어떤 요소든 켜짐/꺼짐 반복), 무지개·강한 채도 이펙트, 파티클 대량 분출.
- **`prefers-reduced-motion: reduce`**: 콩이 숨쉬기·기울기·걷기 다리, 착지 눌림·고리, 우산 기울기·튕김 회전, 팝업 이동 끔(팝업은 그 자리 α 1→0만). 흔들 똥의 **기울기는 끄되 흔들 선과 늘어난 그림자는 유지**(정보). 낙하·이동 자체는 게임이므로 그대로. `> <` 표정과 똥 모자는 유지.
- 프레임: `requestAnimationFrame`, 시간 기준 갱신(dt, 최대 50ms로 자름 — 탭 전환 후 순간이동 방지).

## 조작 UI (터치 버튼 크기 ≥ 44px, 제스처, 키 매핑)

### 터치 / 마우스 — 필드
- **누른 곳으로 걸어가기**: 필드(및 `.stage` 전체) 위에서 손가락을 누르고 있으면 콩이가 **손가락의 x 위치를 목표로 design.md 최고 속도로 걸어감**(순간이동 금지 — 공정성). 끌면 목표 x가 따라 움직임. 손을 떼면 그 자리에서 멈춤(감속은 design.md). 세로 위치는 무관 — 손가락을 콩이보다 위쪽 아무 데나 두어도 됨(손가락이 콩이를 가리지 않게. 시작 안내 문구에 "위쪽을 눌러도 돼요" 포함 가능).
- 목표 표시 ▲(위 "터치 목표 표시"). 멀티터치: **마지막에 닿은 손가락**이 목표.
- 마우스: 누른 채(버튼 down) 같은 동작. 마우스를 누르지 않고 움직이는 것만으로는 이동하지 않음(PC는 키보드가 기본).
- 첫 판 안내: 시작 직후 2초, 필드 땅 띠 위 좌우 끝 안쪽 1u에 ‹ ›(1.5px `--muted` α .35, 높이 .5u) — "좌우로 움직여요" 의미. 2초 뒤 400ms에 사라짐. 두 번째 판부터 안 보임(localStorage).

### 터치 패드 (폰 레이아웃 `body.has-pad`)
- `<button class="pad" id="padL" aria-label="왼쪽으로">`, `padR` "오른쪽으로". 바탕 `--panel`, 1px `--grid`, radius 22, 가운데 셰브론 SVG(`M15 6 L9 12 L15 18`, 2.5px round, `--muted`, 36px). 누르는 동안 이동(`pointerdown`→ 시작, `pointerup`/`pointercancel`/`pointerleave` → 멈춤, `setPointerCapture`). 양쪽 동시 누르면 정지.
- 크기는 레이아웃 표대로(최소 96×96, 44px 기준 훨씬 넘음). 패드와 필드 터치는 공존(필드를 눌러도 됨).
- 눌림 피드백: 바탕 `--grid` + scale .96(80ms). 진동 API 없음.

### 키보드 (PC)
| 키 | 동작 |
|---|---|
| ← / A | 왼쪽 이동(누르는 동안) |
| → / D | 오른쪽 이동(누르는 동안) |
| 둘 다 누름 | **나중에 누른 쪽** 우선 (빠른 방향 전환) |
| Space / P | 일시정지 / 계속 |
| M | 음소거 토글 |
| Enter | 시작하기 / 다시 하기(결과 600ms 뒤) / 계속하기 |
| Esc | 일시정지 |
- 키 반복(`e.repeat`) 무시, keydown/keyup 상태로만 이동. 창 `blur` 시 모든 키 해제 + 일시정지.

### iPad Safari 필수
- `.stage`, 패드, 캔버스: `touch-action: none`(끌기 중 스크롤·확대 방지). 페이지 전체 `touch-action: manipulation`, `-webkit-user-select:none; user-select:none; -webkit-touch-callout:none; -webkit-tap-highlight-color:transparent`.
- 더블탭 확대 방지: 위 `touch-action` + 필드 `pointerdown`에서 `preventDefault()`. `gesturestart` `preventDefault()`.
- 가로 스크롤 금지(`overflow:hidden`, 수치표 검증). 안전 영역은 body 패딩으로.
- 이벤트는 Pointer Events로 통일(`pointerdown/move/up/cancel`), `{passive:false}`.

## 접근성 (대비, 색 외 구분 수단)
- 똥 종류 구분: **크기(큰 똥 1.6배) + 기울기·흔들 선(흔들 똥)** 이 주 수단, 갈색 명도 차는 보조. 우산 아이템은 **둥근 후광 + 우산 모양 + 청록 계열**(갈색과 색상 자체가 다름).
- 낙하 위치는 예고 그림자 **크기·진하기** 두 가지로 순서를 알려 줌. 그림자는 다크에서도 α를 올려 보이게.
- 피격은 표정(`> <`) + 똥 모자 + 결과 화면 — 색 변화에 의존하지 않음. 목숨은 채움/빈 칸 모양 차.
- 숫자: `--ink` 대 `--panel` 15:1 이상. 신기록 `--accent`는 "새 기록!" 글자 배지와 함께(색만으로 알리지 않음).
- 버튼은 모두 `<button>` + `aria-label`, 포커스 링 `outline: 3px solid var(--accent); outline-offset: 2px`. 오버레이 열리면 주 버튼에 포커스.
- `aria-live="polite"` 영역(시각적으로 숨김): 게임 오버 시 1회 "맞았어요. 버틴 시간 12.3초. 최고 45.6초." / 신기록이면 "새 기록!" 추가. 진행 중 시간은 읽지 않음(소음 방지).
- 캔버스 `role="img" aria-label="똥비 피하기 게임 화면"`.
- 깜빡임 없음(광과민 기준 충족: 초당 3회 이상 밝기 변화 요소 없음).
