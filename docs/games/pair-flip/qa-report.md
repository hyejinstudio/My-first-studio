### 버그 (심각도: 치명/높음/보통/낮음)
- [낮음] **뒤집힘 중 멈춤 → 계속 → 0.3초 잠금 중 다시 멈추면 문구가 "시계가 멈췄어요."로 바뀜.** 실제로는 시계가 아직 시작 전이다(시계 0, 계속하면 덮인 채로 0부터 시작 — 동작은 정상, 문구만 틀림).
  - 재현: 시작 → 미리보기 끝 뒤집힘(0.3초) 중 P → Enter → 0.3초 안에 P → 일시정지 화면 문구 확인.
  - 기대: "시계는 아직 시작 전이에요. 계속하면 카드가 덮인 채로 시작해요." (`G.needStart`가 참이면 이 문구)
  - 관련 코드: `lab/games/pair-flip/index.html` 1296행 `pause()`의 잠금 중 다시 멈춤 분기(`$('pauseMsg').textContent = '시계가 멈췄어요.'` 고정).
- 참고(버그 아님): 뒤집힘 중 멈춘 뒤 계속하면 0.3초 잠금 동안 위쪽 안내가 "외우세요 … 1"로 남아 있다(카드는 모두 뒷면, 시계 0.0). 0.3초뿐이고 게임에 영향 없음.

### 실기기 확인 필요
- iPad Safari: Ⅱ → 계속하기를 빠르게 번갈아 눌러도 앞면이 더 오래 보이지 않는지(체감), 일시정지 화면 새 문구 줄바꿈.
- 1차 항목 그대로: 3D 뒤집기 비침, 오버레이 가림, 실제 소리, 실제 멀티 터치, 앱 전환 자동 일시정지, 사람 체감 난이도.

- 키보드: 방향키로 포커스 이동, Space/Enter로 뒤집기, 가장자리에서 멈춤 확인.

개발자가 명세와 다르게 한 점(판단)
- `.flip` transform 안에 perspective를 넣음, will-change를 `.board.wc`에 둠: 타당함(조상에 perspective를 두지 않아 전체 화면 오버레이 position:fixed가 보호됨). 화면 문제 없음.
- 폰 세로 회전 안내 위치(판 아래 알약 + 시작 화면 한 줄): 타당함, 겹침 없음.
- `?seed=N`은 시작 화면에 "테스트 판" 알약을 보여 주고 시작 버튼을 누르면 시작: 타당함(시드 42 적용과 저장 안 함 확인).
- 음악 토글을 시작·일시정지 화면에 둠: 타당함.
- 결과 요약 줄이 통계 3칸과 같은 내용: 숫자는 정확함. 중복이라 줄여도 되지만 기획서 줄 1을 그대로 따른 것이라 허용.
- 점수 `max(0, 60000 − cs)`: 실험실에서는 쓰지 않음. 10분 이상은 eligible false라 문제 없음.
- 마지막 짝 직후 `phase='result'`(오버레이는 0.75초 뒤): 타당함. 이 0.75초 동안 일시정지·키 입력이 막혀 기록이 흔들리지 않음.

### 버그
- [높음] **일시정지 → 계속을 반복하면 미리보기(외우는 시간)를 원하는 만큼 늘릴 수 있음.**
  - 증상: 미리보기 중에 계속을 누르면 덮개가 바로 사라져 카드 24장 앞면이 보이지만, 0.3초 입력 잠금이 끝날 때까지 미리보기 시간이 줄지 않는다. 한 번 할 때마다 앞면을 약 0.3초 더 볼 수 있다. 일시정지 횟수 제한은 없다.
  - 측정: 일시정지 1번 → 앞면을 본 시간 6.35초. P / Enter를 20번 반복 → **9.37초**(기획: 6.0초 고정, "연장 불가"). 더 반복하면 계속 늘어난다.
  - 재현: 시작 → 미리보기 중에 P(또는 Ⅱ)를 누르고 Enter(또는 계속하기)를 누르고, 0.3초 안에 다시 P를 누른다. 이걸 반복한다. iPad에서도 Ⅱ 버튼 → 계속하기 버튼 연타로 같다.
  - 기대: 앞면이 보이는 시간은 합계 6.0초(+ 뒤집힘 0.3초)를 넘지 않아야 한다. 방법 예: 미리보기에서 계속할 때는 덮개를 잠금이 끝날 때 벗기기, 또는 덮개를 벗기는 순간부터 미리보기 시간을 다시 줄이기.
  - 관련 코드: `lab/games/pair-flip/index.html` `resume()`(1311행: `board.classList.remove('covered')`를 바로 함) / `unlockAfterResume()`(1324행: 300ms 뒤에야 `schedulePreview(G.previewLeft)`).
- [보통] **미리보기 중 일시정지 화면의 문구가 사실과 다름.** 미리보기 중에도 "시계가 멈췄어요. 열려 있던 카드는 덮었어요."가 나온다. 실제로는 시계가 아직 시작하지 않았고, 카드는 덮은 것이 아니라 가린 것이며 계속하면 다시 앞면으로 보인다. 재현: 시작 → 미리보기 중 P. 기대: 미리보기 중에는 예) "외우는 시간이 멈췄어요. 남은 시간은 그대로예요." 관련 코드: 458행 `#ovPause p`(문구가 고정).
- [낮음] 틀린 두 장을 보고 있는 동안(대기 중) 일시정지하면 두 장이 바로 덮이고 대기가 끝난다. 그런데 결과 화면은 틀림마다 "0.8초를 기다렸어요 (모두 X초). 이 시간은 이미 위 시간에 들어 있어요."라고 한다. 그 판에서는 실제로 기다린 시간이 이보다 짧다. 드문 경우라 낮음. 재현: 틀린 직후 0.95초 안에 P → 계속 → 클리어 → "모두" 값이 틀림 × 0.8과 같음. 관련 코드: 1252행.
- [낮음] 계속을 누른 뒤 0.3초 잠금 동안 P/Esc 키는 다시 멈추지 않는다(`resume()`이 아무것도 하지 않고 끝남). Ⅱ 버튼은 다시 멈춘다. 키와 버튼의 동작이 다르다. 관련 코드: 1423행(phase가 `paused`이면 `resume()`만 부름).

### 난이도 의견 (근거 있는 추정, 사람 체감은 미검증)
- 6초에 24장이면 카드 한 장당 0.25초다. 보통 사람은 미리보기 뒤에 확실한 짝을 3~5쌍쯤 기억할 것이다. 나머지 7~9쌍은 탐색해야 하므로 틀림이 여러 번 생기고, 기획서가 잡은 45~90초 범위에 맞는다. "너무 쉽지 않게"에 맞다고 본다.
- 같은 색 닮은 그림 가족 6개는 "색만 보고 대충 외우기"를 막는다(색 기억이 반만 맞음). 흑백·색각 이상에서도 모양으로 구분되므로 공정성은 지킨다.
- 붙은 짝 ≤ 1쌍 규칙으로 아주 쉬운 판이 줄었다. 0쌍인 판도 35%라 "옆 칸은 아니다"라는 단서도 생기지 않는다.
- 쉬운 쪽 위험: 틀릴 때 손해가 0.8초 대기뿐이고 예약 탭이 있어 연타 손해가 작다. 사람이 해 보고 연타가 잘 통하면 기획서대로 대기를 1.0초로 늘리는 것이 첫 조정이다.
- 단, 버그 1이 남아 있으면 미리보기를 무한히 늘릴 수 있어 난이도 설계가 무너진다. 반드시 먼저 고쳐야 한다.

### 실기기 확인 필요
- iPad Safari(WebKit): 카드 3D 뒤집기(`preserve-3d`, `backface-visibility`)에서 뒷면으로 앞면이 비치지 않는지, 전체 화면 오버레이가 판을 완전히 가리는지, 홈 화면 앱 모드 safe-area.
- 실제 소리: 뒤집기·짝 맞음(콤보 상승)·틀림·클리어·새 기록, 배경음악 켜기/끄기, 무음 스위치.
- 실제 손가락 멀티 터치·빠른 연타(에뮬레이션에서는 통과), 탭 전환과 앱 전환 때 자동 일시정지.
- 사람 체감: 처음 한 판 시간·틀림 수, "너무 쉬움/어려움".
