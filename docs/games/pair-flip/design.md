# 짝꿍 카드 기획서
- slug: pair-flip
- 한 줄 소개: 처음 6초 동안 모든 카드를 외운 뒤, 같은 그림 두 장을 찾아 판을 비우는 속도 기억 게임. 빨리 비울수록 기록이 좋다.
- 배포: 실험실 `lab/games/pair-flip/` (순위표 없음, 로컬 최고 기록만). 나중 출시를 위한 정수 점수 정의는 아래 "순위표 점수(출시 대비)".
- 장르: 짝 맞추기 기억 게임(장르 규칙만 빌림). 스튜디오 기존 게임(블록 스택, 두더지, 리듬, 뱀, 숫자 10 퍼즐, 눈싸움, 똥비, 불곰 세기, 경영)과 겹치지 않는다. 특정 상용 게임의 이름·캐릭터·카드 그림을 쓰지 않은 오리지널이다.
- 상태: 기획 v1

## 핵심 루프
1. **시작** — "시작" 버튼.
2. **미리보기 (6.0초)** — 카드 24장이 모두 앞면으로 보인다. 남은 시간 막대가 줄어든다. 이때 탭은 무시. **시계는 아직 안 돈다.**
3. **뒤집힘** — 24장이 동시에 뒷면으로 뒤집힌다(0.3초). 다 뒤집힌 순간 시계 시작 + 입력 허용.
4. **짝 찾기** — 카드 1장을 탭 → 앞면. 두 번째 카드를 탭 →
   - 같은 그림: 두 장이 잠깐 반짝이고 사라진다(자리는 빈칸으로 남음, 다른 카드는 움직이지 않음). 바로 다음 카드를 탭할 수 있다.
   - 다른 그림: 두 장이 **0.8초 동안** 보인 뒤 다시 뒷면으로. 그동안 새 카드는 열리지 않는다(아래 "입력 처리").
5. **클리어** — 12쌍을 모두 없애는 순간 시계 정지 → 결과 화면(걸린 시간, 틀린 횟수, 정확도, 최고 기록).

한 판 길이 목표: 처음 하는 사람 **45~90초**, 익숙하면 **25~40초**. 미리보기·결과 포함 약 1~2분.

## 규칙 (승리/패배, 점수)
| 항목 | 규칙 |
|---|---|
| 목표 | 24장(12쌍)을 모두 없앤다. 패배·제한 시간 없음(아래 10분 예외) |
| 짝 | 그림 종류(kind)가 **완전히 같은** 두 장. 같은 가족의 닮은 그림(아래 "카드 그림")은 짝이 아니다 |
| 기록 | **걸린 시간** = 뒤집힘이 끝난 순간(입력 허용 순간) ~ 마지막 짝의 두 번째 카드를 탭한 순간. 짧을수록 좋다 |
| 시간 단위 | 내부는 `performance.now()` ms. **기록 = 0.01초 단위로 내림**(정수 센티초 cs = floor(ms / 10)). 결과 화면은 `38.47초`, 플레이 중 HUD는 0.1초 단위(`38.4`, 내림) |
| 틀린 횟수 | 두 장을 열었는데 짝이 아니었던 횟수 |
| 시도 수 | 두 장을 연 횟수 = 12 + 틀린 횟수 |
| 정확도 | 12 ÷ 시도 수 × 100, **반올림 정수 %**. 한 번도 안 틀리면 100% |
| 시간 벌점 | **없음** (숫자로 더하는 벌점 없음). 대신 틀리면 0.8초 동안 다음 카드를 열 수 없어 그만큼 시계가 흘러간다(아래 근거) |
| 최고 기록 | localStorage `pair-flip-best` = 정수 센티초(작을수록 좋음). 없거나 읽기 실패면 "기록 없음". 클리어 시 이번 cs < 저장값(또는 저장값 없음)이면 갱신 + "새 기록!" |
| 10분 초과 | 걸린 시간이 600.00초 이상이면 클리어는 인정하되 최고 기록 저장 안 함, 결과 화면 시간은 "10분 넘음"으로 표시(출시 점수 정의와 맞추기 위함). 일시정지 시간은 포함하지 않는다 |

### 틀렸을 때 벌점을 따로 주지 않는 이유
- 기억 게임에서 처음 보는 카드를 열어 보는 것은 필요한 탐색이다. 틀릴 때마다 +초를 더하면 "어쩔 수 없는 탐색"까지 벌을 받고, 화면 시계와 기록이 달라져 결과 설명이 복잡해진다(사용자는 설명 정확성을 중시).
- 대신 **틀린 두 장을 0.8초 동안 보여 주고 그동안 새 카드를 못 열게** 한다. 이 0.8초는 (1) 두 번째 카드를 외울 시간이고 (2) 그대로 시계에 쌓이는 비용이다. 결과: 틀린 한 번 ≈ 0.8초 손해 + 다시 두 장을 여는 시간(약 0.5~1초) ≈ **약 1.5초 손해**.
- 막 뒤집기(연타) 검토: 무작정 연타하면 틀린 횟수가 크게 늘고(미리보기를 활용한 사람보다 보통 8~15번 더 틀림 → 12~20초 손해), 기억을 잘 쓰는 쪽이 항상 빠르다. 시계가 멈추지 않으므로 숨은 이득이 없다.
- 단순한 규칙 한 줄로 설명된다: "틀리면 잠깐 기다려야 해요. 시계는 계속 가요."
- 튜닝: QA·체감에서 연타가 너무 잘 통하면 첫 조정은 대기 시간 0.8 → 1.0초(벌점 숫자 도입은 하지 않음).

## 입력 처리 (경합 정리)
| 상황 | 처리 |
|---|---|
| 미리보기·뒤집힘(0.3초) 중 탭/키 | 무시(표시 없음) |
| 이미 열려 있는 첫 번째 카드를 다시 탭 | 무시(다시 덮지 않음) |
| 이미 사라진 자리(빈칸) 탭 | 무시 |
| 두 번째 카드 탭 → **짝 맞음** | 판정 즉시. 두 장은 0.35초 사라짐 연출(입력 막지 않음). 연출 중에도 다른 카드 탭 가능. 사라지는 두 장 자체 탭은 무시 |
| 두 번째 카드 탭 → **짝 아님** | "대기" 0.8초(두 번째 카드가 앞면으로 다 돈 뒤부터 셈 — 뒤집기 0.15초 + 보기 0.8초 = 탭 후 0.95초) → 두 장 동시에 뒷면으로 |
| 대기 중 세 번째 탭 (뒷면 카드) | **하나만 예약**: 대기가 끝나는 순간(두 장이 덮이기 시작할 때) 그 카드가 새 첫 번째 카드로 열린다. 두 번째 예약 탭은 무시. 대기 중인 두 장을 탭하면 무시(예약 안 함) |
| 대기 중 예약한 카드가 대기 중인 두 장 중 하나와 같은 위치 | 생길 수 없음(위에서 무시) |
| 동시 터치(멀티 포인터) | 첫 번째 포인터만, 그 포인터가 떨어질 때까지 다른 포인터 무시 |
| 반응 시점 | `pointerdown`(누르는 순간)에 판정. 손을 떼지 않아도 된다. 같은 포인터로 끌어서 다른 카드에 가도 추가 판정 없음 |
| `pointercancel` | 이미 처리된 탭은 그대로(취소 없음) |
- 판정 순서는 입력이 도착한 순서. 한 프레임에 두 입력이 와도 순서대로 처리하고, "열린 카드 2장 + 대기"를 넘는 상태가 되지 않는다(어느 순간에도 **짝 판정 전 앞면 카드 ≤ 2장**, 사라지는 연출 중인 카드는 제외).
- 마지막 짝: 두 번째 카드 탭 순간 시계 정지 → 사라짐 연출 0.35초 + 0.4초 뒤 결과 화면. 결과 화면이 뜬 뒤 0.7초 동안 버튼 입력 무시(연타 오입력 방지).

## 판
- **항상 가로 6열 × 4행 = 24칸** (모든 화면 방향에서 같은 배치, 회전 안 함). 이유: 판 도중 화면을 돌려도 카드 위치가 바뀌지 않아야 기억이 유지된다. 세로 화면에서는 카드가 작아질 뿐 배치는 같다.
- 카드 크기 = min(사용 가능 폭 / 6, 사용 가능 높이 / 4) − 간격. 카드 비율·모양은 art-ui.md.
  | 환경 | 카드 한 변(대략) |
  |---|---|
  | iPad 10.2" 가로 | 약 140pt |
  | iPad mini 가로 | 약 125pt |
  | iPad 세로 (810pt) | 약 120pt |
  | iPad mini 세로 (744pt) | 약 110pt |
- 화면 회전·크기 변경 시 크기만 다시 계산, 카드 위치·상태·시계는 그대로.
- 짝이 사라진 자리는 빈칸으로 남는다(카드 모양 자리 표시 정도의 아주 옅은 흔적, art-ui.md). 다른 카드는 절대 움직이지 않는다.

## 카드 그림 (12종 = 6가족 × 2)
닮은 그림을 섞어 기억을 어렵게 하되, **카드를 앞면으로 보고 있으면 누구나 한눈에 구분할 수 있게**(공정성) 만든다.

| 가족 | 색(가족 공통, 값은 art-ui.md) | 그림 a | 그림 b | 다른 점 |
|---|---|---|---|---|
| 1 동그라미 | 색 1 | 꽉 찬 원 | 고리(가운데 구멍, 구멍 지름 ≥ 원의 45%) | 채움 vs 속 빔 |
| 2 세모 | 색 2 | 위로 뾰족한 세모 | 아래로 뾰족한 세모 | 방향 180° |
| 3 네모 | 색 3 | 바로 선 정사각형 | 45° 돌린 마름모 | 회전 45° (외곽선 모양이 다름) |
| 4 달 | 색 4 | 초승달(왼쪽이 열림) | 반달(직선 면이 있음) | 모양 자체 다름 |
| 5 잎 | 색 5 | 잎 1장 | 잎 2장(같은 잎 V자) | 개수 1 vs 2 |
| 6 물결 | 색 6 | 물결선 1줄 | 물결선 2줄 | 개수 1 vs 2 |

- **같은 가족 두 그림은 같은 색**이다(그래서 헷갈린다). 가족끼리는 색 **과** 모양이 모두 다르다 → 색을 구분하기 어려운 사람도 모양만으로 12종을 구분할 수 있다(색은 보조 단서).
- 구분 조건(QA 확인): 카드 크기 110pt에서 그림 크기는 카드의 55~65%, 선 두께 ≥ 그림 크기의 12%. 같은 가족의 a·b 차이는 위 표의 한 가지 큰 차이(채움/방향/회전/개수)이고, 작은 장식·선 두께·크기 차이로만 구분되는 그림은 금지.
- 정확한 그림·색 값·뒷면 무늬는 art-ui.md. 뒷면은 24장 모두 **완전히 같다**(뒷면에 단서 없음).
- 그림 이름(해설·접근성 라벨용): 동그라미 / 고리 / 위 세모 / 아래 세모 / 네모 / 마름모 / 초승달 / 반달 / 잎 하나 / 잎 둘 / 물결 하나 / 물결 둘. kind 번호 0~11은 이 순서.

## 배치 생성 (시드)
- RNG: `mulberry32(seed)` 하나. 배치 생성에 `Math.random` 사용 금지(같은 시드 = 같은 배치).
- 일반 플레이 시드: `(Date.now() ^ Math.floor(Math.random() * 2**32)) >>> 0` (시드 결정에만 Math.random). 화면에 표시 안 함. 테스트 URL `?seed=N` 으로 지정 가능(아래 "테스트 판").
- 생성:
  1. 덱 = kind 0~11을 각 2장 → 24장.
  2. Fisher–Yates 섞기(RNG 사용). 칸 번호 i = 행 × 6 + 열 (행 0~3 위→아래, 열 0~5 왼→오른).
  3. **검사**: 같은 kind 두 장이 상하좌우로 붙어 있는 쌍이 **2쌍 이상이면** 2로 돌아가 다시 섞는다(같은 RNG 계속). 최대 200회, 넘으면 마지막 결과 사용 + 콘솔 경고(QA에서 0회여야 함; 무작위 섞기에서 조건 통과 확률 약 50%라 사실상 발생 안 함).
  - 이유: 붙은 짝이 3~4쌍 나오는 "운 좋은 판"을 줄여 판마다 난이도 차이를 좁힌다(시간 기록 비교의 공정성). 0쌍 강제는 하지 않는다(그러면 "옆 칸은 절대 아니다"라는 단서가 생김).
- 산출물: `layout[24]` = kind 번호.

### 난이도 결정: 단일 판 1개
- **판 1개(24장)만** 한다. 여러 판 이어 하기(총 시간)는 하지 않는다.
- 근거: (1) "짧고 굵게, 1~2분"에 판 하나가 정확히 맞는다 — 12쌍 + 미리보기 6초에 보통 45~90초. (2) 단계제로 하면 1~2단계(4~8쌍)는 사실상 기억 없이 풀리는 쉬운 구간이 되어 "너무 쉬움"이 된다. (3) 순위 비교가 "같은 조건 한 판 시간"으로 단순해 설명이 정확해진다. (4) 어려움은 판 크기 대신 **짧은 미리보기 + 닮은 그림 가족**으로 만든다.
- 시간 추정: 기억을 잘 써서 틀림 4~6번 → 약 25~35초. 처음 하는 사람(미리보기에서 3~4쌍만 기억) 틀림 12~18번 → 약 50~80초. 무작정 연타 → 틀림 20~30번 → 70~100초.
- 튜닝 순서(체감이 너무 쉬우면): 미리보기 6 → 5초, 그다음 판 6×5 = 30장(15쌍, 가족 하나를 3종으로)은 이번에 하지 않음. 너무 어려우면 미리보기 6 → 7초.

### 결과 화면 (정확하고 친절하게)
- 제목: "다 찾았어요!" / 새 기록이면 "새 기록!" 강조.
- 큰 숫자: **걸린 시간** `38.47초` (10분 이상이면 "10분 넘음").
- 줄 1: `12쌍을 17번 만에 찾았어요 · 틀림 5번 · 정확도 71%`
- 줄 2: `최고 기록 32.18초` (이번이 새 기록이면 "이전 기록 40.02초 → 38.47초").
- 줄 3 (안내, 틀림 ≥ 1일 때만): `틀릴 때마다 0.8초를 기다렸어요 (모두 4.0초).` — 기다린 시간 = 틀림 × 0.8초를 그대로 계산. 시계에 이미 들어 있는 시간이라는 점이 문구로 분명해야 한다(더해진 벌점이 아님).
- 버튼: "다시 하기". (10분 초과면 줄 2 위에 "10분이 넘으면 최고 기록에 남지 않아요.")
- 모든 숫자는 같은 기록 객체 하나에서 계산(시도 수 = 12 + 틀림, 정확도 = round(12/시도×100)).

## 공정성·부정 방지 (최소한)
- **미리보기 중 탭 무시**, 미리보기 길이 고정(건너뛰기·연장 없음), 시계는 뒤집힘 끝에 시작.
- **일시정지**: Ⅱ / P / Esc, 탭 숨김(`visibilitychange` hidden)이면 자동.
  - 판 전체를 불투명 덮개로 가림(카드 앞뒷면 모두 안 보임). 시계 정지.
  - 플레이 중 일시정지하면 **열려 있던 카드(첫 번째 1장, 또는 대기 중 2장)를 바로 뒷면으로 덮고 예약 탭은 버린다.** 사라지는 연출 중인 짝은 그대로 사라짐 처리. → 카드를 연 채로 멈춰 놓고 생각하는 이득 없음.
  - 미리보기 중 일시정지: 남은 미리보기 시간을 그대로 멈췄다가 이어서(늘어나지 않음). 덮개가 가리므로 멈춘 동안 볼 수 없다.
  - "계속"을 누르면 0.3초 뒤 입력 허용(덮개 사라지는 동안 오탭 방지). 시계는 입력 허용 순간 다시 흐른다.
  - 일시정지 횟수 제한 없음. 결과 화면에는 표시하지 않는다(출시 시 순위 자격 여부는 "결정 필요").
- 뒷면은 모두 같고, 커서·포커스·hover 효과가 앞면 정보를 드러내지 않는다(예: 카드별 다른 접근성 라벨이 뒷면 상태에서 그림 이름을 말하면 안 됨 — 뒷면 라벨은 "카드 3행 2열, 뒷면").
- 그림 이름은 앞면일 때만 DOM/라벨에 노출. 뒷면 카드 요소에 kind 정보를 class·data 속성으로 넣지 않는다(개발자 도구로 쉽게 보이지 않게 — 최소한의 예의 수준, 완전 방지는 아님).
- 테스트 판(`?seed=`, 테스트 훅 사용)은 최고 기록을 저장하지 않는다(결과 화면 작게 "테스트 판").

## 순위표 점수 (출시 대비 — 실험실에서는 쓰지 않음)
순위표 서버는 "점수 높을수록 위"만 지원하므로 시간을 뒤집은 정수로 보낸다.

- **점수 = 60000 − cs** (cs = 걸린 시간 센티초, 0.01초 내림). 예: 38.47초 → 60000 − 3847 = **56153**.
  - 600.00초(10분) 이상은 점수 ≤ 0 → 보내지 않음(`eligible: false`, reason `'slow'`). 그래서 실험실 단계부터 10분 이상은 최고 기록에서도 제외해 둔다.
  - 시간이 짧을수록 점수가 커서 서버 정렬 그대로 쓸 수 있다. 같은 cs는 같은 점수(동점 처리는 서버 기존 규칙).
- **score_cap 제안: 59500** (= 5.00초보다 빠른 기록 거부). 근거: 24번 탭 + 짝 판정 연출 사이 사람 손 한계를 감안해도 5초 미만은 사실상 불가능. 실제 측정한 최고 기록이 10초 근처면 cap을 59000(10초)으로 좁히는 것도 가능.
- **표시 문제**: 순위표에 56153이 그대로 보이면 혼란스럽다. 현재 `lib/leaderboard.js` CONFIG에는 게임별 `show`/`say` 변환 함수가 이미 있다(개구리 텐이 사용 중). 출시 때 예:
  - `{ id: 'pair-flip', name: '짝꿍 카드', short: '짝꿍', unit: '초', cap: 59500, seed: true, best: <pair-flip-best cs를 60000−cs로 바꾼 값, 기록 없으면 0>, show: s → ((60000 − s) / 100).toFixed(2) + '초', say: s → '…초' }`
  - 출시 시 확인할 것: 순위표·결과 칩·내 기록 등 **점수가 보이는 모든 곳이 `show`/`say`를 거치는지**(원점수 노출 0곳), 제목 옆 단위 표시 "(초)"가 "작을수록 좋음"으로 오해 없이 읽히는지, 로컬 최고 기록(`best`)도 변환해서 넘기는지.
- 게임 쪽 호출(출시 때): `Leaderboard.report({ game: 'pair-flip', score: 60000 - cs, eligible, reason, slot })`. 테스트 판은 `eligible: false, reason: 'test'`.

## 테스트 훅 (QA 전용, 화면 표시 없음)
`window.__pair` — 읽기 함수는 깊은 복사본을 반환(수정해도 게임 영향 없음).
| 멤버 | 설명 |
|---|---|
| `generate(seed)` | `{ layout: [24], reshuffles }` 순수 계산. 게임 상태 안 바꿈 |
| `seed()` | 현재 판 시드 |
| `layout()` | 현재 판 kind 배열(사라진 칸은 −1) |
| `state()` | `{ phase: 'title'|'preview'|'flipdown'|'play'|'wait'|'paused'|'result', open: [칸 번호], queued: 칸 번호|null, pairsLeft, misses, tries, elapsedMs, previewLeftMs }` |
| `newGame(seed)` | 지정 시드로 새 판(미리보기부터). 테스트 판으로 표시, 최고 기록 저장 안 함 |
| `skipPreview()` | 미리보기·뒤집힘을 즉시 끝내고 play 상태(시계 0에서 시작) |
| `tap(i)` | 칸 i를 실제 입력과 **같은 처리 경로**로 탭 |
| `result()` | 마지막 결과 `{ cs, ms, misses, tries, accuracy, startAt, endAt, pausedMs }` (startAt/endAt은 performance.now 값) |
- URL `?seed=N` = `newGame(N)`과 같은 테스트 판.

## QA 검증 항목
**배치 (자동, 시드 1~10000)**
1. `layout`에 kind 0~11이 **정확히 2장씩**(24장, 빠진 짝·남는 카드 없음).
2. 같은 시드 두 번 → 같은 layout. 다른 시드 10000개 중 동일 layout 0개(참고: 중복이 나오면 보고).
3. 붙은 같은 짝(상하좌우) ≤ 1쌍 100%. reshuffles 평균·최대 보고, 200회 초과(fallback) 0회.
4. 분포: 각 kind가 각 칸에 나오는 비율이 1/12 ± 1.5%p(치우침 없음).

**규칙·입력 (Chromium, PC·iPad 세로/가로)**
5. 미리보기 6.0초(±50ms) 동안 24장 앞면, 탭·키 무시, 시계 0. 뒤집힘 끝 순간 시계 시작.
6. 짝 맞음 → 두 장 사라지고 자리 유지, 다른 카드 위치 불변. 연출 중 다른 카드 즉시 열림.
7. 짝 아님 → 탭 후 0.95초(±50ms)까지 두 장 앞면, 그 뒤 덮임. 대기 중 탭 1개 예약 → 덮이는 순간 그 카드 열림. 2번째 예약 무시. 대기 중인 두 장 탭 무시.
8. 어느 순간에도 짝 판정 전 앞면 카드 ≤ 2장(빠른 연타·멀티 터치·한 프레임 다중 `tap()`으로 검사).
9. 열린 첫 카드 재탭·빈칸 탭 무시, 멀티 포인터는 첫 포인터만.
10. 닮은 그림(같은 가족 a·b)은 짝으로 판정되지 않음 — 6가족 모두.
11. 완벽 풀이(layout을 보고 `tap()`으로 12쌍 연속) → misses 0, tries 12, 정확도 100%. 일부러 틀리기 n번 → misses n, tries 12+n, 정확도 = round(12/(12+n)×100).

**시간**
12. `result().ms` = endAt − startAt − pausedMs, cs = floor(ms/10). 결과 화면 숫자 = cs/100 소수 둘째 자리(내림 표시, 반올림 아님).
13. 시간 정확도: 스크립트로 알려진 간격(예: 쌍마다 500ms)으로 `tap()` → 측정 ms와 스크립트 경과 시간 차이 ±30ms 안. HUD 0.1초 표시는 내림.
14. 시계 정지 시점 = 마지막 두 번째 카드 탭 순간(사라짐 연출·결과 지연 0.75초가 기록에 안 들어감).
15. 일시정지(버튼·P·Esc·`visibilitychange`) → 시계 정지, 덮개가 판 전체 가림, 열린 카드 덮임·예약 버림. 계속 후 0.3초 입력 잠금. 미리보기 중 일시정지 → 남은 미리보기 시간 보존(합계 6.0초 유지). pausedMs가 기록에서 빠짐.
16. 최고 기록: 첫 클리어 저장, 더 빠르면 갱신 + "새 기록!", 느리면 유지. 600.00초 이상·테스트 판은 저장 안 함. localStorage 막힘(예외)에도 게임 정상.
17. 결과 화면 문구: 시도 수·틀림·정확도·"기다린 시간 = 틀림 × 0.8초"가 `result()`와 일치. 결과 뒤 0.7초 입력 무시.

**공정성·표시**
18. 뒷면 24장 픽셀 동일, 뒷면 카드 DOM에 kind 정보(class·data·라벨) 없음.
19. 110pt 카드에서 같은 가족 a·b가 한눈에 구분되는지 스크린샷 첨부(사람 확인, 미검증이면 명시). 흑백(채도 0) 스크린샷에서도 12종 구분 가능.

21. 사람 체감(수동, 미검증이면 명시): 처음 한 판 시간과 틀림 수, "너무 쉬움/어려움" 판단.
