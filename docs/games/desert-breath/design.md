# 선인장 키우기 기획서
- slug: desert-breath (기획 가제 「사막 숨쉬기」. 화면·카드·제목은 모두 **「선인장 키우기」**)
- 한 줄 소개: 비 올 때만 숨구멍을 열어 쑥쑥 — 1초만 더 욕심내면 모래가 박힌다. 누르고 있는 동안만 선인장이 펴지는 150초짜리 욕심 타이밍 게임.
- 출발점: `docs/proposals/desert-breath.md`(2026-11-27 혜진님 승인). 이 문서는 그 기획안을 개발 가능한 명세로 확정한 것이다. 기획안과 달라진 점은 맨 아래 "기획안 대비 변경점"에 모았다.
- 스튜디오 기존 게임과 겹침: 박자 앵무새(정답 리듬 따라 탭)·똥비 피하기(움직여 피하기)와 다르다. 이 게임은 **제자리에서 "얼마나 오래 열어 둘까"라는 손익을 고르는** 원버튼 누르고-버티기 게임이다. 사이트에 같은 동사의 게임이 없다.

---

## 핵심 루프
1. 화면 위쪽 **날씨 띠**에서 날씨 조각(비·한낮 해·모래바람·맑음)이 오른쪽→왼쪽으로 흘러와 선인장 바로 위 "지금" 선에 닿는다. **모든 날씨는 정확히 3초 전에 띠 오른쪽 끝에 나타난다.**
2. 누르고 있는 동안 선인장이 펴진다(숨구멍 열림). 비를 맞으며 펴져 있으면 몸이 통통해지고, 통통함이 꽉 찬(90) 뒤 더 들어오는 물은 **키**가 된다.
3. 해·모래에 펴진 채 닿으면 "따끔" — 물이 확 빠진다. 닫혀 있어도 해·한낮·오후에는 계속 마른다.
4. 비는 **끝으로 갈수록 굵어지고**(흡수량 증가), 후반엔 비 바로 뒤에 모래가 붙어 온다 → "조금만 더" vs "지금 떼기".
5. 150초(새벽→해질녘)를 버티면 끝, 점수 = 키. 몸속 물이 0이 되면 말라서 끝(그때까지의 키가 점수).

## 규칙

### 1. 상태
| 상태 | 기호 | 범위 | 시작값 | 화면 표시 |
|---|---|---|---|---|
| 몸속 물 | W | 0 ~ 90 (90을 넘는 물은 즉시 키로 바뀌므로 90에서 멈춤) | **60** | 선인장 몸통 굵기(통통함)만. 숫자 없음. 몸통에 "90선" 은은한 띠 |
| 키 | H | 0 ~ | **100mm (10.0cm)** | 몸 높이 + 옆 눈금자 + 좌상단 "10.0 cm" |
| 열림 정도 | o | 0 ~ 1 | 0 | 펼친 연두+물구멍 점(열림) ↔ 웅크린 회녹색 주름(닫힘). 중간값은 보간 |
| 게임 시각 | t | 0 ~ 150.000초 | 0 | 해가 하늘을 가로지르는 위치 + 하늘색 변화 |

- 내부 단위: 시간은 **정수 ms**(시뮬 단계 5ms), 키는 **mm 실수**(점수는 내림 정수), 물은 실수.
- 물 → 키 환산: **물 20 = 키 1cm = 10mm** ⇒ 물 1 = 0.5mm.

### 2. 열기·닫기
| 항목 | 값 | 비고 |
|---|---|---|
| 누름 상태 | "누르고 있는 입력이 1개 이상" (손가락 여러 개·스페이스·마우스 합산) | 토글 없음. 손이 곧 상태 |
| 여는 값 | 입력 수가 **0 → 1**이 되는 순간 W **−2** (즉시) | 짧게 연타해서 이득 보기 방지. 닫히는 도중 다시 눌러도 또 −2 |
| 펴짐 속도 | o가 초당 1/0.15(≈6.667)씩 증가 → 0에서 1까지 **0.15초** | 선형 |
| 닫힘 속도 | o가 초당 1/0.10(=10)씩 감소 → 1에서 0까지 **0.10초** | 선형. 닫히는 동안은 아직 열린 셈 |
| 완전히 편 상태에서 뗀 뒤 o가 0.3 아래로 내려갈 때까지 | **0.07초** | "따끔" 피하려면 최소 이만큼 먼저 떼야 함 |
| 닫힌 상태에서 누른 뒤 o가 0.3에 닿을 때까지 | **0.045초** | |
| 말라서 열 수 없음? | 없음. W ≤ 2일 때 누르면 여는 값으로 W ≤ 0 → 마름(판 끝, 사유 "숨 들이쉴 물이 없었어요") | 규칙 일관성 우선 |

### 3. 물 변화율 (1초당)
한 순간의 물 변화율 = **(1 − o) × 닫힘값 + o × 열림값 + 시간대 추가 마름** (열림 정도로 선형 보간. 반쯤 열리면 반반).

| 날씨 | 모양(색만으로 구별하지 않음) | 닫힘값 | 열림값 | 닿는 순간(따끔) |
|---|---|---|---|---|
| 맑음 | 빈 하늘 | −2.5 | −4 | 없음 |
| 비 | 둥근 구름 + 세로 빗줄(뒤로 갈수록 굵어짐) | −2 | **+12 + 18 × p** (p = 그 비 조각 안에서 진행률 0→1. 처음 +12, 끝 +30, 평균 +21) | 없음 |
| 한낮 해 | 큰 원 + 빛살 | −4 | −30 | **−6** |
| 모래바람 | 가로 물결 줄무늬 + 낮은 먼지 | −2.5 | −90 | **−12** |

**시간대 추가 마름** (열림과 무관하게 항상 더함):
| 시간 | 추가 |
|---|---|
| 0 ~ 40초 (새벽·아침) | 0 |
| 40 ~ 110초 (한낮) | **−2.75/초** (봇 측정 후 조정, 원안 −3) |
| 110 ~ 150초 (오후) | **−(2 + 0.08 × (t − 110))/초** → 110초에 −2, 150초에 −5.2 (봇 측정 후 조정, 원안 0.05) |

- 성장: 매 단계 끝에 W > 90이면 `H += (W − 90) × 0.5mm; W = 90`.
- 성장은 위 변화율이 +일 때만 생긴다(비 + 열림). 닫힌 채로는 절대 자라지 않는다.

### 4. 따끔 (해·모래 벌점)
- 판정 대상 조각: **한낮 해, 모래바람**.
- 판정: 그 조각 안의 시뮬 단계 시작 시각 t(조각 시작 ≤ t < 조각 끝)에서 **o ≥ 0.3**이면 따끔. **조각 하나당 최대 1번.**
  - 조각 시작 순간 이미 o ≥ 0.3 → "늦게 뗌" 유형.
  - 조각 시작 순간엔 o < 0.3이었는데 조각 안에서 0.3을 넘음(해·모래 속에서 누름, 또는 조각 직전에 눌러 펴지는 중) → "속에서 엶" 유형.
- 따끔 효과: 즉시 −6(해) / −12(모래). 이후 그 조각에서 펴져 있는 동안은 위 열림값(−30 / −90)이 계속 적용된다(따끔은 1번이지만 벌어진 만큼 계속 손해).
- 화면: 모래알 박힘 점 + 짧은 흔들림 + 숫자 표시(아래 "늦게 뗌 표시").

### 5. "늦게 뗌" 표시 — 정확한 정의 (터치 지연 대책)
사용자가 억울하지 않게, **"몇 초 더 일찍 뗐으면 따끔을 피했는가"**를 실제 시뮬레이션 값으로 계산해 보여 준다. 근사·꾸밈 숫자 금지.

- 기준 시각 **t_seg** = 그 해/모래 조각이 "지금" 선에 닿은 시각(조각 시작 시각).
- **t\*** (피할 수 있었던 가장 늦은 뗌 시각) = 이번 누름(눌린 시각 t_down, 그때 o = o_down)을 그대로 두고, 손 뗌 시각만 바꿨을 때 `o(t_seg) < 0.3`이 되는 가장 늦은 뗌 시각.
  - o(t) 궤적: 누른 동안 `min(1, o_down + (t − t_down)/0.15)`, 뗀 뒤 `max(0, o_뗌 − (t − t_뗌)/0.10)`.
  - 완전히 펴진 상태라면 t\* = t_seg − 0.07초 (정확한 값). 펴지는 도중이면 위 궤적으로 이분법(5ms 해상도면 충분, 결과는 5ms 단위로 내림)으로 푼다.
- **t_up** = 실제로 손을 뗀 시각(아래 "입력 시각"과 같은 게임 시계, 입력 수가 1 → 0이 된 순간).
- **늦음 = t_up − t\*** (항상 > 0). 표시: 0.01초 단위 **올림**, "0.08초 늦게 뗌". 1.00초를 넘으면 "1초 넘게 늦게 뗌".
- 조각 시작 시 아직 누르고 있었으면: 따끔은 즉시 보여 주고, 숫자는 손을 떼는 순간 덧붙인다(조각이 끝난 뒤에 떼도 같은 공식).
- "속에서 엶" 유형: 숫자 없이 **"모래 속에서 폄" / "해 속에서 폄"** 아이콘 표시(손가락이 모래 위에 내려오는 그림). 조각 시작 0.045초 안쪽에서 눌러 펴지는 중이었던 경우도 여기에 포함("너무 빨리 누름"이 실제 원인이므로).
- 이번 누름 이전에 닫히는 중(o > 0)에 다시 눌러 t\*가 t_down보다 앞서야 하는 경우(= 이번 누름 자체를 안 했어야 피할 수 있음): 숫자 없이 "다시 누름" 표시.
- **입력 시각 기준**: 브라우저가 손 뗌을 받은 시각(`event.timeStamp`)을 게임 시계로 바꾼 값. 화면 유리 → 브라우저까지의 하드웨어 지연은 측정할 수 없어 포함되지 않는다. 그래서 결과 화면 해설에 작게 "늦게 뗌 = 기기가 손 뗌을 알아챈 때 기준"을 한 줄 적는다(사실과 다르게 말하지 않기 위해).
- 열림·닫힘 시간(0.15/0.10초), 따끔 문턱(30%)은 숨은 보정 없이 그대로 쓴다. 판정에 숨은 여유를 넣지 않는다(표시 숫자와 실제 판정이 1:1로 맞아야 하므로).

## 날씨 생성기 (확정)

### 원칙
- **모든 날의 날씨 조각 "재료"(길이 목록·종류 개수)는 똑같다.** 날짜(시드)가 바꾸는 것은 **순서뿐**이다. ⇒ 구간별 비 총시간·해/모래 개수·구간 길이가 모든 날 동일(기획안 권장 "비 총시간 고정 셔플" 적용).
- 아침 0~20초는 **매일 같은 고정 배치**(첫 판 학습용).
- 모든 길이는 **정수 ms, 50ms 배수**. 조각은 빈틈 없이 이어 붙어 정확히 150,000ms를 채운다.

### 시드와 난수 (재현 가능하게 정확히)
- **오늘의 날씨 날짜** = 한국 시간 날짜 문자열 `'YYYY-MM-DD'`. 계산: `new Date(Date.now() + 9*3600*1000)`의 **UTC** 연·월·일(기기 시간대와 무관). 판을 **시작한 순간**의 날짜로 고정(자정을 넘겨도 그 판은 시작 날짜의 날씨).
- **시드** = FNV-1a 32비트 해시(`h = 0x811c9dc5`, 글자마다 `h ^= code; h = Math.imul(h, 0x01000193) >>> 0`)를 문자열 `'desert-breath|' + 날짜`에 적용. (날짜 문자열은 ASCII라 UTF-16 코드 = 바이트.)
- **난수** = mulberry32(시드). 표준 구현:
  ```
  function mulberry32(a){return function(){a|=0;a=a+0x6D2B79F5|0;var t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296;}}
  ```
- **섞기** = Fisher–Yates: `for (i = n−1; i ≥ 1; i−−) { j = floor(rng() × (i+1)); swap(a[i], a[j]) }`. 위 표의 값 순서(오름차순)를 시작 배열로 쓴다.
- **난수 호출 순서(고정)**: ① r2 ② g2 ③ h2 ④ 2구간 위험 종류 5개 ⑤ r3 ⑥ g3 ⑦ h3 ⑧ 3구간 위험 종류 10개 ⑨ 단위 번호 [0..9] ⑩ s ⑪ m ⑫ r4 ⑬ c4 ⑭ m4.
  - 섞인 배열의 k번째 값이 k번째 단위에 들어간다. 3구간 묶음은 ⑨의 앞 4개 번호를 오름차순 정렬해, 섞인 s·m을 그 순서대로 배정. 4구간 m4는 앞 18개가 단위 첫 모래, 19번째가 마지막 모래.
- **연습판 시드** = `crypto.getRandomValues(new Uint32Array(1))[0]` (없으면 `Math.random()*2^32 >>> 0`). 같은 생성기에 시드만 다르다.

## 화면·시간 공정성

### 3초 예고 (세로·가로 동일)
- 날씨 띠에서 "지금" 선(선인장 바로 위 x_now) ~ 띠 오른쪽 끝(x_end) 사이가 **정확히 3.000초**.
- 스크롤 속도 = (x_end − x_now) ÷ 3 (px/초), 화면 크기·회전이 바뀔 때마다 다시 계산. 조각의 x = x_now + (조각 시각 − t) × 속도.
- 띠 오른쪽 끝 밖은 그리지 않는다(잘라냄). 따라서 어떤 기기에서도 조각은 지금 선 도달 **3.000초 전**에 처음 보인다. 지나간 날씨는 지금 선 왼쪽에 최대 0.5초 분량만 흐리게.
- 회전 중 띠 길이가 바뀌어도 시간 축은 그대로(조각 위치는 시각으로 계산하므로 순간이동만 있고 시간 이득·손해 없음).

### 시뮬레이션 시계
- 게임 시각 = `performance.now()` 누적(일시정지 시간 제외). 시뮬은 **고정 단계 5ms**(초당 200단계), 매 프레임 쌓인 시간만큼 단계 실행.
- 한 프레임이 250ms보다 길게 끊기면 250ms까지만 진행(그 이상은 버림 = 게임이 잠깐 느려짐. 입력 없이 시간이 훅 지나가는 불공정 방지).
- 한 단계(시각 t → t+5ms) 순서: ① t 이하 시각의 입력 적용(누름 −2 포함) ② 따끔 판정(o(t) 기준) ③ o를 t+5ms까지 갱신 ④ 물 변화 = 5ms × [(1−ō)·닫힘값 + ō·열림값(p_mid) + 추가마름(t_mid)], ō = 단계 처음·끝 o 평균, p_mid·t_mid = 단계 중간 ⑤ 성장 처리 ⑥ W ≤ 0이면 마름.
- 판 시작: 시작 버튼 → **2초 준비**(t = −2 → 0, 띠는 이미 흐름, 물 변화 없음, 입력 무시). 시작 버튼을 누른 손가락이 그대로 있어도 열리지 않고, t ≥ 0 이후 **새로 누른** 입력부터 센다.

### 입력
| 입력 | 처리 |
|---|---|
| `pointerdown` (게임 영역, 버튼 제외) | 그 pointerId를 누름 목록에 추가, `setPointerCapture`. 마우스·펜·터치 동일 |
| `pointerup` / `pointercancel` / `lostpointercapture` | 그 pointerId 제거 |
| 스페이스 `keydown` | `event.repeat`면 무시, 아니면 "키" 누름 추가. `preventDefault` |
| 스페이스 `keyup` | "키" 누름 제거 |
| `blur`, `visibilitychange`(hidden), `pagehide` | **모든 누름 강제 제거(그 시각에 뗀 것으로)** + 자동 일시정지 |
- 누름 목록이 비었다 ↔ 닫힘 목표. 입력 시각 = `event.timeStamp`를 게임 시계로 바꾼 값을 [직전 처리된 시뮬 시각, 현재 시각]으로 자른 뒤 5ms 단위 반올림. (프레임 처리 시각이 아니라 실제 입력 시각을 쓴다 → 프레임 밀림으로 늦게 판정되지 않게.)
- 누르는 곳: 게임 영역 전체(일시정지·음소거 버튼 제외). 아래쪽 절반에 은은한 "누르는 자리" 표시를 두어 손가락이 날씨 띠를 가리지 않게 유도.
- `touch-action: none`, `user-select: none`, 길게 누르기 메뉴·확대 방지 필수(누르고 버티기 게임이라 iOS 길게 누르기 메뉴가 뜨면 치명적).

### 일시정지
- Ⅱ 버튼 / Esc / P, 그리고 위 자동 조건.
- 일시정지 순간: 모든 누름을 그 시각에 뗀 것으로 처리(손가락을 놓쳐도 열린 채 멈추지 않게). **o는 즉시 0으로 만들지 않는다** — 재개 후 남은 닫힘(최대 0.10초)이 정상 진행(일시정지로 따끔을 피하는 꼼수 방지).
- 일시정지 화면은 **날씨 띠를 불투명하게 가린다**(멈춘 채 앞날씨를 오래 보며 계획하는 이점 차단).
- "계속" → **1.5초 다시 준비**(띠 보임, 시간 멈춤, 입력 무시) → 재개. 재개 후 새로 누른 입력부터 센다.
- 일시정지한 판도 기록 자격 유지(위 처리로 실질 이득이 거의 없음).

**가장 아까웠던 순간 (정의)**
- 따끔이 1번 이상이면: **잃은 물이 가장 큰 따끔 1개.** 표시: 시각 · 날씨 · 잃은 물 · 원인. 예 "1분 52초 모래 — 물 −21 · 0.08초 늦게 뗌" / "58초 해 — 물 −9 · 해 속에서 폄".
- 따끔이 0번이면: **가장 많이 덜 받은 비 1개.** 덜 받은 물 = 그 비 조각 동안 Σ (열림값 − 닫힘값) × (1 − o) × 단계. 표시 "2분 03초 비 — 끝까지 펴 뒀다면 +14". (끝까지 펴 두면 바로 뒤 모래에 따끔일 수 있다는 사실은 숫자에 넣지 않으므로 문구를 "펴 뒀다면"으로 고정해 사실과 어긋나지 않게.)
- 같은 값이면 더 이른 시각.
- 마른 판이면 2번 줄이 마른 시각을 이미 보여 주므로 5번은 위 규칙 그대로.

## 첫 판 학습 (글 없이 30초)
1. **시작 화면 데모(반복 재생, 약 8초, 글 없음)**: 작은 날씨 띠와 선인장. ① 비가 다가옴 → 손가락 그림이 아래쪽을 누름 → 선인장이 펴지고 통통해지며 눈금이 오름 ② 비 끝 직전 손가락이 떨어짐 → 모래가 지나가도 멀쩡 ③ 두 번째 반복에서는 손가락이 늦게 떨어짐 → "따끔" 모래 박힘 + "0.08초" 숫자. 실제 엔진으로 정해진 입력을 재생(가짜 애니메이션 아님 → 보여 준 숫자도 실제 계산값).
   - 시작 화면 구성: 제목 「선인장 키우기」, 데모, 큰 버튼 "오늘의 날씨"(+ 작은 날짜), 작은 버튼 "연습", 오늘 최고·전체 최고 키, 음소거.
2. **아침 0~20초 고정 배치가 튜토리얼**: 1초에 첫 비(4초, 길고 안전) → 7초 두 번째 비 → 12초 첫 해(펴 두면 −6 + 쪼그라듦을 체험) → 15.5초 긴 비. 20.6~21.2초 사이 2구간 첫 위험은 항상 모래(첫 따끔).
3. **첫 판 손가락 힌트**(`desert-breath-seen` 없을 때만): 비가 "지금" 선에 닿기 0.3초 전부터 아래쪽에 손가락 그림이 깜빡이고, 비 끝 0.2초 전에 손가락이 들리는 그림. **아침 비 3개에만** 표시하고 그 뒤로는 없음. 글 없음.
4. 성장 규칙 보이기: 통통함이 90선에 닿은 상태에서 비를 받으면 물방울이 몸 위로 올라가 키 눈금이 오르는 연출(art-ui.md).
