# 박자 앵무새 (parrot-beat) QA 리포트

## 2026-11-14 QA — 첫 출시 검증 (games/parrot-beat/index.html + 홈 카드, 커밋 54ee8dd)
판정: **실패 (높음 1건 수정 후 재검증 필요)**. 판정 정확도, 게임 흐름, 밸런스, 레이아웃, 회귀는 모두 통과했다. "다시 하기"로 시작한 판에서 Ⅱ(일시정지) 버튼이 꺼진 채로 남는 버그(높음)가 있다. iPad에는 Esc/P 키가 없어서 그 판 내내 손으로 일시정지할 수 없다. 박자 맞추기 측정 범위가 기획(+400ms)보다 좁은 문제(보통)도 있다.

### 실행한 테스트와 결과
1. **스모크 (회귀)** `node tests/smoke.js`: 7게임 × PC / iPad 세로·가로 = 21건 모두 통과. 목록 첫 카드가 parrot-beat.
2. **판정 정확도 (실제 입력 경로)**: CDP `Input.dispatchKeyEvent / dispatchTouchEvent / dispatchMouseEvent`에 `timestamp`를 지정해 보냈다. `event.timeStamp`가 의도한 시각과 0.1ms 안으로 맞는 것을 먼저 확인했다. 판정은 `Sound.Beat.tapTime(e)` 경로를 그대로 지났다. iPad(gen 7) 에뮬레이션에서 키·터치·마우스를 섞어 보냈다.

|---|---|---|
| 0 | perfect (0) | Perfect ✓ |
| +40 / −40 | perfect (40) / perfect (−40) | Perfect ✓ (±45 이내라 Perfect가 맞다. 업무 지시의 "Good"은 기획과 다르다) |

   - 연타 보호: 같은 음표 뒤 +30ms 탭은 무시, +60ms 탭은 헛박 ✓
   - 두 손가락 동시 터치(같은 timestamp, pointerdown 2개): 1개만 Perfect, 2번째는 50ms 보호로 무시(헛박 아님) ✓

   - 실시간 한 판(2분 48초) 중 **158초 시점, 8단계 122 BPM**에서 실제 키 입력 7개: 모두 perfect(0) ✓
3. **게임 흐름**
   - 시작(실제 터치/클릭) → 카운트인 1마디(약 2.7초) → 부르기 → 따라하기 → 판정. 1단계 패턴은 A→B→C→D 고정 순서 ✓
   - 실패 패턴 재출제: C 실패 → 다음 라운드에 C 다시 → D가 빠지고 4라운드에서 단계 종료 ✓
   - 하트: 라운드 실패 −1 ✓. 하트 2에서 1단계 무실패 → 3 회복 + 500 보너스 ✓. 0이 되면 게임 오버, 1.3초 뒤 결과 화면, "N단계까지" ✓
   - 클리어: 8단계 σ0 자동 진행 → "클리어!", 점수가 `simulateRun` 같은 시드 값과 일치(9500 = 9500) ✓
   - 결과 0.8초 입력 잠금: 직후 Enter는 무시, 0.9초 뒤 버튼이 켜지고 "다시 하기"에 포커스 ✓
   - 최고 기록 `parrot-beat-best`: `{"score":9500,"stage":8,"cleared":true}` 저장. 더 낮은 판 뒤에도 유지되고 시작 화면에 왕관 + "최고 9500점 · 8단계" 표시 ✓
   - 일시정지 — 버튼: ctx 시계 정지, 덮개 표시. 계속 → 카운트인 → 같은 라운드 부르기부터 ✓. 진행 중 라운드는 무효: 점수 200→0, perfect 2→0으로 되돌림, 같은 패턴 재출제 ✓
   - 일시정지 — Esc 두 번(정지/재개) ✓, 카운트인 중 정지 → 카운트인부터 ✓, 전환 마디 중 정지 → 다음 단계 1라운드(102 BPM)부터 ✓
   - visibilitychange(hidden 흉내): 자동 정지, ctx 정지. 다시 보이게 해도 사용자가 "계속하기"를 누를 때까지 정지 유지 ✓
   - 음소거: 클릭/M 키로 `icoOn`/`icoOff`의 computed display가 block↔none으로 실제 바뀜, aria-pressed와 `parrot-beat-muted` 저장 ✓
   - 박자 맞추기: +150ms 늦게 탭 → "+150ms"(재실행 0/+150/+250/+290/−80 모두 정확), 확인 → `parrot-beat-offset=150` 저장, 새로고침 후에도 유지 ✓. 탭이 없으면 "다시 한 번 해 볼까요?"이고 저장 안 함 ✓, "0으로" ✓
   - 보정 반영: offset 150에서 실제로 +150ms 늦게 친 탭 → perfect(0~1). offset 0에서 같은 탭 → 헛박 ✓

6. **콘솔 오류**: 모든 테스트(스모크 포함)에서 pageerror·console.error·HTTP 4xx 0건 ✓
7. **시계 드리프트 (autoPlay 실시간 한 판 168초, 라이트·다크 2회)**: 1초마다 `heardTime − ctxTime`을 기록했다. −42~−30ms 사이에서 움직였고 누적되지 않았다. 헤드리스 오디오 시계는 performance 시계보다 0.03% 느렸지만(168초에 약 50ms) `getOutputTimestamp` 매핑이 이를 흡수했다. 그 결과 158초 시점 실제 입력 판정 오차가 0ms였다 ✓. 화면(`heardTime − offset`)과 판정(`tapTime`)은 같은 함수를 쓰므로 서로 어긋날 수 없다.

### 버그 (심각도: 치명/높음/보통/낮음)
- **[높음] "다시 하기"로 시작한 판에서 Ⅱ 일시정지 버튼이 꺼진 채(disabled)로 남음**
  - 증상: 결과 화면에서 "다시 하기"(버튼 또는 Enter/Space)를 누르면 새 판이 시작되지만 Ⅱ 버튼이 흐리게(opacity .5) 비활성 상태다. iPad에서는 그 판 동안 손으로 일시정지할 방법이 없다(Esc/P 키 없음, 탭 숨김 자동정지만 동작). 이 판에서 일시정지 메뉴의 "처음부터"로 다시 시작해도 계속 꺼져 있다.
  - 재현: 시작 → 아무것도 치지 않고 게임오버(약 13초) → 결과 0.8초 뒤 "다시 하기" → `pauseBtn.disabled === true` (Playwright 클릭 30초 타임아웃으로 확인).
  - 기대: 새 판이 시작되면 Ⅱ 버튼이 다시 켜진다.
  - 관련 코드: `endGame()`의 `el.pauseBtn.disabled = true`(1391행)와 `showResult()`(1417행)가 끈다. 다시 켜는 곳은 `toMenu()`(1433행)뿐이고 `startGame()`(1279~1298행)에는 없다. `startGame`에서 `el.pauseBtn.disabled = false`가 필요하다. 박자 맞추기 화면(`openCal` 1518행)도 끄지만 `closeCal → toMenu`에서 다시 켜지므로 정상.
- **[보통] 박자 맞추기 측정 범위가 실제로는 약 −300 ~ +299ms (기획 −80 ~ +400ms)**
  - 증상: 블루투스 지연 등으로 매번 +320ms 늦게 치는 사용자는 탭이 하나도 유효 처리되지 않아 "다시 한 번 해 볼까요?"만 나오고 보정값을 저장할 수 없다. +290ms까지는 정확히 측정된다.
  - 재현: 박자 맞추기 → 12번 클릭에 모두 +320ms 늦게 탭(CDP timestamp로 정확히 주입) → 결과 빈 값 + 다시 하기. +300ms도 경계에서 실패했다.
  - 기대: design.md "범위 −80 ~ +400ms", "블루투스 이어폰(약 150~300ms)". 최소한 +400ms까지 측정되어야 한다.
  - 관련 코드: `calTap()` 1536~1537행. 가장 가까운 클릭에 매칭하는데 허용폭이 `CAL.beat * 0.45`(90 BPM에서 300ms)다. 게다가 +333ms를 넘으면 다음 클릭이 더 가까워진다. 제안: 클릭마다 "−150ms ~ +450ms" 비대칭 창으로 매칭(클릭 간격 667ms 안이라 겹치지 않음).
- **[낮음] 테스트 훅 `state().stage`가 단계 전환 마디 첫 순간 이전 단계를 보고함**: 실시간 로그에 "stage 1 phase transition bpm 94"가 찍힌 뒤 같은 마디에서 stage 2로 바뀐다. 화면 HUD는 `onEnterBar`에서 바로 갱신되므로 사용자 영향은 없다(훅 전용, 2109~2115행).
- **[낮음·기획 의견] 4~6단계 따라하기 중에도 선생님 줄에 정답 패턴이 흐리게 보임**: CEO 결정("4~6 힌트 없음(선생님 줄은 보임)")과 일치하므로 버그는 아니다. 다만 design.md 단계표의 "따라하기 때 정답 가이드: 없음 (기억으로)" 취지와 달리, 화면 위쪽을 읽고 치면 된다. "너무 쉬우면 싫어함" 성향을 고려하면 4단계부터 따라하기 마디에는 선생님 줄 기호를 숨기거나 더 흐리게 하는 것을 검토할 만하다(`drawTeacherRound` 1770행, `draw()` 1878행이 response 마디에도 그림).
- **[낮음] iPhone 13 가로(750×342) 시작 화면 오버레이가 2px 세로 스크롤됨**(scrollHeight 344 > 342). 화면상 거의 보이지 않는다.
- **[낮음·참고] M 키는 치기가 아니라 음소거**: design.md는 "아무 키(Esc·P·Tab·modifier 제외)"를 치기로 정했다. M을 쓰면 연주 중 음소거가 토글된다(1988행). 단축키로 의도한 것이라면 design.md에 반영이 필요하다.

### 실기기 확인 필요
