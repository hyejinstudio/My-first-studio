# 박자 앵무새 (parrot-beat) QA 리포트

## 2026-11-14 QA 4회차: 틀린 곳부터 (커밋 a8462cb)
판정: **통과**. 사용자 요청 "방금 틀린부분부터 다시 시작하는 옵션도 넣어줘"를 반영한 「틀린 곳부터」가 design.md 「틀린 곳부터」 절, 화면 흐름 4번, 테스트 훅대로 동작한다. 치명·높음·보통·낮음 버그는 없다. 2회차 낮음 버그(iPhone 13 가로에서 결과 화면과 보정 제안이 함께 뜨면 6px 스크롤)는 **해결**되었다.

### 실행한 테스트와 결과
1. **여러 지점에서 게임 오버 → 「틀린 곳부터」** (iPad gen 7 에뮬레이션. 버튼은 `page.touchscreen.tap`으로 실제 터치, 마디 기록은 `Sound.Beat.onBar`로 수집)
   - **A. 1단계 1라운드**: 시작 버튼을 실제로 터치해 시작했다. 실패 라운드는 실제 터치(CDP timestamp) 2개만 치고 게임 오버 → 결과 200점(손계산 100+100). 「틀린 곳부터」 터치 → countin, 하트 3, 콤보 0, retries 1, 점수 0·판정 수 0으로 되돌아감. 최고 연속 2는 유지됨. 마디 순서 countin@90 → call@90 → ready@90 → response@90, 같은 패턴 `x...x...x...x...`. 부르기 마디의 선생님 북 4번 = 패턴 x 수. 남은 라운드를 σ0으로 치면 1단계 A→B→C 순서가 유지되고, 무실패 +500이 들어간 점수 **1,830 = 손계산값**, 하트 3. 다음은 2단계(94 BPM) ✓
   - **B. 3단계 2라운드, 앞 라운드 실패**: 1라운드를 놓쳐 하트 2, 2라운드는 같은 패턴이 다시 나옴(재출제). 2라운드에서 3개만 치고 게임 오버 → **Space**로 이어하기 → 재출제된 패턴 그대로 98 BPM으로 다시 시작함. 이어 친 라운드가 성공하자 3라운드는 큐의 다음 패턴(`..x.x.....x.x...`)으로 나옴(재출제 아님). 1라운드 실패 기록이 남아 있어서 무실패 보너스와 하트 회복이 없다. 점수 **1,410 = 손계산값** ✓
   - **C. 5단계 3라운드(단계 마지막, 경계 케이스)**: 1·2라운드는 σ0, 3라운드는 실제 키로 4개만 침. 판정 확정이 6단계 전환 마디 안에서 일어나는 것을 확인했다(결과 뒤 HUD는 6, 3회차 [참고]와 같은 동작). failPoint `{5,2}`, stageReached 5, 결과 제목 "5단계까지", 결과 점수 2,940 = 직전 2,470 + 470(손계산, 콤보 배율 1.1 반영). **Enter** → **countin@106 → call@106**(110이 아님), 5단계 3라운드 같은 패턴, 점수 2,470으로 되돌아감, HUD 5. 재도전에 성공하면 +500(라운드) +500(무실패) = **4,170 ✓**, 하트 3. 그다음 전환 마디 110 BPM → 6단계 1라운드 ✓
   - **D. 8단계 3라운드(마지막)**: 첫 게임 오버 결과 3,540 = 2,960 + 580 ✓. 0.8초 잠금 중에는 Enter와 터치를 모두 무시했다(retries 0 유지) ✓. 터치로 이어하기 → 122 BPM 같은 라운드로 시작. 같은 라운드에서 다시 게임 오버 → 실패 직전 점수가 **2,960으로 같다(중복 없음)**. 결과 3,460 = 2,960 + 500(콤보 0에서 시작하므로 배율 1.0, 손계산 일치). 버튼이 아닌 곳에 포커스를 두고 Enter → 틀린 곳부터, retries 2, 점수 2,960. 재도전 성공 후 클리어 7,860 = 2,960 + 600 + 800 + 500 + 3,000(하트 3) ✓
2. **반복 이어하기와 기록**
   - retries 증가 1 → 2 ✓. 이어하기 판의 결과 화면(게임 오버·클리어 둘 다): "이어하기 N번" 알약 표시, 숫자 1/2, aria-label "이어하기 1번". "새 최고 기록"은 숨김 ✓
   - `parrot-beat-best`는 이어하기 판의 게임 오버와 클리어 모두에서 **바뀌지 않았다**(`{"score":10,"stage":1,"cleared":false}` 그대로). 이어하기 전 첫 게임 오버(retries 0)에서는 정상 갱신됨 ✓
   - 클리어 결과: 「틀린 곳부터」 숨김, 「다시 하기」 primary(as-secondary 없음), `retryFromFail()` → null ✓
   - 클리어 결과에서 「다시 하기」(Space) → 새 판: retries 0, failPoint null, 1단계, 점수 0. 이 판에서 `setStage(8)` 후 클리어 → 최고 기록 `{"score":7960,"stage":8,"cleared":true}`로 갱신되고 "새 최고 기록" 알약이 뜬다 ✓
   - E. 이어하기 판 게임 오버에서 「다시 하기」를 터치 → retries 0, failPoint null, 1단계, 하트 3, 점수 0 ✓. 「처음으로」 → 메뉴, 훅 null ✓
   - **오차 기록 되돌림**: 1단계부터 +90ms로 쳐서 좋아 15개를 만든 뒤, 실패 라운드에서 +90ms를 1개 더 쳐서 16개로 만들고 게임 오버 → 보정 제안이 뜸. 이어하기 후 다시 게임 오버(오차 15개) → 보정 제안이 사라짐. 실패 라운드의 `errs`만 정확히 빠진다 ✓
3. **키보드·잠금·포커스**: 게임 오버 결과에서 잠금 중 버튼은 disabled이고, 0.8초 뒤 포커스가 `retryBtn`으로 간다(A/B/C/D 모두). Enter → 틀린 곳부터, Space → 틀린 곳부터, 포커스가 버튼 밖일 때 Enter → 틀린 곳부터. 클리어 결과에서는 포커스가 `againBtn`, Space → 다시 하기 ✓

## 2026-11-14 QA 3회차: 준비 마디·조용한 부르기 (커밋 b6e1f2e)
판정: **통과**. 사용자 피드백 두 가지("선생님이 칠 때 배경 소리 빼기", "선생님 다음에 바로 쳐야 함")를 반영한 변경이 기획서대로 동작한다. 치명·높음·보통 버그는 없다. 낮음 1건과 참고 1건만 있고, 둘 다 배포를 막지 않는다.

### 실행한 테스트와 결과
1. **진행 순서·마디 길이 (PC, 실제 "시작하기" 클릭, autoPlay σ0, 클리어까지 실시간 1판)**
   - `Sound.Beat.onBar`로 모든 마디를 기록했다. 순서: 카운트인 → [부르기 → 준비 → 따라하기] × 3 → 전환 → … 8단계 끝 → 쉬는 마디. 부르기·준비·따라하기 각 24마디, 전환 7마디, 단계마다 3라운드 ✓
   - 모든 마디 길이가 240/BPM과 1e-6초 안에서 같다(불일치 0). 준비 마디는 beats=4이고, 앞뒤 마디와 BPM이 같다 ✓. 부르기 BPM 90/94/98/102/106/110/116/122 ✓
   - 카운트인 시작부터 마지막 따라하기 끝까지 **185.04초 (3분 5초)**. 실제 화면 시간(카운트인 → 결과)은 186.9초 ✓
   - 결과: 클리어, 하트 3, Perfect 126 / Good·Miss·헛박 0, 점수 **38,700** = 독립 계산 이론값(음표 126개) ✓. 최고 기록 `{"score":38700,"stage":8,"cleared":true}`로 저장됨 ✓
   - 1단계는 시드 200개 모두 A→B→C 고정. 2~8단계는 풀 5개 중 서로 다른 3개 ✓
2. **마디별 소리 (AudioNode connect/start를 감싸서, musicBus(gain 0.55)로 가는 소스를 마디별로 셈)**
   - 부르기 24마디 전부: 반주 소스는 사인파 4개(2500Hz 1개 + 2400Hz 3개, 정박마다 아주 약한 틱)뿐이다. 코드·베이스·하이햇·메트로놈은 0개 ✓
   - 선생님 북(teacherBus)은 부르기 마디에서만 울리고, 한 마디에 울린 수가 패턴의 x 수와 같다(합계 126). 다른 마디에서 울린 것은 0개 ✓
   - 준비 24마디 전부: 정박 위치(0/1/2/3박, 오차 1e-6박 이내)에 틱 4번. 1~3박은 triangle 1320Hz, 4박은 sine 1760→2090Hz(높게) + 작은 노이즈. 반주는 없음 ✓
   - 따라하기: 메트로놈 990Hz ×4 + 베이스 + 하이햇(5단계부터 16분 햇 추가), 코드 없음(변경 없음) ✓. 전환 마디: 반주 + 단계 상승음(변경 없음) ✓
3. **판정 (iPad gen7 에뮬레이션, CDP 입력에 timestamp를 넣어 실제 키·터치·마우스 이벤트 전송)**
   - 준비 마디 탭: 키(0.2초), 터치(0.8초), 마우스(1.4초), 따라하기 시작 −125ms의 키 → 4개 모두 `ignored`, 판정 수 변화 없음, **soft 탭 소리** ✓
   - 준비 마디 마지막 110ms: 첫 음표 −105ms 키 → **good(−105)** (따라하기 판정 창으로 처리) ✓. 첫 칸이 쉼표인 패턴(4단계 `....x.....x.x...`)에서 따라하기 시작 −100ms 탭 → `ignored`(헛박 아님), 그 라운드 성공 ✓. 마디 끝 +50ms 탭 → `ignored` ✓
   - 따라하기: 0 → perfect(0), +40/−40 → perfect, +80/−80 → good, +105/−105 → good, **+150 → 헛박 + 그 음표 Miss**, **−150(첫 음표, 창 밖) → ignored + 그 음표 Miss** ✓ (키·터치·마우스 섞어서)
   - 판정 창 상수 `CFG.good = 0.110`, `perfect = 0.045` ✓
4. **게임 흐름·규칙**
   - 점수: 1단계 R0 350+100=450, R1 +250=700, R2(실패) +200=900. 2단계 콤보 8 이상에서 배율 1.1 적용(520+200, 660+200) → 2,880. 손으로 계산한 값과 모두 같다 ✓
   - 하트: 1단계 R2 실패 3→2, 2단계 R0 실패 2→1. 2단계는 실패가 있어서 +500 보너스와 하트 회복이 없다 ✓. 3단계 무실패 → 하트 1→2, heartGain 효과음 ✓
