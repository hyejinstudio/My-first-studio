# 박자 앵무새 기획서
- slug: parrot-beat
- 한 줄 소개: 북 치는 선생님 새가 한 마디를 들려주면, 한 마디 "하나-둘-셋-넷"으로 숨을 고른 뒤 내 앵무새가 똑같이 따라 친다. 정박에서 시작해 엇박·쉼표·당김음·16분까지, 글 없이 듣고 치면서 배우는 약 3분짜리 따라치기 리듬 게임.
- 장르 규칙(콜 앤 리스폰스 따라치기)만 빌린다. 기존 상용 리듬게임의 캐릭터·곡·연출은 쓰지 않는다. 캐릭터: 위쪽 **선생님 새**(작은 북), 아래쪽 **내 앵무새**.
- 기존 스튜디오 게임(블록 쌓기, 뱀, 숫자 퍼즐, 두더지, 피하기, 땅따먹기)과 겹치는 장르 없음. 스튜디오 첫 리듬 게임.

## 핵심 루프
**정박 틱(기준 박)은 시작부터 끝까지 끊기지 않는다.** 반주(코드·베이스·하이햇)는 마디 종류에 따라 빠지고 들어온다(아래 "마디별 소리"). 4/4박자, 한 라운드 = **3마디**.
1. **부르기 마디**: 선생님 새가 패턴을 친다. 반주 없이 **선생님 북 + 아주 약한 정박 틱 4개**만 들린다. 화면 위쪽 타임라인에 박자 칸과 음표가 보인다(후반엔 흐려지거나 사라짐).
2. **준비 마디**: 차례가 선생님 → 나로 넘어간다. "하나-둘-셋-넷" 카운트 틱 4번, 3·4박에 내 앵무새가 북채를 드는 준비 자세. 탭해도 판정 없음.
3. **따라하기 마디**: 내가 화면 아무 곳 탭 / 아무 키로 같은 패턴을 친다. 친 자리가 아래 타임라인에 판정 색으로 찍힌다.
4. **판정**: 마디가 끝나는 순간 성공(선생님 끄덕) / 실패(하트 1개 깨짐, 놓친 음표 잠깐 표시).
5. 다음 라운드의 부르기 마디가 곧바로 시작. **3라운드 = 1단계**, 8단계를 버티면 클리어.

## 규칙

### 시간 구조
- 시작: **카운트인 1마디**(박마다 클릭 4번, 선생님이 북채로 박을 셈. 입력 무시).
- 라운드 = **부르기 1마디 + 준비 1마디 + 따라하기 1마디** (12박).
- 단계 = **3라운드**(9마디 = 36박).
- 단계가 바뀔 때 **단계 전환 1마디**(부르기 없음, 반주만, 새 BPM으로 이 마디부터 바뀜, 단계 표시 연출). 이 마디의 탭은 무시. 전환 마디 다음은 곧바로 그 단계 1라운드 부르기 마디.
- 한 단계 안에서는 BPM이 바뀌지 않는다(준비·따라하기 마디 = 부르기 마디와 같은 BPM).
- 전체 길이(BPM 곡선 기준, 클리어): 카운트인 2.7초 + 본 라운드 72마디 약 166.5초 + 전환 7마디 약 15.8초 ≈ **3분 5초**.
  - 마디 길이(초) = 240 / BPM: 90→2.67, 94→2.55, 98→2.45, 102→2.35, 106→2.26, 110→2.18, 116→2.07, 122→1.97. 8단계 합 18.50초 × 9마디 = 166.5초.

### 준비 마디 (2026-11-14 추가)
- 목적: 부르기 직후 곧바로 따라하기가 시작돼 숨 돌릴 틈이 없다는 피드백 해결. 들은 패턴을 머릿속으로 한 번 되새기고, 따라하기 첫 박을 미리 세고 들어가게 한다.
- 길이: **1마디 전체(4박)**. 반 마디(2박)는 쓰지 않는다(아래 "결정 이유").
- 소리: **카운트 틱 4번**(정박마다, "하나-둘-셋-넷"). 4번째 틱은 살짝 높게 → "다음이 네 차례". 부르기 마디의 약한 틱보다 또렷하게, 카운트인 클릭과 같은 계열(음색·볼륨 상세는 sound.md). 선생님 북·반주 코드는 없음.
- 화면: 강조가 선생님 → 내 앵무새로 넘어간다(선생님은 날개로 앵무새를 가리키는 "넘겨주기" 동작). 내 타임라인은 "대기" 상태(반쯤 활성), 정박 큰 원 4개가 카운트에 맞춰 차례로 켜진다(숫자 1~4를 함께 보여줄지는 art-ui.md). **3박부터 앵무새가 북채를 드는 준비 자세**, 4박에 가장 높이. 플레이헤드는 내 줄에서 움직이지 않는다(따라하기 마디 시작에 왼쪽 끝에서 출발).
- 선생님 줄 기호: 준비 마디 동안 **부르기 때와 같은 상태로 유지**(1~6단계는 보임, 7단계는 소리 날 때만이라 준비 마디에는 안 보임, 8단계 없음). 즉 준비 마디는 "다시 보며 되새기는 시간"이고, 4~6단계의 "기억해서 치기"는 지금처럼 **따라하기 마디 시작**에 기호가 사라지면서 시작된다.
- 1~3단계 내 줄 힌트(빈 기호)도 준비 마디 동안 그대로 보인다.
- 탭: **판정 없음**(부르기 마디와 같은 취급: 앵무새가 작게 따라 움직이고 작은 탭 소리만, 헛박 아님). 단, 따라하기 판정 구간은 기존대로 따라하기 시작 − Good 창(현재 110ms)부터이므로, 준비 마디 마지막 110ms의 탭은 첫 음표에 매칭될 수 있고 매칭 안 되면 무시(기존 규칙 그대로).
- 일시정지·실패 재출제·하트 회복·단계 전환과의 관계는 각 항목에 반영.

### 결정 이유 (간격 길이·라운드 수)
| 안 | 단계당 라운드 | 한 판 길이 | 판단 |
|---|---|---|---|
| 현재(간격 없음) | 4 | 2분 46초 | 피드백 문제 그대로 |
| 반 마디(2박) 간격 | 4 | 약 3분 24초 | 2/4 마디가 끼어 마디 단위 루프가 깨지고(박자 엔진도 16칸 마디 기준), 시간도 더 김 → 제외 |
| 1마디 간격 | 4 | 약 4분 1초 | 사용자 선호(짧고 굵게, 3분대 초반 이내) 초과 → 제외 |
| **1마디 간격** | **3** | **약 3분 5초** | 4/4 마디 루프 유지, 시간 기준 충족 → **채택** |
- BPM 곡선은 그대로 둔다(템포를 올려 시간을 줄이면 이번 피드백 "너무 바로 친다"와 반대 방향).
- 단계당 3라운드여도 패턴 풀(5개)·학습 순서는 유지. 단계마다 3개만 보여주는 대신 무작위로 뽑아 판마다 조합이 달라진다.

### 마디별 소리 (2026-11-14 결정, 상세 레시피는 sound.md)
| 마디 | 들리는 것 |
|---|---|
| 카운트인 | 카운트 클릭 4번 (변경 없음) |
| 부르기 | **선생님 북 + 정박 4개에만 아주 약한 틱.** 코드·베이스·하이햇 없음 |
| 준비 | 카운트 틱 4번(4번째 살짝 높게). 코드·베이스·하이햇 없음 |
| 따라하기 | sound.md 결정에 따름(내 탭이 잘 들리는 가벼운 반주 + 정박 틱) |
| 단계 전환 | 반주 + 단계 상승 효과음 (변경 없음) |
- 부르기 마디에 약한 정박 틱을 남기는 이유: 엇박(뒷박·16분 엇박)은 "박과 박 사이"라는 기준이 있어야 귀로 구분된다. 틱이 완전히 없으면 `..x.`(뒷박 단독)과 `x...`(정박)이 같은 소리로 들린다. 틱은 선생님 북보다 확실히 작게(북을 가리지 않게).

### 패턴 표기
- 한 마디 = **16칸(16분음표 그리드)**. `x` = 친다, `.` = 쉰다. `|`는 박 구분(4칸 = 1박).
- 각 박의 4칸 이름: 1칸 = **정박(박)**, 3칸 = **뒷박("앤")**, 2·4칸 = **16분 엇박**.
- 칸 i(0~15)의 시각 = 마디 시작 + i × (60 / BPM / 4)초.

### 단계표 (BPM 곡선, 학습 목표, 화면 보조)

| 단계 | BPM | 새로 배우는 것 | 부르기 때 타임라인 | 따라하기 때 정답 가이드 |
|---|---|---|---|---|
| 1 | 90 | 정박 4분음표, 박 쉼표 | 음표 전부 미리 표시 | 흐린 가이드 표시 |
| 2 | 94 | 8분 (박 + 앤) | 전부 미리 표시 | 흐린 가이드 표시 |
| 3 | 98 | **뒷박 단독(엇박)** | 전부 미리 표시 | 흐린 가이드 표시 |
| 4 | 102 | 쉼표 증가, 당김음 | 전부 미리 표시 | 없음 (기억으로) — 따라하기 마디가 시작되면 선생님 줄 기호도 사라짐 |
| 5 | 106 | 16분 묶음 | 전부 미리 표시 | 없음 (선생님 줄 기호도 사라짐) |
| 6 | 110 | 점8분 + 16분, 3-3-2 | 전부 미리 표시 | 없음 (선생님 줄 기호도 사라짐) |
| 7 | 116 | 16분 엇박 | **소리 나는 순간에만** 음표가 나타남(미리보기 없음) | 없음 |
| 8 | 122 | 종합 | **음표 표시 없음 — 귀로만**(선생님 북 치는 동작은 보임) | 없음 |

- "흐린 가이드" = 따라하기 타임라인에 정답 위치를 불투명도 25% 윤곽으로 표시. 4단계부터 빠진다(외워서 치기 시작).
- 4~6단계: 부르기 마디·준비 마디에는 선생님 줄에 기호가 보이고, **따라하기 마디가 시작되면 선생님 줄 기호가 짧게(0.18초) 사라진다**(reduced-motion이면 즉시). 사라지는 시점은 준비 마디 시작이 아니라 따라하기 마디 시작(준비 마디가 생겨도 기억해야 하는 구간 길이는 이전과 같음). 보고 치는 대신 기억해서 친다. 7단계(소리 순간만 표시)·8단계(표시 없음)·1~3단계(내 줄 힌트)는 그대로.
- 박자 칸은 항상 보인다: 정박 = 큰 원, 뒷박 = 중간 원, 16분 칸 = 작은 점(4단계까지는 더 흐리게). 진행 막대(플레이헤드)가 왼→오로 이동.
- 후반 변형 결정: **템포 업(매 단계 +4~6 BPM)과 시각 보조 제거(7·8단계)를 넣는다.** 패턴 반전·변박 등은 넣지 않는다(2~3분 안에 배울 요소가 이미 충분).

### 단계 상승
- 성적과 무관하게 **3라운드가 끝나면 다음 단계**. 버티기 = 하트 관리.
- 8단계 3라운드가 끝났을 때 하트가 남아 있으면 **클리어**.

## 판정

### 타이밍 창
| 판정 | 오차 (들린 음표 시각 기준) | 점수 |
|---|---|---|
| Perfect | **±45ms** 이내 | 100 |
| Good | **±110ms** 이내 (±100 → ±120 → 준비 마디·3라운드 개편 후 ±110, 변경 이력 참고) | 50 |
| Miss | 음표 시각 + 110ms까지 매칭되는 탭 없음 | 0 |

- 단계와 무관하게 고정(가장 빠른 122 BPM의 16분 간격 123ms에서도 아래 매칭 규칙으로 처리 가능).

### 탭 ↔ 음표 매칭
1. 탭 시각(오디오 시계, 아래 "오디오 지연" 참고)을 구한다.
2. **따라하기 판정 구간** = 따라하기 마디 시작 − 100ms ~ 마디 끝 + 100ms.
3. 구간 안 탭: 아직 매칭 안 된 음표 중 |오차| ≤ 100ms인 **가장 가까운 음표 1개**에 매칭. 없으면 **헛박**.
4. 단, 구간의 앞뒤 100ms 겹침 부분(마디 밖)에서 매칭되지 않은 탭은 헛박이 아니라 **무시**.
5. **연타 방지**: 직전 탭 후 **50ms** 이내 탭은 무시(터치 튐 방지).
6. 부르기 마디·**준비 마디**·카운트인·전환 마디의 탭은 판정 없음(앵무새가 작게 따라 움직이고 작은 탭 소리만, 연습 허용).

### 헛박(빈 곳 탭)
- 쉼표를 지키는 것도 배우는 대상이므로 **헛박 = Miss와 같은 취급**: 콤보 끊김, 그 라운드 실패. 점수 차감은 없음.
- 화면에 헛박 위치를 회색 ×로 표시.

### 라운드 성공/실패
- 성공 = 그 라운드 모든 음표가 Perfect/Good이고 헛박 0회.
- 실패 = Miss 1개 이상 또는 헛박 1회 이상 → **하트 −1**, 마디 끝에 놓친 음표 위치를 0.6초 깜빡여 보여줌.
- 판정 확정 시각 = 따라하기 마디 끝 + 100ms (다음 부르기 첫 음표와 겹쳐도 연출은 병행).

### 점수·콤보
- 음표 점수 × 콤보 배율. 배율 = **1 + 0.1 × floor(콤보 / 8)**, 최대 **×2.0**. Perfect·Good이면 콤보 +1, Miss·헛박이면 콤보 0.
- 라운드 성공 보너스: **+100 × 단계**.
- 단계 무실패 보너스(3라운드 모두 성공): **+500**.
- 클리어 보너스: **+1000 × 남은 하트**.
- 점수는 정수(배율 계산 후 반올림).

### 하트
- 시작 **3개**, 최대 3개.
- 라운드 실패마다 −1.
- **단계 무실패(3라운드 모두 성공) 시 +1**(최대 3). 잘하면 회복되고, 흔들리면 금방 끝나는 긴장감.
- 0이 되면 그 판정 시점에 **게임 오버**: 반주 0.8초 페이드아웃 → 결과 화면.

### 틀린 곳부터 (이어 하기) — 2026-11-14 추가
게임 오버 결과 화면에서 **방금 하트를 다 잃게 만든 그 라운드부터** 바로 다시 시작하는 버튼. 3분짜리 판을 처음부터 다시 하지 않고, 막힌 패턴을 곧바로 다시 듣고 연습하게 한다.

### 최고 기록
- localStorage `parrot-beat-best` = JSON `{"score":0,"stage":0,"cleared":false}` (stage = 도달한 최고 단계, cleared = 한 번이라도 클리어). 판 종료마다 항목별로 더 좋은 값만 갱신. **단, 이어 하기를 쓴 판(`retries ≥ 1`)은 갱신하지 않는다**(위 "틀린 곳부터").
- `parrot-beat-offset` = 사용자 지연 보정값(ms, 정수). 기본 0.
- `parrot-beat-muted` = 음소거(sound.md).
- 저장소 접근 실패·형식 오류 시 기본값으로 진행.

## 오디오 지연 대응 (결정)

### 원칙
- **모든 박자 시각은 `audioContext.currentTime` 기준.** `setTimeout`/`requestAnimationFrame`은 시각의 기준으로 쓰지 않는다.
- 스케줄러: 25ms마다 깨어나 **100ms 앞**까지의 반주·선생님 음을 `start(t)`로 미리 예약(look-ahead 방식). 패턴 음표 시각은 게임 시작 시각 `t0`와 마디 번호·BPM으로 계산해 누적 오차 없음(BPM 바뀌는 전환 마디는 마디 시작 시각을 누적 저장).
- **탭 시각 변환**: `tapCtx = ctx.currentTime − (performance.now() − event.timeStamp) / 1000`. (이벤트가 처리되기까지 밀린 시간을 되돌림.)
- **지연 L(초)** = 자동 지연 + 사용자 보정.
  - 자동 지연 = `ctx.outputLatency`가 숫자면 그 값, 아니면 `ctx.baseLatency`, 둘 다 없으면 0. (Safari는 outputLatency가 없을 수 있음.) 시작할 때 1회 + 1초마다 갱신(값이 튀지 않게 이전 값과 0.8:0.2 평균).
  - 사용자 보정 = `parrot-beat-offset` / 1000.
- **판정 오차** = `tapCtx − (음표 예약 시각 + L)`. 즉 "소리가 귀에 들린 순간" 기준.
- **화면 동기**: 플레이헤드·음표 연출은 `ctx.currentTime − L` 시각으로 그려 귀에 들리는 소리와 맞춘다.
- 내 탭 소리는 탭 즉시 재생(지연 보정 없음).

### 간단 보정(캘리브레이션) — 넣는다
- 이유: 블루투스 이어폰(약 150~300ms)은 iPad Safari에서 지연이 보고되지 않아 자동 보정이 불가능하다. 보정이 없으면 모든 탭이 Good/Miss가 되어 "게임이 고장 난" 경험이 된다.
- 위치: 시작 화면의 작은 **이어폰 아이콘 버튼**(글 설명 없이 아이콘 + "박자 맞추기" 짧은 라벨).
- 방법: 90 BPM 클릭 **12번**, 플레이헤드와 큰 원이 박마다 반짝임. 사용자는 박에 맞춰 탭. 처음 4번은 버리고 나머지 8번의 (tapCtx − (클릭 시각 + 자동 지연)) **중앙값**을 offset으로 저장. 범위 **−80 ~ +400ms**로 자름. 유효 탭이 5개 미만이면 저장하지 않고 다시 하기.
- 끝나면 "+180ms" 같은 숫자만 보여주고 "다시 / 확인" 버튼. "0으로" 버튼도 제공.
- **자동 제안**: 한 판 동안 매칭된 탭 오차의 중앙값이 **+60ms 이상**(또는 −60ms 이하)이고 매칭 탭이 16개 이상이면, 결과 화면에 이어폰 아이콘 버튼을 강조 표시(자동으로 값을 바꾸지는 않음).

## 조작
| 동작 | PC 키보드/마우스 | iPad 터치 |
|---|---|---|
| 치기 | Space 또는 아무 키(아래 예외 제외), 마우스 클릭 | 화면 아무 곳 탭 (`pointerdown` 즉시) |
| 일시정지 | Esc / P, Ⅱ 버튼 | Ⅱ 버튼 |
| 음소거 | M, 음소거 버튼 | 음소거 버튼 |
| 시작·다시 하기·틀린 곳부터 | Enter / Space(포커스된 버튼), 버튼 | 버튼 |

- 치기 판정은 `pointerdown`과 `keydown`에서 즉시(`click`/`touchend` 쓰지 않음). 키 반복(`event.repeat`)은 무시. **키 정리: M = 음소거, Esc / P = 일시정지, 그 외 키 = 치기**(Tab·modifier 키는 치기에서 제외).
- 버튼(Ⅱ, 음소거) 위 탭은 치기로 세지 않는다. 버튼은 화면 구석에 작게 두어 오탭을 줄인다(art-ui.md).
- 게임 영역 `touch-action: none`, `user-select: none`, 더블탭 확대·길게 누르기 메뉴 방지. 멀티터치는 손가락마다 각각 1탭(두 손가락 번갈아 치기 허용, 연타 방지 50ms는 공통 적용).
- 첫 시작 버튼 탭에서 AudioContext 생성·`resume()`(iOS 오디오 잠금 해제).

## 화면 흐름
1. **시작 화면**: 제목, 두 새 캐릭터, 최고 점수·최고 단계(클리어했으면 왕관 표시), 큰 시작 버튼, 이어폰(보정) 버튼, 음소거 버튼. 튜토리얼 문장 없음.
2. **플레이**: 카운트인 → 단계 1 … 8. HUD: 점수, 콤보, 하트 3칸, 단계 표시(점 8개 중 현재 위치), Ⅱ, 음소거. 지금이 부르기/준비/따라하기 중 무엇인지는 글 대신 **선생님/앵무새 중 누가 강조되는지 + 타임라인 위/아래 활성**으로 보여준다(art-ui.md). 준비 마디 = 앵무새 강조 + 내 타임라인 "대기"(반쯤 활성) + 정박 원 카운트 점등, 따라하기 마디 = 내 타임라인 완전 활성 + 플레이헤드 이동.
3. **일시정지**: Ⅱ / Esc / P, 또는 탭 숨김(`visibilitychange` hidden) 시 자동.
   - `ctx.suspend()`로 소리·시계 정지, 덮개: "계속" / "처음으로".
   - "계속" → **현재 라운드는 무효 처리**(판정·하트 변화 없음), 카운트인 1마디 후 **같은 라운드의 부르기 마디부터 다시**. 부르기·준비·따라하기 마디 중 어디서 멈췄든 같다(준비 마디도 라운드의 일부). 단계 전환 마디 중이었으면 그 다음 라운드부터. 재개 후에도 라운드 구조(부르기 → 준비 → 따라하기)는 동일.
   - 카운트인·결과·메뉴 중에는 자동 일시정지하지 않음(카운트인 중 숨김은 카운트인부터 다시).
4. **결과 화면**: "클리어!" 또는 도달 단계 표시, 점수, Perfect/Good/Miss/헛박 수, 최대 콤보, 새 기록이면 강조(이어 하기 판이면 대신 "이어하기 N번" 알약). 결과 표시 후 **0.8초** 입력 잠금(치던 손가락 오작동 방지, 새 버튼 포함). 필요하면 이어폰 보정 제안 버튼.
   - **게임 오버**: 버튼 3개 — **「틀린 곳부터」(primary, 되감기 아이콘)** / 「다시 하기」(secondary, 1단계부터 새 판) / 「처음으로」(secondary). 잠금이 풀리면 포커스는 「틀린 곳부터」.
   - **클리어**: 기존대로 「다시 하기」(primary) / 「처음으로」. 「틀린 곳부터」는 숨김.
   - 버튼 문구는 짧게 고정: 「틀린 곳부터」(5글자). 시각 구분(아이콘·색·모양 상세)은 art-ui.md, 기본값은 위 primary/secondary 위계.
   - **결과 화면 배치(높이 문제 함께 해결)**: 버튼이 하나 늘어나므로 모든 크기에서 다음을 적용한다.
     1. "최고 연속 N" 줄(`resLine`)을 따로 두지 않고 판정 수 알약 줄(`resList`)의 **다섯 번째 알약**으로 합친다(줄 1개 절약).
     2. 보정 제안 버튼(`calSuggest`)을 따로 줄에 두지 않고 **버튼 줄의 마지막**(작은 크기, 귀 아이콘 + "박자 맞추기")에 넣는다(줄 1개 절약).
     3. "새 최고 기록"과 "이어하기 N번" 알약은 같은 자리(동시에 나오지 않음).
     4. 높이 ≤ 520px에서는 결과 앵무새 64 → **48px**.
   - 목표: iPhone 13 가로 **750×342**에서 게임 오버 + 새 기록/이어하기 알약 + 보정 제안 + 버튼 3개가 모두 보일 때 오버레이 **스크롤 0**(scrollHeight ≤ clientHeight). iPhone SE 세로(320 폭)에서는 버튼 줄이 2줄로 감겨도 됨(높이 여유), 단 스크롤 0.

### 난이도 검증 (Developer/QA, 봇 시뮬레이션)
봇 = 각 음표 시각 + 정규분포 오차 N(bias, σ)로 1탭, 헛박 없음. 패턴 무작위 시드를 바꿔 **200판** 몬테카를로. 오디오 없이 규칙 엔진만으로 돌린다(`simulateRun`).

| 봇 | 목표 |
|---|---|
| 정확 봇 (σ=0) | 100% 클리어, 전부 Perfect, 점수 = 이론 최대값(QA가 계산값과 일치 확인) |
| σ=20ms | 클리어율 ≥ 99% |
| σ=30ms (잘하는 사람) | 클리어율 **≥ 90%** |
| σ=50ms (보통 사람) | 클리어율 **10~30%**, 탈락 단계 중앙값 **5~7** |
| σ=70ms (처음 하는 사람) | 클리어율 ≤ 3%, 탈락 단계 중앙값 **2~4** |
| σ=30ms, bias=+150ms (보정 안 한 블루투스) | 클리어율 ≤ 5% → offset 150 넣으면 σ=30 결과와 같아야 함 |

- 봇은 패턴 기억 실수(엇박을 정박으로 치기 등)를 모델링하지 않는다. 실제 사람의 후반 난이도는 대부분 이 기억·리듬 해석에서 나오므로, 봇 목표는 **타이밍 창·하트 규칙의 상한 확인**용이다.
- 추가 봇 "엇박 착각 봇": σ=40ms + 뒷박·16분 엇박 음표를 각각 확률 p로 가장 가까운 정박으로 옮겨 침. p=0.05에서 탈락 단계 중앙값 **4~6**이면 적정.
- 목표를 벗어나면 Good 창(±90~±120ms)과 하트 회복 규칙만 조정하고 CEO에게 보고. 패턴·BPM은 바꾸지 않는다.
- **준비 마디 추가(2026-11-14) 후 재검증 필수**: 준비 마디 자체는 타이밍 봇에 영향 없음(봇은 따라하기 시각만 봄). 하지만 단계당 라운드가 4 → 3으로 줄어 전체 라운드가 32 → 24개가 되고, 단계 무실패(하트 +1)가 쉬워져 **클리어율이 올라갈 것**으로 예상. 목표표는 그대로 유지하고 다시 200판(시드 100~299) 돌린다.
  - σ50 클리어율이 30% 초과 또는 σ70이 3% 초과면: **1순위 Good 창 ±120 → ±110ms**로 재측정. 그래도 초과면 ±100ms. 이때 σ30 ≥ 90%가 깨지면 Good 창을 되돌리고 대신 **하트 회복을 "단계 무실패 +1" → "2단계 연속 무실패 +1"**로 바꿔 재측정. 결과를 CEO에게 보고.
  - σ50 탈락 단계 중앙값 목표(5~7)는 유지. 정확 봇(σ0) 이론 최대값은 3라운드 기준으로 QA가 다시 계산.

## 테스트 훅 (QA 전용, 화면 노출 없음)
`window.__parrot`:
- `state()` → 복사본 `{ phase('menu'|'calibrate'|'countin'|'call'|'ready'|'response'|'transition'|'paused'|'over'|'result'), stage, round, bpm, hearts, score, combo, maxCombo, counts:{perfect,good,miss,stray}, pattern(현재 16글자), nextNotes:[초], latency:{auto, offset}, audioTime, cleared }`.
- `start({stage=1, seed})` — 카운트인 포함 즉시 시작. stage 지정 시 그 단계 1라운드부터.
- `setStage(n)` — 다음 라운드부터 n단계(BPM·풀 적용).
- `setHearts(n)`, `setOffset(ms)`.
- `tapAt(audioTime)` — 오디오 시계 기준 시각에 탭이 들어온 것으로 판정 주입(실제 입력과 같은 경로, 반환 `{result:'perfect'|'good'|'stray'|'ignored', errMs}`).
- `autoPlay({sigma, bias, seed} | null)` — 실시간 플레이 중 봇이 자동으로 탭(실기 동작 확인용).
- `simulateRun({sigma, bias, missP, seed})` — 오디오·화면 없이 규칙 엔진으로 한 판 즉시 계산, `{cleared, stageReached, score, counts, maxCombo}` 반환.
- `patterns()` — 단계별 패턴 풀 복사본.
- `pause()`, `resume()`.
- `retryFromFail()` — (2026-11-14 추가) 결과 화면 「틀린 곳부터」와 같은 경로로 이어 하기 시작. 0.8초 입력 잠금은 건너뜀. 게임 오버 결과 화면(`phase 'result'`, 클리어 아님)이 아니면 아무것도 하지 않고 `null` 반환, 성공하면 `state()` 반환.
- `state()`에 추가: `retries`(이 판 이어 하기 횟수, 새 판 0), `failPoint`(`{stage, round, pattern}` 또는 `null` — 마지막 게임 오버를 만든 라운드).
