# 박자 앵무새 기획서
- slug: parrot-beat
- 한 줄 소개: 북 치는 선생님 새가 한 마디를 들려주면, 내 앵무새가 바로 다음 마디에 똑같이 따라 친다. 정박에서 시작해 엇박·쉼표·당김음·16분까지, 글 없이 듣고 치면서 배우는 2분 반짜리 따라치기 리듬 게임.
- 장르 규칙(콜 앤 리스폰스 따라치기)만 빌린다. 기존 상용 리듬게임의 캐릭터·곡·연출은 쓰지 않는다. 캐릭터: 위쪽 **선생님 새**(작은 북), 아래쪽 **내 앵무새**.
- 기존 스튜디오 게임(블록 쌓기, 뱀, 숫자 퍼즐, 두더지, 피하기, 땅따먹기)과 겹치는 장르 없음. 스튜디오 첫 리듬 게임.

## 핵심 루프
반주(메트로놈 + 가벼운 BGM)는 시작부터 끝까지 **끊기지 않고** 흐른다. 4/4박자, 한 라운드 = 2마디.
1. **부르기 마디**: 선생님 새가 패턴을 친다. 화면 위쪽 타임라인에 박자 칸과 음표가 보인다(후반엔 흐려지거나 사라짐).
2. **따라하기 마디**: 바로 이어서 내가 화면 아무 곳 탭 / 아무 키로 같은 패턴을 친다. 친 자리가 아래 타임라인에 판정 색으로 찍힌다.
3. **판정**: 마디가 끝나는 순간 성공(선생님 끄덕) / 실패(하트 1개 깨짐, 놓친 음표 잠깐 표시).
4. 다음 라운드의 부르기 마디가 곧바로 시작. 4라운드 = 1단계, 8단계를 버티면 클리어.

## 규칙

### 시간 구조
- 시작: **카운트인 1마디**(박마다 클릭 4번, 선생님이 북채로 박을 셈. 입력 무시).
- 단계 = **4라운드**(부르기 + 따라하기 = 8박 × 4 = 32박).
- 단계가 바뀔 때 **단계 전환 1마디**(부르기 없음, 반주만, 새 BPM으로 이 마디부터 바뀜, 단계 표시 연출). 이 마디의 탭은 무시.
- 전체 길이(BPM 곡선 기준): 카운트인 2.7초 + 본 라운드 약 148초 + 전환 7마디 약 15초 ≈ **2분 46초**.

### 패턴 표기
- 한 마디 = **16칸(16분음표 그리드)**. `x` = 친다, `.` = 쉰다. `|`는 박 구분(4칸 = 1박).
- 각 박의 4칸 이름: 1칸 = **정박(박)**, 3칸 = **뒷박("앤")**, 2·4칸 = **16분 엇박**.
- 칸 i(0~15)의 시각 = 마디 시작 + i × (60 / BPM / 4)초.

### 단계표 (BPM 곡선, 학습 목표, 화면 보조)

| 단계 | BPM | 새로 배우는 것 | 부르기 때 타임라인 | 따라하기 때 정답 가이드 |
|---|---|---|---|---|
| 1 | 90 | 정박 4분음표, 박 쉼표 | 음표 전부 미리 표시 | 흐린 가이드 표시 |
| 2 | 94 | 8분 (박 + 앤) | 전부 미리 표시 | 흐린 가이드 표시 |
| 3 | 98 | **뒷박 단독(엇박)** | 전부 미리 표시 | 흐린 가이드 표시 |
| 4 | 102 | 쉼표 증가, 당김음 | 전부 미리 표시 | 없음 (기억으로) |
| 5 | 106 | 16분 묶음 | 전부 미리 표시 | 없음 |
| 6 | 110 | 점8분 + 16분, 3-3-2 | 전부 미리 표시 | 없음 |
| 7 | 116 | 16분 엇박 | **소리 나는 순간에만** 음표가 나타남(미리보기 없음) | 없음 |
| 8 | 122 | 종합 | **음표 표시 없음 — 귀로만**(선생님 북 치는 동작은 보임) | 없음 |

- "흐린 가이드" = 따라하기 타임라인에 정답 위치를 불투명도 25% 윤곽으로 표시. 4단계부터 빠진다(외워서 치기 시작).
- 박자 칸은 항상 보인다: 정박 = 큰 원, 뒷박 = 중간 원, 16분 칸 = 작은 점(4단계까지는 더 흐리게). 진행 막대(플레이헤드)가 왼→오로 이동.
- 후반 변형 결정: **템포 업(매 단계 +4~6 BPM)과 시각 보조 제거(7·8단계)를 넣는다.** 패턴 반전·변박 등은 넣지 않는다(2~3분 안에 배울 요소가 이미 충분).

### 단계 상승
- 성적과 무관하게 **4라운드가 끝나면 다음 단계**. 버티기 = 하트 관리.
- 8단계 4라운드가 끝났을 때 하트가 남아 있으면 **클리어**.

## 판정

### 타이밍 창
| 판정 | 오차 (들린 음표 시각 기준) | 점수 |
|---|---|---|
| Perfect | **±45ms** 이내 | 100 |
| Good | **±120ms** 이내 (구현 시 ±100에서 조정, 변경 이력 참고) | 50 |
| Miss | 음표 시각 + 120ms까지 매칭되는 탭 없음 | 0 |

- 단계와 무관하게 고정(가장 빠른 122 BPM의 16분 간격 123ms에서도 아래 매칭 규칙으로 처리 가능).

### 탭 ↔ 음표 매칭
1. 탭 시각(오디오 시계, 아래 "오디오 지연" 참고)을 구한다.
2. **따라하기 판정 구간** = 따라하기 마디 시작 − 100ms ~ 마디 끝 + 100ms.
3. 구간 안 탭: 아직 매칭 안 된 음표 중 |오차| ≤ 100ms인 **가장 가까운 음표 1개**에 매칭. 없으면 **헛박**.
4. 단, 구간의 앞뒤 100ms 겹침 부분(마디 밖)에서 매칭되지 않은 탭은 헛박이 아니라 **무시**.
5. **연타 방지**: 직전 탭 후 **50ms** 이내 탭은 무시(터치 튐 방지).
6. 부르기 마디·카운트인·전환 마디의 탭은 판정 없음(앵무새가 작게 따라 움직이고 작은 탭 소리만, 연습 허용).

### 헛박(빈 곳 탭)
- 쉼표를 지키는 것도 배우는 대상이므로 **헛박 = Miss와 같은 취급**: 콤보 끊김, 그 라운드 실패. 점수 차감은 없음.
- 화면에 헛박 위치를 회색 ×로 표시.

### 라운드 성공/실패
- 성공 = 그 라운드 모든 음표가 Perfect/Good이고 헛박 0회.
- 실패 = Miss 1개 이상 또는 헛박 1회 이상 → **하트 −1**, 마디 끝에 놓친 음표 위치를 0.6초 깜빡여 보여줌.
- 판정 확정 시각 = 따라하기 마디 끝 + 100ms (다음 부르기 첫 음표와 겹쳐도 연출은 병행).

### 점수·콤보
- 음표 점수 × 콤보 배율. 배율 = **1 + 0.1 × floor(콤보 / 8)**, 최대 **×2.0**. Perfect·Good이면 콤보 +1, Miss·헛박이면 콤보 0.
- 라운드 성공 보너스: **+100 × 단계**.
- 단계 무실패 보너스(4라운드 모두 성공): **+500**.
- 클리어 보너스: **+1000 × 남은 하트**.
- 점수는 정수(배율 계산 후 반올림).

### 하트
- 시작 **3개**, 최대 3개.
- 라운드 실패마다 −1.
- **단계 무실패 시 +1**(최대 3). 잘하면 회복되고, 흔들리면 금방 끝나는 긴장감.
- 0이 되면 그 판정 시점에 **게임 오버**: 반주 0.8초 페이드아웃 → 결과 화면.

### 최고 기록
- localStorage `parrot-beat-best` = JSON `{"score":0,"stage":0,"cleared":false}` (stage = 도달한 최고 단계, cleared = 한 번이라도 클리어). 판 종료마다 항목별로 더 좋은 값만 갱신.
- `parrot-beat-offset` = 사용자 지연 보정값(ms, 정수). 기본 0.
- `parrot-beat-muted` = 음소거(sound.md).
- 저장소 접근 실패·형식 오류 시 기본값으로 진행.

## 오디오 지연 대응 (결정)

### 원칙
- **모든 박자 시각은 `audioContext.currentTime` 기준.** `setTimeout`/`requestAnimationFrame`은 시각의 기준으로 쓰지 않는다.
- 스케줄러: 25ms마다 깨어나 **100ms 앞**까지의 반주·선생님 음을 `start(t)`로 미리 예약(look-ahead 방식). 패턴 음표 시각은 게임 시작 시각 `t0`와 마디 번호·BPM으로 계산해 누적 오차 없음(BPM 바뀌는 전환 마디는 마디 시작 시각을 누적 저장).
- **탭 시각 변환**: `tapCtx = ctx.currentTime − (performance.now() − event.timeStamp) / 1000`. (이벤트가 처리되기까지 밀린 시간을 되돌림.)
- **지연 L(초)** = 자동 지연 + 사용자 보정.
  - 자동 지연 = `ctx.outputLatency`가 숫자면 그 값, 아니면 `ctx.baseLatency`, 둘 다 없으면 0. (Safari는 outputLatency가 없을 수 있음.) 시작할 때 1회 + 1초마다 갱신(값이 튀지 않게 이전 값과 0.8:0.2 평균).
  - 사용자 보정 = `parrot-beat-offset` / 1000.
- **판정 오차** = `tapCtx − (음표 예약 시각 + L)`. 즉 "소리가 귀에 들린 순간" 기준.
- **화면 동기**: 플레이헤드·음표 연출은 `ctx.currentTime − L` 시각으로 그려 귀에 들리는 소리와 맞춘다.
- 내 탭 소리는 탭 즉시 재생(지연 보정 없음).

### 간단 보정(캘리브레이션) — 넣는다
- 이유: 블루투스 이어폰(약 150~300ms)은 iPad Safari에서 지연이 보고되지 않아 자동 보정이 불가능하다. 보정이 없으면 모든 탭이 Good/Miss가 되어 "게임이 고장 난" 경험이 된다.
- 위치: 시작 화면의 작은 **이어폰 아이콘 버튼**(글 설명 없이 아이콘 + "박자 맞추기" 짧은 라벨).
- 방법: 90 BPM 클릭 **12번**, 플레이헤드와 큰 원이 박마다 반짝임. 사용자는 박에 맞춰 탭. 처음 4번은 버리고 나머지 8번의 (tapCtx − (클릭 시각 + 자동 지연)) **중앙값**을 offset으로 저장. 범위 **−80 ~ +400ms**로 자름. 유효 탭이 5개 미만이면 저장하지 않고 다시 하기.
- 끝나면 "+180ms" 같은 숫자만 보여주고 "다시 / 확인" 버튼. "0으로" 버튼도 제공.
- **자동 제안**: 한 판 동안 매칭된 탭 오차의 중앙값이 **+60ms 이상**(또는 −60ms 이하)이고 매칭 탭이 16개 이상이면, 결과 화면에 이어폰 아이콘 버튼을 강조 표시(자동으로 값을 바꾸지는 않음).

## 조작
| 동작 | PC 키보드/마우스 | iPad 터치 |
|---|---|---|
| 치기 | Space 또는 아무 키(아래 예외 제외), 마우스 클릭 | 화면 아무 곳 탭 (`pointerdown` 즉시) |
| 일시정지 | Esc / P, Ⅱ 버튼 | Ⅱ 버튼 |
| 시작·다시 하기 | Enter / Space, 버튼 | 버튼 |

- 치기 판정은 `pointerdown`과 `keydown`에서 즉시(`click`/`touchend` 쓰지 않음). 키 반복(`event.repeat`)은 무시. Esc·P·Tab·modifier 키는 치기에서 제외.
- 버튼(Ⅱ, 음소거) 위 탭은 치기로 세지 않는다. 버튼은 화면 구석에 작게 두어 오탭을 줄인다(art-ui.md).
- 게임 영역 `touch-action: none`, `user-select: none`, 더블탭 확대·길게 누르기 메뉴 방지. 멀티터치는 손가락마다 각각 1탭(두 손가락 번갈아 치기 허용, 연타 방지 50ms는 공통 적용).
- 첫 시작 버튼 탭에서 AudioContext 생성·`resume()`(iOS 오디오 잠금 해제).

## 화면 흐름
1. **시작 화면**: 제목, 두 새 캐릭터, 최고 점수·최고 단계(클리어했으면 왕관 표시), 큰 시작 버튼, 이어폰(보정) 버튼, 음소거 버튼. 튜토리얼 문장 없음.
2. **플레이**: 카운트인 → 단계 1 … 8. HUD: 점수, 콤보, 하트 3칸, 단계 표시(점 8개 중 현재 위치), Ⅱ, 음소거. 지금이 부르기인지 따라하기인지는 글 대신 **선생님/앵무새 중 누가 강조되는지 + 타임라인 위/아래 활성**으로 보여준다(art-ui.md).
3. **일시정지**: Ⅱ / Esc / P, 또는 탭 숨김(`visibilitychange` hidden) 시 자동.
   - `ctx.suspend()`로 소리·시계 정지, 덮개: "계속" / "처음으로".
   - "계속" → **현재 라운드는 무효 처리**(판정·하트 변화 없음), 카운트인 1마디 후 **같은 라운드의 부르기 마디부터 다시**. 단계 전환 마디 중이었으면 그 다음 라운드부터.
   - 카운트인·결과·메뉴 중에는 자동 일시정지하지 않음(카운트인 중 숨김은 카운트인부터 다시).
4. **결과 화면**: "클리어!" 또는 도달 단계 표시, 점수, Perfect/Good/Miss/헛박 수, 최대 콤보, 새 기록이면 강조. 버튼 "다시 하기" / "처음으로". 결과 표시 후 **0.8초** 입력 잠금(치던 손가락 오작동 방지). 필요하면 이어폰 보정 제안 버튼.

### 난이도 검증 (Developer/QA, 봇 시뮬레이션)
봇 = 각 음표 시각 + 정규분포 오차 N(bias, σ)로 1탭, 헛박 없음. 패턴 무작위 시드를 바꿔 **200판** 몬테카를로. 오디오 없이 규칙 엔진만으로 돌린다(`simulateRun`).

| 봇 | 목표 |
|---|---|
| 정확 봇 (σ=0) | 100% 클리어, 전부 Perfect, 점수 = 이론 최대값(QA가 계산값과 일치 확인) |
| σ=20ms | 클리어율 ≥ 99% |
| σ=30ms (잘하는 사람) | 클리어율 **≥ 90%** |
| σ=50ms (보통 사람) | 클리어율 **10~30%**, 탈락 단계 중앙값 **5~7** |
| σ=70ms (처음 하는 사람) | 클리어율 ≤ 3%, 탈락 단계 중앙값 **2~4** |
| σ=30ms, bias=+150ms (보정 안 한 블루투스) | 클리어율 ≤ 5% → offset 150 넣으면 σ=30 결과와 같아야 함 |

- 봇은 패턴 기억 실수(엇박을 정박으로 치기 등)를 모델링하지 않는다. 실제 사람의 후반 난이도는 대부분 이 기억·리듬 해석에서 나오므로, 봇 목표는 **타이밍 창·하트 규칙의 상한 확인**용이다.
- 추가 봇 "엇박 착각 봇": σ=40ms + 뒷박·16분 엇박 음표를 각각 확률 p로 가장 가까운 정박으로 옮겨 침. p=0.05에서 탈락 단계 중앙값 **4~6**이면 적정.
- 목표를 벗어나면 Good 창(±90~±120ms)과 하트 회복 규칙만 조정하고 CEO에게 보고. 패턴·BPM은 바꾸지 않는다.

## 테스트 훅 (QA 전용, 화면 노출 없음)
`window.__parrot`:
- `state()` → 복사본 `{ phase('menu'|'calibrate'|'countin'|'call'|'response'|'transition'|'paused'|'over'|'result'), stage, round, bpm, hearts, score, combo, maxCombo, counts:{perfect,good,miss,stray}, pattern(현재 16글자), nextNotes:[초], latency:{auto, offset}, audioTime, cleared }`.
- `start({stage=1, seed})` — 카운트인 포함 즉시 시작. stage 지정 시 그 단계 1라운드부터.
- `setStage(n)` — 다음 라운드부터 n단계(BPM·풀 적용).
- `setHearts(n)`, `setOffset(ms)`.
- `tapAt(audioTime)` — 오디오 시계 기준 시각에 탭이 들어온 것으로 판정 주입(실제 입력과 같은 경로, 반환 `{result:'perfect'|'good'|'stray'|'ignored', errMs}`).
- `autoPlay({sigma, bias, seed} | null)` — 실시간 플레이 중 봇이 자동으로 탭(실기 동작 확인용).
- `simulateRun({sigma, bias, missP, seed})` — 오디오·화면 없이 규칙 엔진으로 한 판 즉시 계산, `{cleared, stageReached, score, counts, maxCombo}` 반환.
- `patterns()` — 단계별 패턴 풀 복사본.
- `pause()`, `resume()`.
